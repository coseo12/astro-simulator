## §1 배경 — 두 가지가 동시에 참이었다

2026-08-16 메인 오케스트레이터가 이슈 #850 의 스프린트 계약을 발행하고 dev 를 디스패치했다. dev 는 **착수 전 실측**으로 두 사실을 보고했다.

1. **Phase 1 은 이미 구현·머지·릴리스됐다** — PR #936 (`824e9fa`, 2026-08-02), 태그 **`v0.57.0`** 부터 포함.
2. **그런데 완료 기준 2건은 여전히 미달**이고, 그 미달은 **구조적으로 도달 불가**다.

두 번째가 이 ADR 의 실질이다. 첫 번째만 보면 단순 NO-OP 이지만, 미달 2건이 남아 있어 **계약을 닫을 수 없는 상태**였다.

### 왜 「미착수」 로 보였는가 — 이것이 (C) 의 대상이다

| 층 | 상태 |
| --- | --- |
| architect 설계안 | `.context/design-850.md` (453줄) — **gitignored 로컬 문서** |
| 이슈 마지막 코멘트 | 그 설계 제안 (2026-08-02) — 「승인 대기」로 읽힘 |
| 실제 구현 | PR #936 이 **그 다음 날** 머지 |

즉 **설계 제안이 이슈의 최신 상태로 남았고 구현 사실이 어디에도 반영되지 않았다.** 메인은 그 상태를 그대로 계약으로 옮겼다. **머지 이력을 한 번만 조회했으면 드러났을 값**이다.

```bash
gh pr list --search '850 in:title' --state merged --json number,mergedAt,title   # #936 즉시 노출
git branch -r --contains 824e9fa                                                 # develop · main
git tag --contains 824e9fa                                                       # v0.57.0 v0.58.0 v0.59.0
```

## §2 실측 — 완료 기준 8축

메인 독립 재확인 (rev `01401dd`). 계측 술어는 설계안 §1.0 의 셸 명령을 그대로 옮긴 것이고, **리팩토링 전 파일에서 설계안 §1.0 표를 바이트 단위로 재현**해 술어 충실성을 먼저 확인했다.

### 미달 2건은 「못 한 것」이 아니라 **임계 도출 오차**다

**P1-1** — 설계안은 테일 실코드를 `~290` 으로 추정했으나 실측은 **`239`** 다 (51줄 과대). 임계 `1,299 − 290 ≈ 1,000` 이 그 오차 위에 세워졌다.

| 구간 (`824e9fa~1`) | 총 | 주석 | 빈 | 실코드 |
| --- | ---: | ---: | ---: | ---: |
| 파일 전체 | 2,502 | 1,072 | 131 | **1,299** |
| 테일 2017-2502 | 486 | 217 | 30 | **239** |
| └ 이동 2041-2502 | 462 | 203 | 28 | 231 |

- **이론 하한**: 잔류 8줄 전량 이관 + 데드 2줄 제거 → `1,299 − 239 − 2 = 1,058` → **초과 58줄**
- **현행 기준**: 잔류 테일 8줄을 전부 제거해도 `1,075 − 8 = 1,067` → **초과 67줄**

`≤1,000` 도달은 **팩토리 내부(485~2016)** 를 건드려야 하므로 **Phase 5 범위**이며, 이는 본 계약의 명시적 비목표(*"Phase 2~5 착수 금지"*)와 **정면 충돌**한다. 주석을 지워 맞추는 경로는 **C4 가 금지**한다.

**P1-6** — `462`줄을 4파일로 나누면 헤더 docblock `33` + import `24` 가 필연이다 (`body-mesh-factory.ts` 는 의존 8개라 import 만 18줄). 편차 `≤5%` 는 총 스캐폴딩 `≤24`줄을 요구하므로 **1→4 분할에서 원리적으로 불가능**하다.

> ⚠️ **PR #936 은 이미 이 재조정을 요청했다.** 본문에 「DoD 재조정 요청 (P1-1 / P1-6)」 절을 두고 도출 오차를 실측으로 제시하며 사용자 판단을 요청한 뒤, **임의 갱신 없이** 머지됐다. 미해결로 남아 있던 것은 **구현이 아니라 계약 갱신**이다. 그리고 2026-08-16 계약이 그 요청을 모른 채 **같은 임계를 재발행**했다.

## §4 결정

### 결정 1 — P1-1 을 **지표 자체로 대체**한다 (임계 완화가 아니다)

`≤ 1,080` 으로 숫자만 낮추는 것도 가능하나 채택하지 않는다. 그 숫자 역시 **또 하나의 추정**이고, 다음 리팩토링에서 같은 종류의 오차를 낳는다.

**대체 지표**: *"Phase 1 이 지목한 테일 구간(2017~2502)의 **실코드 잔여 `0`**"*

- **측정 대상이 명확하다** — 「파일이 충분히 작아졌는가」(추정 필요)가 아니라 「이번 Phase 가 옮기기로 한 것을 다 옮겼는가」(사실 확인)를 잰다.
- **현재 상태**: 잔류 8줄 (`isArcRotateCamera` / `defaultBodyScale`) — **미충족**. 이 8줄은 클로저 참조가 있어 Phase 1 범위에서 이관 불가로 판정됐다.
- ⇒ **그 8줄을 「Phase 1 잔여」로 명시 박제**하고 Phase 2 재평가 시 함께 판단한다. 숨기지 않는다.

### 결정 2 — P1-6 을 **정규화 라인 multiset 차이 `0`** 으로 대체한다

`diff 편차 ≤5%` 는 «순수 이동인가» 를 **줄 수로 근사**한 것이다. 근사를 버리고 **직접 재는 지표**로 바꾼다.

PR #936 은 설계안 §4(e) 순수 이동 실증을 **이미 수행**했다 — 구 테일 462줄 vs 신규 4파일 본문을 정규화 후 라인 multiset 대조 → **`434/434` 완전 일치, 차이 `0`**. 즉 **대체 지표는 이미 충족**돼 있다.

> 스캐폴딩(헤더 docblock + import)이 편차를 만드는 것은 **1→N 분할의 필연**이지 순수성 위반이 아니다. 이 대체가 그 둘을 분리한다.

### 결정 3 — Phase 1 **종결**. Phase 2 재평가는 **실물 이슈**로 분리

설계안 §7 은 *"Phase 2 는 Phase 1 완주 후 재평가"* 라 했다. 그 재평가를 **표에만 남기지 않는다** — 이 저장소는 「표에만 남은 후속은 유실된다」를 [#962](https://github.com/coseo12/astro-simulator/issues/962)→[#970](https://github.com/coseo12/astro-simulator/issues/970) / [#1014](https://github.com/coseo12/astro-simulator/issues/1014)→[#1035](https://github.com/coseo12/astro-simulator/issues/1035) 로 **두 번** 겪었고, [`20260816-1073`](20260816-1073-clause13-observation-wiring.md) 이 세 번째 고리를 끊었다.

### 결정 4 — (C) 구조 원인 박제: **gitignored 설계 문서는 이슈 상태의 SSoT 가 될 수 없다**

본 사고의 원인은 「미착수 판단」이 아니라 **판단에 쓴 자료의 위치**다.

- 설계안이 `.context/**`(gitignored)에 있어 **머지 이력과 대조되는 경로가 없었다**
- 이슈의 마지막 코멘트가 설계 제안이라 **「승인 대기」가 최신 상태로 보였다**

⇒ **계약 발행 전 머지 이력 조회를 의무화**한다. 술어는 §1 의 3줄이며, 비용은 `O(1)` 이다.

⚠️ **이 사고는 같은 세션에서 3회 반복됐다** — #850 (이미 v0.57.0 포함) / [#884](https://github.com/coseo12/astro-simulator/issues/884) 범위 1 (#915 가 6일 뒤 선행 제거) / [#851](https://github.com/coseo12/astro-simulator/issues/851) (PR #921·#922 로 초과 달성). **셋 다 「본문이 아니라 나중 코멘트·다른 PR 이 잔여 범위의 SSoT」** 였다. 단발 실수가 아니라 **구조**다.

## §5 비목표

- **Phase 2~5 착수** — 본 결정은 Phase 1 의 **계약을 닫을 뿐** 새 범위를 열지 않는다.
- **`.context/design-850.md` 의 `docs/` 승격** — Phase 2 재평가 시점에 별도 판단한다. 지금 승격하면 **재평가되지 않은 설계**가 정본처럼 보인다.
- **잔류 8줄 강제 이관** — 클로저 참조가 있어 Phase 1 범위 밖이다. 결정 1 대로 「잔여」로 박제하고 Phase 2 에서 판단한다.
- **「파일 줄 수」 DoD 부활** — 두 파일의 **43%가 주석**이고 그것은 ADR·이슈 번호·실측 수치를 담은 프로젝트 자산이다. 줄 수 DoD 는 **주석 삭제 유인**을 만든다.

## §6 결과 / 한계 / 재검토 조건

### 6-1 결과

- Phase 1 **종결**. 재조정된 지표 2건은 **이미 충족**(결정 2) 또는 **잔여가 명시 박제**(결정 1)됐다.
- 계약 발행 전 **머지 이력 조회**가 의무가 됐다 (결정 4).

### 6-2 한계

- 결정 1 의 대체 지표는 **「Phase 가 지목한 구간」이 선행 정의돼야** 잴 수 있다. 구간 정의가 모호한 Phase 에는 그대로 쓸 수 없다.
- 결정 4 의 술어는 **이슈 제목에 번호가 들어간 PR** 만 잡는다. 제목 규약을 어긴 PR 은 놓친다 (본 저장소는 PR 제목 규약이 있어 실효하나, 전칭이 아니다).

### 6-3 재검토 조건

1. **결정 1 의 잔여 8줄이 Phase 2 에서도 이관 불가로 판정**되면, 그 8줄을 「영구 잔류」로 재분류하고 대체 지표를 다시 정의한다.
2. **결정 4 의 사고가 재발**하면 (계약 발행 후 「이미 완료」가 드러남) 조회를 사람 규약이 아니라 **기계**로 옮긴다 — [`20260816-1073`](20260816-1073-clause13-observation-wiring.md) 이 항 13 에서 밟은 경로와 같다.
3. **`.context/**` 에 설계안을 두는 관행 자체**가 세 번째 사고를 내면, gitignored 설계 문서 금지를 검토한다.
