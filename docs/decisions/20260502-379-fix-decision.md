### 후보 비교의 핵심 — forensic 결과의 해석

forensic 측정 매트릭스에서 sun 도 100% low 로 떨어진 것이 결정적 신호:

- **이론값 (sun coverage ≈ 71px, mid 임계 8 의 8.9배 초과)** vs **실측 결과 (low)** 의 괴리
- 임계 50/8 자체가 잘못된 게 아니라 **measure 가 0 근처** 이므로 임계 조정만으로는 해결 불가
- 따라서 **(a)/(b)/(c) 단독 채택 모두 부분 fix** — 사각형은 사라질 수 있지만 LOD 결정 로직 자체는 여전히 잘못됨 (mid/low 분기가 무의미)
- (d) 효과 0 (메커니즘 아님)
- **(e) "screenCoverage 식 / camera distance 계산 식 검증"이 1차 fix 의 핵심**

## 결정 — 단계적 fix (Phase 분리 릴리스 리듬, volt #30)

### Phase 1 (#379 본 fix, priority:high) — 측정 식 검증 + 정정

#### 결정 (e) 의 첫 단계: developer 가 일회성 debug 박제 후 식 정정

**developer 단계 작업 명세**:

1. **debug 측정 박제** — `runLodPass` 진입 시 첫 5 frame 동안 sun/mercury/venus 의 `screenCoverageRadius` 결과값 + `cameraDistanceMeters` + 카메라 globalPosition 의 m 단위 환산값을 console.log 박제 (일회성, fix 후 제거)
2. **가설 확정** (`lod-policy-review.md` §"가설"):
   - **가설 1**: `screenCoverageRadius` 의 viewProj matrix indexing 식 bug (`mulMat4Point` row/column-major)
   - **가설 2**: 카메라 globalPosition → m 환산 bug (`metersPerSceneUnit` 식)
   - **가설 3**: bodyScale × renderScale 적용 시점 mismatch
3. **확정된 가설에 따라 1~2 라인 식 수정** — 식 수정 직후 코드 주석으로 다음 3종 박제 (cross-validate 이견 수용 #2, drift 방어):
   - `mulMat4Point` 의 row/column-major 가정 명시 + Babylon `scene.getTransformMatrix().m` 메모리 레이아웃 참조
   - `metersPerSceneUnit` 환산의 의미 + sceneUnit 기반 카메라 → m 단위 body 거리 계산 단계
   - `bodyScale × renderScale` 적용 시점 (effective radius 정의의 의도)
4. **회귀 가드 박제**:
   - 단위 테스트: `packages/core/src/render/lod.test.ts` 에 추가:
     - sun T1 default 시나리오 (carrera radius=35) → coverage ≥ 50 → `high` 결정
     - mercury T1 default → coverage ≥ 8 → `mid` 결정
     - venus T1 default → coverage ≥ 8 → `mid` 결정
     - **엣지 케이스** (cross-validate 이견 수용 #1): (i) 카메라 frustum 경계 (clip w ≤ 0) body → coverage = 0 + low fallback / (ii) 극원거리 sub-pixel asteroid (10 AU 거리) → coverage < 8 → low 결정 / (iii) 카메라가 body 내부에 위치 (cameraDistance < radius) → high 강제 (kind 규칙)
   - browser-verify: `apps/web/scripts/browser-verify-379-lod.mjs` 신설 또는 r1-guard `--measure-billboard-fallback` 플래그 확장 (DoD-Guard-1). **3종 LOD 시나리오 매트릭스 검증** (cross-validate 이견 수용 #3):
     - **시나리오 A**: T1 default (현재 forensic 매트릭스 40 cell, fix 후 sun=high 비율 ≥ 95%)
     - **시나리오 B**: T3 body focus (지구 / 화성 focus, focus body=high 보장 + 배경 body 적정 LOD 분기)
     - **시나리오 C**: asteroid belt sub-pixel scenario (T1 solar 뷰에서 asteroid 100+ body 가 low billboard 유지 — fix 가 sub-pixel body 의 low fallback 까지 막지 않는지 회귀 검증)

#### Phase 1 의 Concrete Prediction

- 식 수정 후 forensic 매트릭스 재측정 시 sun=high 비율 ≥ 95% (40 cell 중 38+ high), mercury=mid 또는 high (low 0%), venus=mid 또는 high (low 0%)
- 재측정 시 lodStats `low` 항목이 16+ 감소 (sub-pixel asteroid 위주만 low)
