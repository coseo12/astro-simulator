## 가설 1 vs 가설 2 인과 분석

CI run `25636707640` (FAIL) 의 로그를 정밀 재해석:

```
[browser] [floating-origin] focus body 'mercury' local 좌표 초과 (≥1e5m): ... (가설 2 spam)
... (수십 회 반복, 매 frame mercury focus 시) ...
FATAL: page.goto: Timeout 30000ms exceeded.
- navigating to "...?focus=mercury...", waiting until "networkidle"
```

**추정 인과 chain**:

1. mercury focus 진입 → 가드 C (PR #451 c2e2074 시점) 의 setOriginToBody 호출이 mesh.position 후로 이동 → assert (line 901) 가 stale ox 사용 → fx 임계 초과
2. 매 frame `console.error` 호출 → 페이지 활동 (logging IO) 폭증
3. networkidle 신호 = "500ms 동안 ≤2 네트워크 요청" 정의. console.error 자체는 네트워크 아니지만 **dev mode HMR SSE keep-alive + 매 frame logging 의 결합** 이 networkidle 정의를 위반
4. `waitUntil: 'networkidle'` 30s timeout → 가설 1 발현

→ **가설 1 은 가설 2 의 부수 효과**. 가설 2 의 console.error spam 이 networkidle 신호를 만들지 못하게 한 게 직접 원인.

PR #451 commit `a73542e` 가 가설 2 해소 → console.error 0건 → networkidle 정상 → 가설 1 부수 해소 → develop CI 3회 연속 SUCCESS.
