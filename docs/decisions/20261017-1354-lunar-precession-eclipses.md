## 배경

ADR 1347 은 일식 · 월식을 제외했다 — 달 요소가 상수라 식 날짜를 맞추지 못했다 (§1-B). 이슈 #1354 의 목표는 (1) 달 궤도에 시간 변화를 넣어 장면의 달 위치 · 삭망 시각을 실제에 가깝게 하고 (2) 이벤트 마커에 일식 · 월식을 넣는 것이다. 그림자 · 달 위상 렌더는 비목표다.

설계의 첫 질문은 「어떤 모델이 식 목록을 맞추는가」다. 사건 시각은 ADR 1347 결정 D2 대로 **장면과 같은 식**에서 나와야 하므로, 모델 선택이 곧 장면의 달 위치 선택이다.

### 실측 (2026-10-17, architect)

환경: macOS · Apple M1 Pro · Node 24.14.0 · develop `ec0d365d` (#1349 반영). 모델 계산은 앱 코드 그대로 — `packages/core/dist` 의 `loadSolarSystem` · `positionAt` · `orbitMu` 를 import 하고, 후보는 달 요소만 바꿔 같은 `positionAt` 에 넣었다 (dist 는 src 와 내용 일치 확인 — `ALIGNMENT_SCAN_STEP_DAYS = 4` · `resolveBodyChainPosition` export). 측정 스크립트는 일회성 (커밋 안 함, volt #67 패턴).

**기준값 출처** (전부 2026-10-17 조회):

- **삭망 시각** — JPL Horizons API 벡터, `COMMAND='301'` (달) · `'10'` (태양), `CENTER='500@399'` (지구 중심), `REF_PLANE='ECLIPTIC'` · `REF_SYSTEM='J2000'` · `VEC_CORR='NONE'` (기하 위치 — 모델과 같은 정의, 광행차 없음) · TDB · `STEP_SIZE='2 h'`. 응답 헤더 `{source: DE441}`. 6개 10년 (1901 · 1991 · 2011 · 2021 · 2051 · 2091 시작, ADR 1347 §1-B 와 같은 구간) 을 받아 4점 Lagrange 보간 + 이분법으로 지구 중심 황경차 `0` (삭) · `π` (망) 근을 구했다. 모델 범위 (스크러버 `SCRUBBER_MAX` = 2100-01-01) 밖 표본을 빼고 **1,459개**.
- **식 목록** — NASA GSFC Eclipse Web Site (F. Espenak) 10년 목록 `SEdecade<Y>.html` · `LEdecade<Y>.html` (1901 ~ 2091 시작 20개 10년) + 1900년분은 같은 사이트 5천년 목록 `SEcat5/SE1801-1900.html` · `LEcat5/LE1801-1900.html`. 스크러버 범위 (1900-01-01 ~ 2100-01-01) 안 **일식 452 · 월식 457**. 시각 열은 TD 최대식. 종류: 일식 부분 155 · 금환 145 · 개기 139 · 혼성 13 / 월식 반영 169 · 개기 166 · 부분 122.
- **월식 그림자 반경** — NASA GSFC `LEcat5/shadow.html` 식 (1-5) · (1-6) (Danjon 방식): 반영 `Rp = 1.01·Pm + Ss + Ps`, 본영 `Ru = 1.01·Pm − Ss + Ps` (`1.01 ≈ 1 + 1/85 − 1/594`). 5천년 월식 목록이 이 방식을 쓴다고 같은 페이지가 밝힌다.
- **달 이론 계수** — J. Meeus, *Astronomical Algorithms* 2판 (1998) 47장 식 47.1 · 47.2 · 47.4 · 47.5 · 47.7 (평균 요소 · 율) · 표 47.A / 47.B (주기 항). 원서는 직접 열람하지 못했고, **PyMeeus `Moon.py`** (LGPL v3, `pymeeus.readthedocs.io/en/latest/_modules/pymeeus/Moon.html`) 가 47장을 출처로 재현한 값을 대조했다 — 식 · 표의 수치가 아래 사용 계수와 자리수까지 같다. 평균 근지점 `83.3532465 + 4069.0137287 T` 도 같은 모듈의 `longitude_mean_perigee`.
- **일반세차** — Meeus 율은 「날짜 평균 분점」 기준이라 장면 좌표 (J2000 황도 고정) 로 옮길 때 `p_A = 5028.796195″/세기` (IAU 2006 P03, Capitaine et al. 2003 — ERFA `p06e.c` 의 선형항) 를 뺀다. 검산: Meeus 의 부가항 `A3 = 313.45 + 481266.484 T` 율이 `481267.881 − 1.397` 과 같다.
- 모델 JD 는 앱과 같이 그대로 쓰고 기준값은 TDB/TD 다. ΔT (이 범위에서 분 단위) 는 아래 시 단위 수치에 들어 있다 (보정하지 않았다).

**1-A. 식 판정식 자체 검증 [실측].** 아래 판정식 (§결정 E2) 을 **DE441 위치** (위 Horizons 표) 에 그대로 적용하면 6개 10년 (Horizons 표 범위 — 2100년 포함) 의 NASA 식 일식 138 · 월식 138 에 대해 **적중 138 · 138, 오탐 0 · 0, 종류 일치 138 · 138**, 최대식 시각 차 `+0.5 ~ +0.7` 분. 판정식은 기준 위치에서 목록을 재현한다 — 아래 후보별 차이는 **위치 모델**의 차이다.

**1-B. 현 상태 재측정 [실측 — #1349 교정 후].** ADR 1347 §1-B 의 지표 (NASA 최대식 − 최근접 모델 삭망, 6개 10년, n = 272) 는 교정 전 `−32.8 h ~ +34.0 h` 에서 **`−24.7 h ~ +25.5 h`**. 삭망 시각을 DE441 과 직접 대조하면 `−26.54 h ~ +27.01 h` (1,459개). 식 (1900 ~ 2100, §결정 E2 판정식): 일식 적중 93/452 · 오탐 368, 월식 92/457 · 오탐 373. 장면 달 위치 (모델 − DE441, 지구 중심): J2000 `Δλ −0.739°` `Δβ −0.070°` `Δr −2,192 km` · 2026-10-17 `Δλ −1.302°` **`Δβ +6.737°`** · 2095-06-01 `Δλ −9.461°`.

**1-C. 오차 기전 [실측 + 계산].** 현 모델의 달 평균 운동은 Kepler `n = √(G(M⊕+m☾)/a³)` = `13.1762843°/일` (항성월 `27.3218` 일), 근점 운동도 같은 값이다. 실제는 평균경도 (J2000 고정) `13.1763582°/일`, 진근점 `13.0649930°/일` (근점월 `27.5545` 일 — Meeus 율) 이다. 그래서 (i) 근지점이 고정이라 중심차 (`6.29°` 진폭) 의 위상이 1년에 `~40°` 어긋나고 (ii) 승교점 고정으로 식 계절이 맞지 않으며 (iii) 평균경도가 세기당 `−2.70°` 밀린다.

### 축 M — 달 위치 모델 [실측]

- **A1 이 보여 주는 것** — 근지점 율을 넣으면서 평균근점이각 율을 Kepler n 에 그대로 두면 평균경도 율이 `ϖ̇` (`0.111°/일`) 만큼 빨라져 1년에 `40°` 앞서 간다. 「Ω̇ · ϖ̇ 필드만 추가」 는 이 결함을 만든다 — **평균경도 율이 함께 데이터여야 한다** (축 M 의 첫 결론).
- **A3 의 남은 오차** 는 주기 섭동 (출차 · 이각차) 이다. A3 의 놓침 (일식 10 · 월식 14) 은 전부 경계 사건이다 — 일식은 NASA 식분 `≤ 0.086` 부분일식, 월식은 본영 식분 `−0.83 ~ −1.07` 의 반영월식. 오탐 0 · 놓침이 한쪽으로 몰린 이유는 삭망 때 실효 경사 차다: Kepler 위도 진폭 `5.145°` 에 대해 실제는 위도 항 `2D − F` (`0.173°`) 가 삭망 (`D = 0, π`) 마다 진폭을 `5.128 − 0.173 = 4.955°` 로 줄인다 [계산 — 표 47.B].
- **항 수와 개선** — 경도 항은 삭망 시각을 (B6 `±1.13` → B9 `±0.76` → B28 `±0.49` h), 위도 3항은 적중을 (A3 442 → 451), 거리 2항은 종류 (개기 ↔ 금환 · 부분 ↔ 개기) 를 맞춘다. 적중 · 오탐은 B6 ~ B28 에서 경계 사건 몇 개 안에서 오르내릴 뿐 단조 개선이 아니다 (B9 놓침: 2083-07-15 식분 `0.017` 부분일식 · 2027-07-18 반영월식 / 오탐: 일식 4건 γ `1.527 ~ 1.538` 지구 반경 · 월식 2건 σ `1.48° · 1.57°` — 판정 한계 근처).
- **B9 의 9항** (표 47.A · 47.B, `[D, M, M′, F]` · 진폭): 경도 `[2,0,−1,0] 1.274027°` (출차) · `[2,0,0,0] 0.658314°` (이각차) · `[0,1,0,0] −0.185116°` (연주차) · `[2,0,−2,0] 0.058793°` / 위도 `[2,0,0,−1] 0.173237°` · `[2,0,−1,1] 0.055413°` · `[2,0,−1,−1] 0.046271°` / 거리 `[2,0,−1,0] −3,699.111 km` · `[2,0,0,0] −2,955.968 km`.
- **잔여의 추세** — B28 의 삭망 오차는 1901 `+0.19 ~ +0.48` h → 2091 `−0.49 ~ −0.27` h 로 시간에 비례한다. 크기 · 부호가 지구 (EMB) 일심 황경의 잔여 (ADR 1347 §1-C 반사실: 1900 `+0.188°` · 2100 `−0.191°`) 를 이각 속도 `12.19°/일` 로 나눈 `±0.37` h 와 맞는다 [계산 — 원인 단정은 하지 않는다: 반사실 미측정]. 지구 요소는 이 이슈의 비범위다.

### 축 S — 화면 기하 (위성 배율 ×30)

장면 달의 world 위치는 `earth + local × 30` (`updateAtKepler`) 이다. **지구 → 달 방향은 배율과 무관하게 물리값 그대로**다 (반경 방향 스칼라 배) [정적 판독]. 그래서 식 순간 「태양–지구–달 한 줄」 은 화면에서도 맞다. 맞지 않는 것은 거리 · 크기 비 — 화면의 달은 지구에서 `0.077 AU` (실제 `0.00257 AU`) 라 지구 본영 길이 (`~1.38e6 km`) 보다 멀다. 그림자를 렌더하지 않는 이 이슈에서 이 불일치가 드러나는 곳은 「사용자가 거리 비를 실제로 읽는 것」 뿐이다.

| (a) **사건 상세에 배율 고지 1줄** (`getOrbitVisualScale` 값 — 1341 R6 패턴) + 거리 자 지구 기준점 (실측 거리 표기) | 신규 API 0. 거리 자가 실측 `384,400 km` 대를 보인다 | 화면 비율은 그대로 |

| (c) 아무것도 안 함 | | 사용자가 화면 거리를 실제로 오인 (principles §1 사용자 가이드 위반) |

## 결정 (Provisional — Q 표 권고안 기준)

### 모델 · 데이터

1. **M1 — 모델 = B9** (A3 율 3개 + 주기 9항). 율과 항은 **물리 데이터**다 — 장면 · 정보 카드 · 거리 자 · 사건이 모두 같은 달 위치를 쓴다 (ADR 1347 D2 유지).
2. **M2 — 스키마** (`OrbitalElementsRawSchema` 에 optional 2필드, 달만 채움 — 다른 천체 데이터 변경 0):
   - `rates`: `{ frame: 'mean-equinox-of-date', meanLongitudeDegPerCentury, longitudeOfAscendingNodeDegPerCentury, longitudeOfPerihelionDegPerCentury }` — 값은 Meeus 원값 `481267.88123421` · `−1934.1362891` · `4069.0137287`. `frame` 은 `z.literal` (다른 값은 파싱 실패).
   - `periodicTerms`: `[{ component: 'longitude' | 'latitude' | 'distance', D, M, Mp, F, amplitude }]` — 경도 · 위도는 도, 거리는 km. 9행. 인자 기준 (D · M · M′ · F 의 정의) 은 「모체가 태양을 도는 위성」 에서만 정의된다 — 로더가 그 외 천체에 이 필드가 있으면 거부한다.
   - 로더가 `rate_J2000 = rate − p_A` (`p_A` = shared 상수 `GENERAL_PRECESSION_DEG_PER_CENTURY = 5028.796195 / 3600`, IAU 2006) 로 변환해 rad/일로 싣는다. 기점 값 (`Ω 125.08` · `ϖ 83.22` · `L 218.32`) 은 **바꾸지 않는다** (Q-D2 — 바꿔도 삭망 오차 `±3.39 → ±3.38` h, A 후보 실측).
3. **M3 — 시각 요소 식** (`rates` 가 있는 궤도만, Δt = jd − epoch):
   `Ω(t) = Ω₀ + Ω̇·Δt` · `ω(t) = ω₀ + (ϖ̇ − Ω̇)·Δt` · `M(t) = M₀ + (L̇ − ϖ̇)·Δt` — **M 율이 `√(μ/a³)` 을 대체**한다 (A1 결함 회피). Δt = 0 에서 더하는 값이 정확히 `0` 이라 J2000 요소는 비트 동일하다. `rates` 가 없으면 현 코드 경로 그대로 (다른 천체 비트 동일).
4. **M4 — 위치 함수 단일화**: core 에 `satelliteLocalPositionAt(body, parent, grandparent, jd)` (가칭) 하나를 두고 scene `updateAtKepler` 와 `resolveBodyChainPosition` 이 **같이 호출**한다. 내부 = `positionAt(elementsAt(orbit, jd), jd, μ)` → `periodicTerms` 가 있으면 지구 중심 (λ, β, r) 에 Δλ · Δβ · Δr 를 더한다. 인자 `L☉` · `M☉` 는 모체 (지구) 요소에서 만든다 — 상수를 따로 두지 않는다 (1347 D2 「기준을 따로 두지 않는다」 와 같은 원리).
5. **M5 — N-body 초기 상태**: `buildInitialState` 는 `elementsAt(orbit, jd)` (율 반영) 의 상태 벡터를 쓰고 **주기 항은 넣지 않는다** (섭동은 적분이 만든다). 엔진 전환 순간 달 위치 차 ≤ `13,913 km` (축 V 실측) — ×30 후에도 메시 반경 안. J2000 에서는 N-body 초기 상태가 비트 동일하다 (율 × 0, 주기 항 미적용).

### 궤도선 · 궤적

6. **V1 — 축 V (a)**. 궤도선은 `rates` 보유 천체만 현재 시각 평균 요소로 정점 갱신 (`updatable` LineSystem 의 `instance` 갱신 — **재생성 금지**: ADR 1265 결정 3 의 머티리얼 `uniqueId` 순서). 갱신 문턱은 dev 가 실측으로 정한다 (근지점 `0.111°/일` · 승교점 `0.053°/일` 기준 — 문턱 값과 근거를 PR 에 기록). 궤적 spec 은 같은 천체만 프레임마다 현재 요소로 만든다 (`p` · `q` · `meanMotion` = `L̇ − ϖ̇`).

### 일식 · 월식 사건

7. **E1 — 계산 유형 신설** `{ type: 'syzygy-eclipse'; phase: 'new' | 'full' }` (주체 = 달, 지구 중심 = 달의 모체, 태양 = 체인 뿌리). 삭망 = 지구 중심 황경차 `0` · `π` 의 근 (`resolveBodyChainPosition` 의 달 `local` + 지구 일심 위치), 사건 시각 `t*` = 그 근 ±0.4일 안의 **최대식** (일식 γ 최소 · 월식 그림자 중심 이각 최소) — NASA 목록 시각 정의와 같다.
8. **E2 — 판정식** (순수 함수, 반경은 데이터 `radius` — 태양 `695,700 km` · 지구 `6,378.137 km` · 달 `1,737.4 km`):
   - 일식 — 그림자 축 (태양 → 달) 과 지구 중심 거리 γ (지구 반경 단위), 기본면에서 반영 반경 `l1 = z·tan f1 + k·sec f1`, 본영 `l2 = z·tan f2 − k·sec f2` (`sin f1 = (R☉+R☾)/d`, `sin f2 = (R☉−R☾)/d`). `γ < 1 + l1` → 부분. `γ < 1` 이면 축이 지표에 닿는 점의 본영 반경 부호로 개기 / 금환, `1 ≤ γ < 1 + |l2|` 는 비중심 개기 / 금환. 혼성은 구별하지 않는다 (NASA 혼성 13 중 B9 판정 개기 12 · 부분 1).
   - 월식 — Danjon 식 (NASA `LEcat5/shadow.html` 1-5 · 1-6): 그림자 중심 이각 `σ` 에 대해 `σ < Rp + S☾` 반영 · `σ < Ru + S☾` 부분 · `σ < Ru − S☾` 개기.
   - 판정식은 DE441 위치에서 NASA 목록을 재현한다 (§1-A).
9. **E3 — 종류 표 행**: `solar-eclipse` · `lunar-eclipse` 2행 (필터 칩 2개 — 「일식」 · 「월식」). `AstroEvent` 에 optional `eclipseType` (`total` · `annular` · `partial` · `penumbral`). 목록 · 스크린리더 사건명에 종류를 붙인다 (「개기일식」 · 「금환일식」 · 「부분일식」 · 「개기월식」 · 「부분월식」 · 「반영월식」).
10. **E4 — 허용 오차** (`EVENT_KIND_TOLERANCE_DAYS`, ADR 1347 D5 규칙 그대로 — 최대 `|오차|` 를 0.1일 올림 + 0.2일): 일식 최대식 `0.66 h` = `0.028` 일 → **`0.3`**, 월식 `0.67 h` → **`0.3`**. 구현 후 실측으로 재확정 (§DoD E4).
11. **E5 — 선택**: ADR 1347 D6 + S3 (b) 그대로 — `jumpToJulianDate(t*)` → `focusOn('moon')` → `setTimeScale(0)` → 거리 자 기준점 = 지구 (`autoRulerAnchorEarth: true`). 지구–달 선 · 실측 거리 표기가 「한 줄」 을 보이고, 상세에 배율 고지 1줄 (축 S (a), `getOrbitVisualScale` 값 — 리터럴 30 금지).
12. **E6 — 필터 기본값**: 일식 · 월식 **둘 다 꺼짐** (Q-K1). 근거: 200년 452 · 457건 = 연 2.3건씩이라 데스크톱 트랙 (`452.4` px, ADR 1347 A1-4) 에서 눈금 간격이 `~1 px` 이다 — ADR 1347 D7 이 목성 · 토성 충 (간격 `2.5` px) 을 꺼 둔 기준과 같다.
13. **E7 — 미포함 안내 제거**: `time-events.tsx` `ECLIPSE_EXCLUSION_NOTE` 를 지운다 (1347 §교차검증 합의 3 의 조건 해소).
14. **E8 — N-body**: ADR 1347 D8 그대로 (패널 전체 비활성 + 사유). 식 행에 추가 규칙 없음.
15. **E9 — 계산 비용**: 지연 · 청크 (1347 D3) 를 따른다. 측정 스크립트의 단순 구현 (1일 간격 스캔 + 최대식 황금분할) 은 200년 삭망 4,948개 + 식 판정이 Node `~0.6` s 라 **10년 단위 청크** 이상으로 나눠야 한다 (dev 가 청크 크기 · 탐색법을 정하고 §DoD E9 로 잰다).

### #1347 Concrete Prediction 판정

이 이슈는 예측 「같은 계산 유형의 종류 추가 → 계산 함수 변경 0 줄」 을 **시험하지 않는다** — 일 · 월식은 새 계산 유형 (지구 중심 삭망 + 그림자 판정) 이라 `compute-events.ts` 에 유형 분기 1개가 늘고, `AstroEvent` 에 사건별 속성 (`eclipseType`) 이 생긴다. 예측의 전제 (같은 유형) 밖이므로 반증도 아니다. 이 ADR 이후 같은 유형의 종류 (예: 「개기 · 금환 일식만」 필터) 를 더할 때는 같은 예측이 다시 적용된다.

## 결과 · 재검토 조건

- **기대 효과** — 장면 달이 DE441 대비 `0.2°` 안 (현행 2026 `6.7°` 위도 어긋남 해소). 삭망 `±0.76` h. 이벤트 패널에 1900 ~ 2100 일식 · 월식이 NASA 목록 대비 놓침 1 ~ 2 · 오탐 2 ~ 4 수준으로 들어가고, 고르면 달에 포커스된 채 식 순간에 멈춘다.
- **받아들인 비용** — J2000 장면 달 위치가 바뀐다 (Q-M (b)). 달이 궤도선에서 반경 방향 최대 `1.83 %` 벗어난다. 혼성 일식은 개기 / 금환으로 표기된다. 판정 한계 근처 식 몇 건은 NASA 와 다르다.
- **재검토 트리거**
  1. 지구 (EMB) 요소에 율 · 섭동을 넣으면 → E1 · E4 재측정 (잔여 추세 `±0.4` h 가 지구 기인인지 확인) 후 허용치 Amendment.
  2. 그림자 · 달 위상 렌더 (로드맵 「달 위상 / 일식·월식 그림자」) 착수 시 → 축 S 재검토 (배율 ×30 과 그림자 원뿔 길이의 충돌).
  3. E9 에서 청크가 `50` ms 를 넘으면 → 탐색법 (삭망 시드 · |β| 사전 필터) Amendment.
  4. 다른 위성에 율을 넣자는 요구가 생기면 → 스키마 M2 를 그대로 쓰되 `periodicTerms` 인자 기준이 위성마다 다르다는 점 재설계.
