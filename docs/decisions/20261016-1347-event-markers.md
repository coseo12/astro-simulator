## 배경

로드맵 [`roadmap-track-ab.md`](../phases/roadmap-track-ab.md) §후보 「시간 스크러버 + 이벤트 마커 (근일점·합·식)」 (트랙 D). 스크러버는 #1288 (v0.93.0) 로 끝났고 이벤트 마커가 남았다. 목표 — 스크러버 위에 천문 사건의 위치가 보이고, 사건을 고르면 그 시각으로 가서 화면에서 사건을 본다.

설계의 첫 질문은 「현 Kepler 요소 (J2000 접촉 요소 · 섭동 없음) 로 계산한 사건 시각이 실제와 얼마나 어긋나는가」다. 마커는 **장면이 그리는 위치와 같은 식**으로 계산해야 고른 순간 화면에 사건이 보인다. 그러면 마커 시각의 오차 = 장면 모델의 오차다.

### 실측 (2026-10-16, architect)

환경: macOS · Apple M1 Pro · Node 24.14.0. 모델 계산은 앱 코드 그대로 — `packages/core/dist` 의 `positionAt` · `orbitMu` · `getSolarSystem` 을 import 해 썼다 (dist 는 `kepler.ts` · loader 소스 최종 변경 이후 빌드, `orbitMu` 포함 확인). 브라우저 측정은 develop 빌드 (`apps/web/.next`, 2026-10-15) `next start` + Playwright 1.62.1 headless Chromium (`--use-angle=metal`). 측정 스크립트는 일회성 (커밋 안 함, volt #67 패턴).

**기준값 출처** (전부 2026-10-16 조회):

- 지구 근일점 — USNO Astronomical Applications API `https://aa.usno.navy.mil/api/seasons?year=<Y>` (지구 중심, UT). 장면의 「지구」 는 Standish 요소, 즉 **지구–달 질량중심 (EMB)** 궤도라서 JPL Horizons `COMMAND='3'` (EMB) 의 일심 거리 최솟값도 함께 구했다.
- 행성 근일점 · 충 · 내합 · 혜성 근일점 — JPL Horizons API 벡터 (`CENTER='500@10'` · `REF_PLANE='ECLIPTIC'` · `REF_SYSTEM='J2000'` · `VEC_CORR='NONE'` · TDB). 근일점 = 일심 거리 최솟값 (거친 창 → ±2일 30분 간격 → 포물선 보간). 충 · 내합 = 일심 황경 일치 (`COMMAND='399'` 지구 vs `499` · `299` · `599` · `699`, 1시간 간격 선형 보간) — 지심 황경 충/합과 같은 정의다 (광행차 · 광시간 보정 없음). 혜성은 회귀별 궤도해 (`DES=1P;CAP<1911;NOFRAG` 등, 응답의 `source` 를 표에 적었다).
- 일식 · 월식 — NASA GSFC Eclipse Web Site (F. Espenak) 10년 목록 `SEdecade<Y>.html` · `LEdecade<Y>.html` (1901 · 1991 · 2011 · 2021 · 2051 · 2091 시작 6개 10년). 시각 열은 TD (역학시) 최대 식.
- 모델 JD 는 UTC 기준으로 해석했고 (앱 `dateToJulianDate`) 기준값은 TDB/TD 다. 그 차 (ΔT) 는 이 범위에서 분 단위라 아래 일 단위 오차에 영향이 없다.

**1-B. 일식 · 월식 [실측].** 모델의 삭 (new) · 망 (full) 을 지구 중심 달 · 태양 황경 일치로 구하고 (달은 `local('moon')` — 지구 중심, 시각 배율 미적용), 「삭망 순간 달 황위 |β| < 1.5°」 를 모델의 식 판정 술어로 썼다 (거친 문턱 — 실제 한계는 식 종류별로 다르다. 술어를 바꿔도 아래 결론은 같은 방향이다: 시각 자체가 어긋난다).

- NASA 식 시각과 가장 가까운 모델 삭/망의 시각 차: `−32.8 h ~ +34.0 h`. 예 — 2017-08-21 개기일식은 모델 삭 `19:07` (β `+2.13°`), 2024-04-08 개기일식은 모델 삭이 **다음 날** `2024-04-09 12:35` (β `−4.99°` — 식 아님).
- [정적 판독] 달 요소 (`solar-system.json` `moon`) 는 승교점 경도 · 근지점 경도가 상수다 (변화율 필드 없음 — 스키마에도 없다). 식 계절은 승교점 위치가 정하므로 고정 승교점으로는 식을 맞출 수 없다. 시각 배율 (달 궤도 ×30, ADR 1341 1-E) 때문에 화면의 달 위치도 그림자 기하와 맞지 않는다.

**1-C. 행성 사건 오차의 근원 [실측].** 1-A 의 행성 사건 오차는 J2000 에서 0 근처이고 과거는 `+`, 미래는 `−` 로 **시간에 비례해 벌어진다**. 장면 `orbitMu` 의 태양 직속 μ = `G · M_sun` = `6.6743e-11 × 1.98892e30` 이 IAU 태양 GM (`1.32712440041e20`) 보다 `0.02566 %` 크다 — 모델 공전주기 지구 `365.2115` 일 (IAU GM 이면 `365.2583` 일), 화성 `686.9045` 일 (`686.9926` 일). 같은 측정을 **μ 만 IAU 값으로 바꿔** 다시 돌린 반사실 결과:

| 사건 | 앱 μ — 오차 범위 (일) | IAU GM — 오차 범위 (일) |
| --- | --- | --- |
| 지구 근일점 vs EMB | `−4.83 ~ +4.53` | `−0.19 ~ +0.17` |
| 화성 근일점 | `−4.62 ~ +4.63` | `−0.04 ~ +0.30` |
| 화성 충 | `−5.05 ~ +4.63` | `−0.37 ~ +0.40` |
| 금성 내합 | `−4.06 ~ +3.89` | `−0.47 ~ +0.49` |

같은 μ 차이가 **현재 장면 위치**에도 있다 — 일심 황경 (모델 − Horizons), 2026-10-16 00:00: 지구 (EMB) `+1.189°` (IAU GM `−0.056°`) · 화성 `+0.506°` (`−0.105°`) · 목성 `−0.226°` (`−0.326°`). 1900-01-01 지구 `−4.587°` (`+0.188°`) · 2100-01-01 지구 `+4.584°` (`−0.191°`). 목성 · 핼리 · 엥케는 μ 를 바꿔도 남는다 (섭동 · 궤도 요소 자체).

**1-D. 사건 밀도 · 스크러버 폭 [실측 — 브라우저].** 스크러버 트랙 폭 (`[data-testid="time-scrubber-slider"]`): 1280×800 · 1440×900 · 1920×1080 모두 **`484.4` px** (타임바 폭이 1행 내용 폭을 따른다 — `time-bar.tsx`), 375×812 **`246.4` px**. 200년을 이 폭에 놓으면 연당 `2.42` px (데스크톱) · `1.23` px (375). 같은 종류 인접 사건 간격 (모델, 1900~2100): 화성 충 `763.9 ~ 810.8` 일 · 금성 내합 `579.7 ~ 587.7` · 목성 충 `395.4 ~ 402.8` · 토성 충 `377.1 ~ 379.1` 일 → 데스크톱에서 `5.1` · `3.8` · `2.6` · `2.5` px 간격 (375 는 절반). hit target `24` px (`min-h-6` 규약) 은 데스크톱 `9.9` 년 · 375 `19.5` 년에 해당한다 — **사건 하나하나를 누를 수 있는 마커로 만들 수 없다.**

**1-F. 자기 일관성 판별력 [실측].** 모델이 구한 충 · 내합 시각 `t*` 에서 `|Δλ(t*)|` 최댓값 화성 `2.51e-10°` · 목성 `4.29e-10°` · 토성 `4.33e-10°` · 금성 `2.90e-10°`. `t* ± 1일` 의 `|Δλ|` 최솟값 화성 `0.329°` · 목성 `0.869°` · 토성 `0.923°` · 금성 `0.596°` (전 사건). 근일점 `r(t*±1일)/r(t*) − 1` 최솟값 지구 `2.60e-6` · 화성 `5.24e-6` · 핼리 `7.11e-4`.

### 축 K — 사건 종류 (정밀도 근거)

판정 기준: 「고른 시각에 화면에서 사건이 보이고, 그 시각이 실제 날짜와 며칠 이내인가」. 사건 주기 대비 오차와 화면 기하 (1-F — 1일당 황경 `0.33°` 이상) 를 함께 본다.

| 화성 충 | `±5.1` 일 | **포함** — 주기 780일 대비 0.7 %. 대접근 (2003 · 2018) 이 대표 사건 |

## 결정 (Provisional — Q 표 권고안 기준)

1. **D1 — 사건 종류**: 화성 충 · 금성 내합 · 목성 충 · 토성 충 · 혜성 근일점 (핼리 1986 · 스위프트-터틀 1992). 일식 · 월식 · 지구 근일점 · 엥케 · 핼리 1910/2061 제외 (축 K 표). 범위는 스크러버와 같은 `SCRUBBER_MIN/MAX` (1900-01-01 ~ 2100-01-01).
2. **D2 — 계산은 장면과 같은 식**: 순수 모듈 `packages/core/src/events/` (Babylon 비의존). 위치는 `positionAt(orbit, jd, orbitMu(body, parent))` 의 모체 체인 합 — `body-distance.ts` 와 같은 식이며, 같은 `jd` 에서 두 결과의 상대오차 `≤ 1e-12` 를 단위 테스트로 묶는다 (core 는 web 을 import 할 수 없어 함수를 공유하지 못한다 — parity 테스트가 대체). 근일점은 `M ≡ 0 (mod 2π)` 해석해, 충 · 내합은 일심 황경차 부호 변화 + 이분법. **기준 μ 를 따로 두지 않는다** — μ 를 바꾸면 (Q0 (b)) 사건이 같이 움직인다.
3. **D3 — 지연 계산**: 기능이 꺼져 있으면 계산 0회. 켜지면 `requestIdleCallback` (미지원 시 `setTimeout`) 으로 **종류별 1청크**씩 계산해 모듈 레벨에 메모한다. 부팅 동기 경로에 넣지 않는다.
4. **D4 — 표시**: `Slider.Track` 안 `pointer-events-none` 눈금 (`TICK_YEARS` 와 같은 `inset-x-1.5` 배치식). 종류별 색 · 1 px 폭, 혜성 근일점은 길게. 스크러버 행 오른쪽 끝 (`2100` 라벨 뒤) 에 24 px 아이콘 버튼 → 비모달 「사건」 패널 (`display-panel.tsx` 패턴): 종류 필터 칩 · 「이전 / 다음 사건」 (현재 시각 기준) · 목록 (날짜 `YYYY-MM-DD` · 사건명 · 종류별 오차 배지 「±N일」). 목록은 listbox (↑↓ · Enter). 관찰 · 연구 모드 같은 UI.
5. **D5 — 오차 표기 SSoT**: 종류별 허용 오차 `EVENT_KIND_TOLERANCE_DAYS` 상수 하나를 UI 배지와 단위 테스트 (DoD M3) 가 함께 쓴다. 값 = 1-A 실측 최대 `|오차|` 를 0.1일 올림 + 0.2일 (화성 충 `5.3` · 금성 내합 `4.3` · 목성 충 `6.0` · 토성 충 `4.8` · 핼리 1986 `8.7` · 스위프트-터틀 `0.3`). 날짜만 표시하고 시각 (시:분) 은 표시하지 않는다.
6. **D6 — 선택**: `jumpToJulianDate(t*)` → `focusOn(주체)` (충 · 내합 = 해당 행성, 근일점 = 혜성) → `setTimeScale(0)`. 재생 버튼은 기존 `lastNonZeroScaleRef` 로 이전 배속을 복원한다.
7. **D7 — 기본값 · URL**: 기능 기본 켜짐 (토글 표 행 `events`, `?events=off`). 필터 기본 = 화성 충 · 금성 내합 · 혜성 근일점 켜짐, 목성 · 토성 충 꺼짐. 필터 상태는 URL 에 넣지 않는다. 시각은 현행 계약 유지 (축 URL (a)).
8. **D8 — N-body 엔진**: Newton · Barnes-Hut · WebGPU 에서 눈금 숨김 · 패널 버튼 `aria-disabled` + 사유 (「Kepler 해석해 기준 사건 — 현재 엔진에서는 위치가 다르다」). Kepler 복귀 시 다시 보인다 (ADR 1341 결정 T4 선례).
9. **D9 — 거리 자 연계**: 자동 설정하지 않는다 (상태 부작용 0). 사용자가 기준점을 지구로 둔 상태에서 화성 충을 고르면 기존 거리 자가 그대로 지구–화성 거리를 보여 준다.

행성 사건은 오차가 J2000 양쪽에서 부호가 반대라 일정한 밀림이 어느 한쪽 끝을 키워 대칭 허용치로도 잡힌다. 표본이 1개이거나 오차가 한쪽 부호뿐인 종류 (핼리 · 엥케 · USNO 지구) 는 대칭 허용치만으로는 한 방향을 놓친다 → (ii) 표본별 대역을 함께 둔다. 대칭 허용치 (i) 는 사용자에게 보이는 「±N일」 의 근거이고, 결함 판별은 (ii) 와 M1 이 맡는다.

**CI fps 셀은 추가하지 않는다** (Q-V1). 눈금은 정적 DOM 이고 장면 렌더 경로를 바꾸지 않는다 (M8 로 확인). 나중에 셀을 추가한다면 baseline 은 **판정 경로와 같은 측정 방법** (gate: best-of-3 max) 으로 잰다 — ADR 1335 Amendment 2.

### 이견 (기각 · 정정 — 근거)

1. **「일심 황경 일치 = 지심 충/합」 정의 오류** (agy Q1 High) — agy 스스로 「황도면 투영에서 일심 황경이 같으면 지심 황경도 같다」 고 인정했다. 본문 정의는 황경 (투영) 기준이라 맞다. agy 가 든 나머지 두 축 중 EMB ↔ 지구 차이는 본문 1-A 기준값 출처에 이미 있고 (지구 근일점 두 행), 「황경 합 ↔ 최소 이각」 차이는 정의 선택 문제다 — 본문이 황경 합을 정의로 택했고 기준값도 같은 정의로 구했다. 다만 반사실 잔여 오차 (`±0.5` 일) 의 원인을 「섭동」 으로 단정하지 않는다 — 본문도 단정하지 않았다 (원인 미분리).
2. **D-K 판정 비일관 (화성 근일점)** (agy Q3-1) — 본문의 제외 근거는 정밀도가 아니라 범위 축소 (관심도) 였다. 정밀도 기준으로는 agy 지적대로 목성 · 토성 충과 같은 급이다. 사용자 선택지로 전달한다 (아래).
