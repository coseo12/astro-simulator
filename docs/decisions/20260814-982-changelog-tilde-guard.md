### 손상은 작성자가 타이핑하지 않는다 — 포맷터가 쓴다

`prettier --write` 는 인라인 코드 **밖**의 단일 `~` 를 GFM 취소선 delimiter 로 정규화한다. 이 저장소의
`lint-staged` 는 `*.md` 에 `prettier --write` 를 걸어 두었으므로(`package.json`), **손상은 pre-commit
훅 안에서 생성**된다. 작성자는 `~` 를 하나 썼을 뿐 `~~` 를 본 적이 없다.

격리 재현 (본 rev 워크트리, `pnpm exec prettier` = lockfile 정본 `3.9.6`):

```text
입력:  - 산문 근사: sun 대비 ~5% / ~9% 보수 여유
출력:  (불변)
입력:  - 산문 범위: R1~R4 누적 / 7~12 라운드
출력:  - 산문 범위: R1~~R4 누적 / 7~~12 라운드     ← 손상
입력:  - 코드 스팬: `~5% / ~9%` 및 `R1~R4`
출력:  (불변)                                      ← 인라인 코드가 보호
입력:  - HTML del: <del>철회된 항목</del> 과 근사 ~5% 병존
출력:  (불변)                                      ← <del> 이 보호
입력:  - 의도 취소선: ~~철회된 항목~~ 과 근사 ~5% 병존
출력:  (불변)                                      ← 기존 취소선은 재페어링되지 않음
펜스 안 `R1~R4 / 7~12`:  (불변)                     ← 코드 펜스가 보호
```

**근사 `~5%` 는 손상되지 않고 범위 `R1~R4` 는 손상된다** — GFM 의 flanking 규칙상 여는 쪽과 닫는 쪽이
모두 필요하며 `A~B` 형태(양쪽이 비공백)만 그 둘을 동시에 만족하기 때문이다. 즉 위험 표기는
**범위 표기**이고, 그것이 §7-1 이 코드 스팬을 처방한 이유다.

### 그래서 `~~` 만 봐도 되는 이유 — prettier 가 오라클이다

_"단일 `~` 를 먼저 잡아야 하는 것 아닌가"_ 라는 질문의 답이다. prettier 는 markdown 을 **GFM 파서로
파싱한 뒤 재출력**하므로, prettier 소유 파일에서 *"GFM 이 취소선으로 페어링하는 단일 `~`"* 는 커밋
시점(`lint-staged`)에 **`~~` 로 정규화된다.** 위 재현이 그 판별을 보여준다 — 페어링되지 않는 `~5%` 는
불변으로 남고 페어링되는 `R1~R4` 만 `~~` 가 된다. 따라서 **모집단 안에서는 `~~` 검출로 충분**하고,
단일 `~` 를 직접 판정하려 시도하면 prettier 의 flanking 판정을 **재구현**하는 두 번째 출처가 된다.

이 등가는 **prettier 소유 모집단 안에서만** 성립한다. `docs/**` 처럼 포맷 대상이 아닌 파일에서는 단일
`~` 가 정규화되지 않은 채 남으므로 본 가드의 범위 밖이다 (그리고 그 파일들에는 손상이 애초에 생기지
않는다 — 손상의 주체가 포맷터이므로).

### `prettier --check` 는 이 손상의 술어가 될 수 없다

`--write` 가 만든 형태는 prettier 기준으로 **정답**이라 이후 `--check` 도 초록이다. §7-1 이 이미 이
자기모순을 박제했고(초판이 _"잔여 0 (술어: `--check` 통과)"_ 이라 적었다가 리뷰에서 차단), 본 rev 에서도
재현된다 — `pnpm exec prettier --check '**/*.md'` → `All matched files use Prettier code style!`
(exit `0`) 인데 `CHANGELOG.md` 에는 손상 21줄이 살아 있다.

⚠️ 이슈 [#1040](https://github.com/coseo12/astro-simulator/issues/1040) 완료 기준 5항의
_"`--write` 이후엔 탐지 불가라 **작성 시점** 개입이 유일"_ 은 **부정확하다.** 탐지 불가한 것은
`prettier --check` 이고, **문자열 검색은 사후에도 탐지한다** — 본 ADR 이 채택하는 것이 그 술어다.
작성 시점 개입이 유일한 것이 아니라, **작성 시점 개입이 가장 이르다**.

## 실측

### 모집단 — prettier 가 소유하는 markdown 은 5개다

술어 (본 rev 워크트리, `pnpm install --frozen-lockfile` 후):

```bash
for f in $(git ls-files '*.md'); do
  pnpm exec prettier --file-info "$f"   # .ignored 필드 판독
done
```

| 판정 | 개수 | 파일 |
| --- | --- | --- |
| `ignored: false` (= prettier 소유) | **5** | `CHANGELOG.md` · `README.md` · `packages/{core,physics-wasm,shared}/README.md` |
| `ignored: true` | **228** | `docs/**` · `.claude/**` · `CLAUDE.md` · `.github/**` 전부 |

이슈 #982 본문의 _"노출면은 `CHANGELOG.md` 단독"_ 은 **결론은 맞고 근거는 틀렸다.** 근거로 든
`.prettierignore` 의 `docs/**` 는 맞지만, 실제 노출면은 CHANGELOG **+ README 4개** = 5 파일이다.
(부수 발견 — `.prettierignore` 의 부정 패턴 4줄 `!docs/benchmarks/**` · `!docs/phases/**` ·
`!docs/reports/**` · `!docs/retrospectives/p*-retrospective.md` 는 **무효**다. 상위 `docs/**` 가
디렉토리째 제외하므로 gitignore 문법상 재포함이 성립하지 않는다. 실측: `docs/phases/*.md` →
`ignored: true`. 본 ADR 범위 밖이라 후속 분리한다.)

### 정본 술어 — bare `~~` (펜스 · 인라인 코드 제외)

§7-1 의 술어 `[0-9A-Za-z]+~~[0-9A-Za-z]+` 는 자신이 **하한**임을 명시했다. 세 후보 술어를 같은 rev 에서
`CHANGELOG.md` 에 적용한 결과:

| 술어 | 발생 | 줄 | 오검출 | 미검출 |
| --- | --- | --- | --- | --- |
| **A.** `[0-9A-Za-z]+~~[0-9A-Za-z]+` (§7-1) | 33 | 19 | 0 | **2줄** — `:680` (`#320~~#324`) · `:1276` (` ~~9%`) |
| **B.** `-F -- '~~'` (넓은 그물) | 45 | 22 | **1줄** — `:123` (인라인 코드 안) | 0 |
| **★ C.** bare `~~` = 펜스 밖 ∧ 인라인 코드 밖 (채택) | **44** | **21** | **0** | **0** |

C 의 재현 (본 ADR 부속 분류기와 동일한 규칙 — 백틱 런 매칭으로 인라인 코드 구간을 계산한 뒤
그 밖의 `~~` 만 계수):

```bash
# 넓은 그물 (의도분 포함) — 22 줄 / 45 발생
git grep -nF -- '~~' -- CHANGELOG.md
# 하한 술어 (§7-1) — 19 줄 / 33 발생
git grep -nE '[0-9A-Za-z]+~~[0-9A-Za-z]+' -- CHANGELOG.md
```

B 가 잡고 C 가 거르는 1줄 = `CHANGELOG.md:123` 이며, 그 `~~` 는
`` `git grep -nE '[0-9A-Za-z]+~~[0-9A-Za-z]+' -- '*.md'` `` 라는 **§7-1 술어 자신의 인용**이다.
가드를 문서화하는 문장이 가드의 오검출이 되는 형태이며 volt [#995](https://github.com/coseo12/volt/issues/995)
_"가드가 자기 자신만 찾고 있었음"_ 의 대칭 변형이다.

### 의도된 취소선과 손상은 술어로 구분되지 않는다 — 그러나 모집단으로 분리된다

이슈 #982 설계 질문 2항의 답이다. 두 사실이 같이 성립한다:

1. **구문적 판별자는 없다.** 손상 `92k~~122.5k km) / Main (122.5k~~129k` 와 의도
   `~~6.18%~~ 3.88%` 는 **같은 토큰 두 개**다. §7-1 이 금지한 _"여는 `~~` 앞이 공백이면 의도"_
   대조 규칙은 실손상 ` ~~9%` 를 의도로 분류해 반증된다. 길이·내용 휴리스틱은
   [#1006](https://github.com/coseo12/astro-simulator/issues/1006) 이 산문 대상 형태 검출기 전반에서
   기각한 계열이다.
2. **그런데 모집단이 이미 분리돼 있다.** 저장소 전체 markdown 의 bare `~~` **92 발생** 중
   `CHANGELOG.md` 가 **44**, 나머지 **48** 은 전부 `docs/**`(= prettier `ignored: true`)이며
   전수 확인 결과 **의도된 취소선**이다 (예: `docs/decisions/20260425-r1-sun-visualization.md:89`
   의 errata `~~6.18%~~ 3.88%`, `20260807-971-required-status-checks.md:577` 의 폐기 행 표기).

즉 **정밀도의 출처는 술어가 영리해서가 아니라 모집단이 prettier 소유로 좁혀져 있기 때문**이다.
prettier 소유 5 파일에서 의도된 취소선은 **0 발생**이고, 그 0 이 본 결정 전체를 지탱한다.
그래서 §재검토 조건 1항이 **모집단 크기 자체**를 감시 대상으로 삼는다.

### 이력 시뮬레이션 — 209 커밋에서 발화 2회, 오검출 0

`CHANGELOG.md` 를 접촉한 전체 커밋에 대해 "커밋의 **추가 라인** ∩ 그 커밋 post-image 의 bare `~~` 라인"
을 계산했다 (술어 C 를 diff 스코프로 적용한 것과 동치):

| 커밋 | 일자 | bare | codespan | 성격 |
| --- | --- | --- | --- | --- |
| `4f4544d` (#851 / PR #922) | 2026-08-02 | **20** | 0 | **참양성** — `prettier ^3.8.2 → ^3.9.6` 버전 상향 커밋이 확정 구간 20줄을 일괄 재작성 |
| `909c55c` (#971 / PR #993) | 2026-08-08 | **1** | 0 | **참양성** — `[Unreleased]` 신규 entry 의 `R1~R4` 손상 (도입 시점 `:10` = Unreleased 구간 안) |
| `aeb6c07` (#1013 / PR #1038) | 2026-08-13 | 0 | 1 | **오검출 후보** — 인라인 코드 안. 술어 C 는 **미발화**, 넓은 그물 B 는 발화 |

- 모집단 **209 커밋** / 술어 C 발화 **2** / 오검출 **0** → precision `2/2` · recall `2/2`
- 넓은 그물 B 는 발화 **3** / 오검출 **1** → precision `2/3` = **66.7%**
- 하한 술어 A 는 커밋 단위로는 같은 2건을 잡으나 **줄 단위 recall 이 `19/21` = 90.5%** 다 —
  A 의 보고만 보고 고치면 `:680` · `:1276` 2줄이 손상된 채 남는다

`blame` 대조: 현존 손상 21줄 중 **20줄이 `4f4544d` 단일 커밋**, 1줄이 `909c55c` 다. 즉 손상은
꾸준한 작성 실수가 아니라 **버전 상향 1회의 일괄 사건 + 정상 상태의 산발 1건**이다. 그리고
`package.json` 이력상 prettier 버전 상향은 **1회뿐**이며 그 **1회가 20줄을 만들었다** (n=1 — 재발률의
근거로는 약하고, "다음 상향에서 같은 일이 없다"는 근거는 **0** 이라는 뜻으로만 읽어야 한다).

### 잔여 노출 — 규약은 아직 소진되지 않았다

prettier 소유 5 파일의 **bare 단일 `~`** (펜스·인라인 코드 밖):

| 파일 | 발생 | 줄 |
| --- | --- | --- |
| `CHANGELOG.md` | 149 | 123 |
| `README.md` | 8 | 8 |
| `packages/*/README.md` | 0 | 0 |

이들이 전부 위험한 것은 아니다 (위 flanking 실측 — 근사 `~5%` 형태는 페어링되지 않는다). 다만
**범위 표기를 코드 스팬 없이 쓰는 습관이 149 발생 규모로 살아 있다**는 뜻이고, 규약이 강제 지점 없이
문서로만 존재하는 한 다음 entry 에서 재현된다.

  `4f4544d` 를 **놓친다**. 그 한 건이 현존 손상의 **20/21 (95.2%)** 이다
- **(f) 기각** — allowlist·예외 경로는 CLAUDE.md §가드 설계 원칙이 금지하고
  [#1006](https://github.com/coseo12/astro-simulator/issues/1006) §5 가 그대로 재확인했다 —
  _"잡음이 크면 그것은 가드를 **끄는** 근거이지 예외를 추가할 근거가 아니다"_
- **(g) 기각** — 매직 넘버 `44` 는 통과시키려고 올리면 그만이고
  ([#996](https://github.com/coseo12/astro-simulator/issues/996) 부호 반전 계보), #1040 판정에 따라
  값이 움직이며, 어느 줄이 새로 손상됐는지 **국소화하지 못한다**
- **(h) 기각** — 근거는 아래 §"세 번의 기각과 무엇이 다른가"

### FAIL 인가 WARN 인가 — [#1010](https://github.com/coseo12/astro-simulator/issues/1010) 3계급과의 명시 비교

[`20260811-1010`](20260811-1010-measurement-c-verdict-tiers.md) 은 blocking 안을 기각하고 WARN 계급을
신설했다. 그 결정이 성립한 두 근거를 본 건에 그대로 대입하면 **반대 결론**이 나온다:

| #1010 의 WARN 성립 근거 | 본 건 |
| --- | --- |
| blocking 안의 **오검출 10/12 발화** — 규약을 지킨 PR 이 FAIL | 오검출 **0/2 발화** (209 커밋 시뮬레이션) |
| `phrase≥1 ∧ 구조 0` 이라는 **관측 가능한 중간 상태**가 실재 (침식 21셀) | 중간 상태 없음 — bare `~~` 는 prettier 소유 md 에서 **손상이거나 규약 위반이거나 둘 다**이고, 실측상 그 밖의 상태가 0 |

[#1006](https://github.com/coseo12/astro-simulator/issues/1006) 이 WARN 을 기각한 근거(_"역방향 비용
기울기"_)도 본 건에서는 방향이 뒤집힌다. 발화를 받은 작성자의 **최저 마찰 대응은 범위 표기를 코드
스팬으로 감싸는 것**이고, 그것이 정확히 §7-1 이 원하는 행동이다. #1006 에서는 최저 마찰 대응이
_"`vs` 를 다른 말로 바꾸기"_ 라 가드가 문서 표현력을 퇴보시켰다.

→ **FAIL (차단)**. `|| true` · soft-exit · allowlist · 예외 경로를 두지 않는다.

### 세 번의 기각과 무엇이 다른가

이 저장소는 직전 세 건을 **측정 기반으로 기각**했다. 본 건이 같은 결론에 이르지 않는 이유를
측정으로 제시한다 (_"원리적으로 다르다"_ 가 아니라 수치로).

| 판정 | precision | 검사 대상 | 비용 기울기 |
| --- | --- | --- | --- |
| [#1020](https://github.com/coseo12/astro-simulator/issues/1020) 전수 등재 강제 | `8/98` = **8.2%** | 사람이 내린 **의미론적 판정** (횡단인가) | 중립 |
| [#1020](https://github.com/coseo12/astro-simulator/issues/1020) 참조 휴리스틱 | `5/19` = **26.3%** | 동상 | 중립 |
| [#1006](https://github.com/coseo12/astro-simulator/issues/1006) 병치 검출 | 엄격 **`0/76`** | 사람이 쓴 **산문의 의미** | **역방향** (표현력 퇴보 유도) |
| **본 건 (술어 C · diff 스코프)** | **`2/2`** | **포맷터가 기계적으로 생성한 문자열** | **정방향** (코드 스팬 = 규약 준수) |

핵심 차이는 임계값이 아니라 **검사 대상의 성질**이다. 앞의 세 건은 사람이 쓴 것의 *의미* 를
추론했고, 본 건은 **결정적 규칙을 가진 도구가 만든 문자열**을 본다. 그래서 판정에 의미론이 들어가지
않는다.

⚠️ **과대 해석 금지.** `precision 2/2` 는 **n=2 위의 값**이다. 209 커밋 모집단은 크지만 양성 사건이
2건뿐이라, 이 값은 _"오검출 사례가 이력에 없다"_ 는 뜻이지 _"오검출률이 0 이다"_ 라는 뜻이 아니다.
가드가 유의미해지는 근거는 precision 수치보다 **오류 비용의 비대칭**에 있다 (§결정 3).

## 결정

### 1. 규약 — prettier 소유 markdown 에서 bare `~~` 를 금지한다

§7-1 의 _"범위·구간 표기는 반드시 인라인 코드로 감싼다"_ 를 **기계 판정 가능한 형태로 좁힌다**:

> prettier 가 `ignored: false` 로 판정하는 markdown 파일에서, 코드 펜스 밖 ∧ 인라인 코드 스팬 밖의
> `~~` 는 **금지**한다.

대상은 `prettier --file-info` 판독으로 **파생**한다 — 파일 목록을 하드코딩하면 `.prettierignore` 와
두 번째 출처가 생겨 조용히 갈린다 (volt [#120](https://github.com/coseo12/volt/issues/120)
_"drift 감지보다 중복 출처 제거"_).

### 2. 예외를 두지 않는다 — 탈출구도 규약에 넣지 않는다

규약 1 은 **의도된 취소선도 함께 금지**한다. 술어가 둘을 구분하지 못하기 때문이다(§실측).

초판은 여기에 _"취소선이 필요하면 `<del>…</del>` 를 쓴다"_ 는 **탈출구 조항**을 두었고,
cross-validate 가 YAGNI 위반으로 지목해 **철회했다** (§교차검증 반영 사항 이견 수용 1). 수요가 실측
**0** 인 우회로를 규약과 가드 출력 문구에 넣으면, 규약 1(전면 금지)의 신호가 약해지고 작성자에게
쓰지 않을 선택지를 읽히는 비용만 남는다.

**측정 사실 자체는 §결과 에 남긴다** — 전면 금지가 표현 능력을 영구히 잃게 하는 결정이 아님을
보이는 근거이지, 지금 처방하는 절차가 아니기 때문이다. 실제 수요가 나타나면 §재검토 조건 2 가
발동한다.

### 3. 강제 지점 — diff 스코프 · fail-fast

**단일 술어 · 단일 스크립트 · 두 호출 지점**으로 배선한다.

| 호출 지점 | 모드 | base 해석 | 근거 |
| --- | --- | --- | --- |
| `.husky/pre-commit` — **`pnpm lint-staged` 다음 줄** | staged diff (index ↔ HEAD) | 항상 해석 가능 (네트워크 무관) | 손상이 **생성되는 지점**이 lint-staged 의 `prettier --write` 다. 그 직후가 가장 이른 검출 시점이고, 작성자가 커밋을 만들기 전에 고칠 수 있다 |
| `.github/workflows/ci.yml` — `pull_request` 한정 | `<base.sha>..HEAD` 추가 라인 | 기존 `diff-scope` job 의 검증된 fetch 패턴 재사용 | 훅 우회(`--no-verify`) backstop |

- **base 미해석 시 exit 1** (차단). 조용한 통과 분기를 두지 않는다
- push 이벤트는 배선 대상이 아니다 — `main`/`develop` 직접 push 는 CLAUDE.md §금지 사항이고,
  `<type>/*` 브랜치 push 는 PR 이벤트로 다시 검사된다
- 검출 시 출력에 **파일:줄 + 처방 1종**(_"범위 표기를 인라인 코드로 감싼다"_)만 포함한다.
  #1010 가드가 _"수동: 체크박스 추가"_ 로 안내해 작성자가 헤더를 넣은 전례가 있으므로, 처방 문구는
  §7-1 규약과 **같은 낱말**을 쓴다. 우회로는 출력에 넣지 않는다 (결정 2)

### 4. 오류 비용의 비대칭이 채택의 실질 근거다

- **미검출 비용** — 손상이 확정 구간에 들어가면 회수 자체가 _"소급 편집인가"_ 라는 **정책 판정을
  요구**한다. 실제로 21줄이 그 상태이고 [#1040](https://github.com/coseo12/astro-simulator/issues/1040)
  이 아직 열려 있다. 되돌리는 비용이 **기술 비용이 아니라 거버넌스 비용**이다
- **오검출 비용** — 범위 표기를 백틱 2개로 감싸는 것. 한 줄 수정

### 5. 본 ADR 은 결정만 박제한다 — 발효는 구현 PR 이다

본 PR 의 산출물은 ADR · 인덱스 행 · CHANGELOG entry 뿐이고 `.claude/**` · `scripts/**` ·
`.github/**` · `docs/ops/**` 는 무접촉이다. 규약 1·2 의 **발효 지점과 §7-1 갱신은 dev 구현 PR** 소관이다
(§Developer 인계).

### CLI 계약 (cross-validate 합의 3 — 인터페이스 명시)

| 모드 | 동작 | 호출처 |
| --- | --- | --- |
| `--staged` | staged diff (index ↔ HEAD) 의 추가 라인 검사 | `.husky/pre-commit` |
| `--base <sha>` | `<sha>` ↔ `HEAD` 추가 라인 검사. `<sha>` 미해석 시 **exit 1** | `ci.yml` (`pull_request`) |
| `--self-test` | 결정적 자기 검증 (아래 픽스처) | CI 사용 직전 스텝 |

exit `0` = 위반 없음 / exit `1` = 위반 또는 판정 불가. 출력은 `파일:줄` + 규약 처방 1줄.

### 파서 엣지 케이스 — self-test 필수 항목 (cross-validate 합의 1)

인라인 코드 스팬 판정을 정규식으로 구현할 때 아래를 **단언으로 고정**한다. 정규식 대신 markdown AST
파서(`remark` 등)를 쓰는 안은 **신규 의존성 도입**이라 기각한다 (CLAUDE.md §새 라이브러리 도입 시
사전 확인). 필요한 하위 문법은 백틱 런과 펜스뿐이라 규모가 좁다.

   `<TT>`            2개 런: ``<TT>``            3개 런: ```<TT>```

### precision 논거는 깨지지 않는다 — 편입분 물결 `0`

- 술어 ① (상한, 넓은 그물): `git grep -nF -- '~~' -- <편입 4 파일>` → **0 hit**
- 술어 ② (더 넓게 — 단일 물결까지): `git grep -nF -- '~' -- <편입 4 파일>` → **0 hit**

즉 편입분에는 의도된 취소선도, 손상형도, **장래 손상 후보(단일 `~`)도 없다.** 상한 술어로 0 이므로
하한 술어로도 0 이다. 본 ADR §정밀도의 출처 를 지탱하는 *"소유 모집단 안의 의도된 취소선 = 0 발생"*
은 `49` 에서도 유지된다. Amendment 1 의 편입 40 파일이 `~~` 0 hit 이었던 것과 같은 결론이며,
이번에는 단일 `~` 까지 0 이라 §잔여 노출 표에도 행이 늘지 않는다.

### 갱신되지 않는 것

- **술어** — 변경 없음 (코드 펜스 밖 ∧ 인라인 코드 스팬 밖의 `~~`)
- **차단 정책** — 변경 없음. 계수는 여전히 **차단하지 않는다**. 본 Amendment 가 그 *"사람의 판단"* 이다
- **diff 스코프** — 변경 없음. #1040 존량 21줄은 전부 `CHANGELOG.md` 이고 편입 4건과 **disjoint**

### 후속 감시

다음 재검토 트리거는 **계수가 `49` 에서 이탈**할 때다. 판정 규칙은 Amendment 1 과 동일 —
증가는 정상, **감소는 `.prettierignore` 회귀 신호**. `.prettierignore` 의 4경로는 이제 **전건 동일
형식**(`!docs/x/` + `!docs/x/**/` + `!docs/x/**/*.md`)이므로, 다음 이탈이 게이트 형식 비대칭에서
비롯될 여지는 닫혔다.

> ⚠️ **[2026-08-14 — _"감소 = 회귀 신호"_ 는 실측 반증됐다]** 위 서술은 **측정 없이 세운 가정**이었다.
> ADR [`20260814-1031-1064`](20260814-1031-1064-committed-claim-guard-rejected.md) §측정 6 이 직전
> **250 non-merge 커밋**(2026-05-25 ~ 2026-08-14, rev `38b6c8a`)에서 계수 변동을 측정한 결과 전이는
> **3회**이고, **유일한 감소**(`48 → 45`, 삭제 live-set 3건 / 추가 0건)의 원인은 커밋 `0c316f0`
> ([#905](https://github.com/coseo12/astro-simulator/issues/905) 감사 P0 위생 — **고아 문서 정리**)로
> `.prettierignore` 회귀가 **아니었다**. 정상 삭제와 회귀가 같은 관측값을 공유하므로 **방향별
> FAIL/WARN 계급을 세울 축이 없다** (정밀도 `0/1`). **위 서술은 그 시점 기록이라 보존한다** —
> 감소를 보면 원인을 규명하라는 **사람 대상 지침으로는 유효**하고, 반증된 것은 그것을 **기계 차단
> 기준으로 쓸 수 있다**는 함의뿐이다.

### 재현 — 박제 술어를 그대로 추출해 실행 (2026-08-16, #1078)

`--population` 은 **워킹트리를 읽는다** — `git ls-files '*.md'` (인덱스) 와 `prettier --file-info`
(디스크의 `.prettierignore`) 의 곱이다. 그래서 rev 를 **인자로 줄 수 없고** 체크아웃해야 한다
([`20260808-983`](20260808-983-measurement-recording-convention.md) §(ii) `> 확장 (#1064)` 이
처방한 `git grep <pat> <rev>` 형식이 이 술어에는 **적용되지 않는 이유**다).

```bash
# 저장소 루트에서. PRETTIER_BIN 은 스크립트 위치 기준이라 체크아웃 트리에 node_modules 가 필요하다.
# 아래 4개 rev 는 pnpm-lock.yaml 의 prettier 가 전부 3.9.6 이라 심볼릭 링크로 대신할 수 있다
# (술어: `git show <rev>:pnpm-lock.yaml | grep -m1 'prettier@'` → 4/4 `prettier@3.9.6:`).
for REV in 38b6c8a fe922bb 79ed14c 804dce6; do
  # ⚠️ 침묵 fallback 금지 — `>/dev/null 2>&1` 로 실패를 삼키면 **직전 회차의 stale worktree
  #    가 그대로 재사용**되어 「헤더 rev 에 다른 트리 값」이 exit 0 으로 박제된다. 그것이
  #    바로 이 Amendment 가 신설하는 오기록 클래스라, 재현 펜스가 그 결함을 생산하게 된다
  #    (PR #1101 reviewer 실측 — stale 잔존 시 `38b6c8a … 240 … 49`, 진단 0).
  #    CLAUDE.md §가드 설계 원칙 «fail-fast 만, fallback 분기 금지».
  git worktree add --detach ".tmp-md-tilde-$REV" "$REV" || exit 1
  ln -s "$PWD/node_modules" ".tmp-md-tilde-$REV/node_modules"
  printf '%s ' "$REV"
  (cd ".tmp-md-tilde-$REV" && node scripts/verify-md-tilde.mjs --population |
    grep -E 'tracked \*\.md|ignored: false' | tr -s ' ' | tr '\n' ' ')
  echo
  git worktree remove --force ".tmp-md-tilde-$REV"
done
```

| 체크아웃 rev                                            | `.prettierignore` 게이트 (= 모집단 술어)  | `tracked *.md` | `--population` |
| ------------------------------------------------------- | ----------------------------------------- | -------------: | -------------: |
| `38b6c8a` (본 Amendment 헤더가 적은 rev)                | 구 — `!docs/retrospectives/**/*-retrospective.md` |          `236` |     **`45`** |
| **`fe922bb`** (#1072 머지 커밋 — **재현 anchor**)       | 신 — `!docs/retrospectives/**/*.md`       |          `236` |     **`49`** |
| `79ed14c` (#1069 머지 — `fe922bb` 의 후손)              | 신                                        |          `236` |     **`49`** |
| `804dce6` (본 부기 PR 의 **base 커밋**, 2026-08-16)     | 신                                        |          `240` |     **`49`** |

**앞 두 행의 `tracked *.md` 가 둘 다 `236` 이라는 것이 결정적이다** — 모집단 입력(추적 `*.md`
집합)이 **같은데** 계수만 `45` ↔ `49` 로 갈린다. 즉 차이는 트리가 아니라 **게이트**에서 온다.
`804dce6` 의 `240` 은 그 뒤 md 4개가 추가된 결과이며 계수 `49` 는 불변이라, **그 rev 까지는**
§후속 감시 의 감시값 `49` 가 이탈하지 않았다.

⚠️ **네 행 모두 고정 SHA 로만 적었다 — `origin/develop` 같은 이동하는 ref 이름은 쓰지 않았다.**
본 부기를 쓰는 동안에도 develop 은 이동했다 — ref 이름으로 적으면 그 순간 표가 재현 불가능해지고,
그것이 바로 본 부기가 다루는 결함이다. 같은 이유로 위 문장은 _"현행 tip 에서 `49`"_ 를 주장하지
않는다. tip 은 rev 가 아니라 **시점 종속 별칭**이므로 [`20260808-983`](20260808-983-measurement-recording-convention.md)
§(ii) 의 «무시점 절대 수치» 와 같은 형태로 썩는다.

**대조군 — 같은 PR 의 형제 Amendment 는 같은 헤더로도 재현된다.**
[`20260814-958`](20260814-958-prettier-live-docs-scope.md) §Amendment 2 도 헤더에
`측정 rev: 38b6c8a` 만 적었으나 그쪽 술어는 `git ls-files 'docs/retrospectives/*.md'` 라
**rev 로 닫힌다** —
`38b6c8a` 체크아웃에서 `19` / `-retrospective.md` `15` 로 **그대로 재현**된다. 헤더 형식이 아니라
**술어가 워킹트리의 다른 파일을 읽는가**가 가르는 축이라는 실증이다.

**같은 PR 이 `.prettierignore` 주석에는 조건을 붙였다** — 그쪽은 _"실측 (rev `38b6c8a`): 편입
`4` 건 / 모집단 `45` → `49`"_ 로 **두 끝점을 함께** 적어 게이트 축이 노출돼 있고, 위 표의 1·2행이
그 서술을 그대로 재현한다. 잃어버린 것은 값이 아니라 **한쪽 끝점만 적은 헤더 형식**이다.
