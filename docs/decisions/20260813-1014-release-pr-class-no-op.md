## 배경

이슈 #1014 는 *"`pr-template-checklist-guard` 가 release PR 클래스에서 **상습 발화**한다"* 로 (a)~(d) 택일을 요구했다. 착수 시점 실측 결과 **이슈 본문의 전제와 메인 오케스트레이터의 정정 코멘트가 둘 다 부분적으로 틀렸다.**

### 모집단을 구조 정의로 재수립했다

메인의 정정 코멘트는 v0.60.0~v0.69.0 **10 릴리스**만 봤다. 본 ADR 은 모집단을 **구조 조건**으로 재정의한다:

```text
release 클래스 ≔ (baseRefName == "main") ∨ (headRefName 이 "release/" 로 시작)
```

술어: `gh pr list --state merged --limit 300 --json number,body,author,baseRefName,headRefName,mergedAt` 산출물을 위 조건으로 필터 → **107 PR** (#592 2026-05-27 ~ #1033 2026-08-13), **54 릴리스 사이클**. 각 PR 본문에 대해 판정 정본 `node scripts/verify-pr-template-checklist.mjs --check-corpus <json>` 을 돌려 셀 계급을 센다 (7 kw × 107 PR = **749 셀**).

전수 결과: **PASS 671 / WARN 52 / FAIL 26**.

### 정정 1 — WARN 클래스는 "소멸" 하지 않았다. 간헐적이고, 이미 한 번 더 긴 침묵 뒤에 재발했다

사이클 단위 (prep PR + release PR 을 한 사이클로 묶고, 둘 중 하나라도 WARN 셀 ≥ 1 이면 그 사이클을 WARN 으로 계상):

| 구간 | 사이클 | WARN 사이클 |
| --- | --- | --- |
| 전체 (#593 ~ #1033) | 54 | **19 (35.2%)** |
| 최장 WARN=0 연속 | — | **17 사이클** (#792 2026-07-03 ~ #956 2026-08-04) |
| 현재 말단 WARN=0 연속 | — | **6 사이클** (#1001 2026-08-09 ~ #1033 2026-08-13) |

**결정적 관측**: 17 사이클 연속 WARN=0 이 있었고, 그 침묵은 **#965 (v0.60.0, 2026-08-05) 에서 깨졌다** — 이슈가 인용한 바로 그 클러스터다.

⇒ 메인이 *"연속 6 릴리스 소멸"* 을 소멸의 근거로 쓴 것은 **성립하지 않는다.** 같은 모집단이 과거에 그 3배 가까운 침묵(17) 뒤에 재발한 이력이 있으므로, 6 사이클은 관측 잡음 대역 안이다.

### 정정 2 — WARN 클러스터의 키워드 서명이 매번 다르다. 단일 클래스가 아니다

| 클러스터 | 사이클 | WARN 키워드 |
| --- | --- | --- |
| #593 (2026-05-28) | 1 | kw1 커밋 컨벤션 / kw2 불필요한 변경 |
| #616 (2026-06-04) | 1 | kw7 Test plan |
| #636 (2026-06-08) | 1 | kw4 SSoT / kw5 cross-validate |
| #703 ~ #708 (2026-06-18) | 2 | kw6 ADR 호환성 + kw7 |
| #736 ~ #748 (2026-06-22~25) | 3 | kw6 |
| #772 ~ #787 (2026-06-30~07-02) | 4 | kw6 |
| **#965 ~ #992 (2026-08-05~08)** | **4** | **kw3 보안 / kw4 SSoT** |

같은 자리에서 같은 이유로 반복되는 것이 아니라, **원인이 매번 회전한다.** kw 별 WARN 총계도 특정 키워드에 몰리지 않는다 — kw6 **20** / kw7 **10** / kw4 **9** / kw3 **8** / kw1 **2** / kw2 **2** / kw5 **1** 로 **7 키워드 전건에 분포**한다.

이것이 (a)/(b) 기각의 핵심 근거다 — 클래스 단위 예외·전용 템플릿은 **아직 관측되지 않은 미래의 원인까지 영구히 가린다.**

### 정정 3 — *"(c) 가 이미 구현돼서 WARN 이 끊겼다"* 는 인과 주장은 시간순으로 성립 불가다

메인은 `create-pr` 스킬이 템플릿을 직접 읽어 `[ ]` → `[x]` **in-place 갱신만** 하는 규약을 근거로 *"WARN 이 v0.64.0 에서 끊긴 것과 정합한다"* 고 했다. **그 규약의 도입 시점을 실측하면 정합하지 않는다.**

```text
$ git log --format='%h %ad' --date=short \
    -S '갱신만 허용 (라인 자체 변경·삭제 금지)' -- .claude/skills/create-pr/SKILL.md
94bf614 2026-05-16
```

`-S` 가 **단일 커밋**만 반환한다 — 이 규약 문언은 **2026-05-16 (`94bf614`, #471 / PR #478) 에 도입된 뒤 오늘까지 한 번도 변경되지 않았다.** 즉 위 표의 **7개 WARN 클러스터 전부가 이 규약이 이미 발효 중인 상태에서 발생**했다.

**상수는 변화를 설명할 수 없다.** #1010 의 PR (`ebd9866`, 2026-08-11) 역시 현재 침묵 구간의 시작(#1000, 2026-08-09)보다 **뒤**다.

⇒ **현재 WARN=0 침묵의 메커니즘은 미확인이다.** 본 ADR 은 이를 *"관행이 이미 고쳤다"* 로 서술하지 않는다 — 그렇게 박제하면 미래 관찰자가 존재하지 않는 방어를 믿게 된다.

### FAIL 축 — 선언 모집단 107 PR **전수** (창 축소 없음)

> **초판 정정 (2026-08-13, PR [#1034](https://github.com/coseo12/astro-simulator/pull/1034) reviewer BLOCK-1/2).** 초판은 이 절에서 예고 없이 `#902 이후` 로 창을 좁혔고, 그 결과 *"빨간 X 인 채 머지된 릴리스 클래스 PR 은 0건"* 이라는 **거짓 명제**를 4곳에 전파했다. 아래는 선언 모집단 전수로 재작성한 것이다.

술어: 각 PR 의 `headRefOid` 에 대해 `gh api repos/coseo12/astro-simulator/commits/<SHA>/check-runs?per_page=100` 로 `name=="pr-template-checklist"` 인 run **전체**를 `started_at` 오름차순 열거.

- **첫 run** ≔ 정렬 후 첫 원소의 `conclusion` (사후 본문 편집으로 계급이 바뀌어도 첫 발화는 남는다)
- **무정정 머지(escape)** ≔ `success run = 0 ∧ failure run ≥ 1` 인 채로 머지됨

107 PR **전건이 체크런을 보유**한다 (체크런 0건 = **0**). 가드 도입 `a1c1373`(2026-05-17, #473)이 코퍼스 시작 #592(2026-05-27)보다 앞서므로 전 구간이 가드 존재 이후다.

| 지표 | 전수 (107 PR) | 종류별 |
| --- | --- | --- |
| 첫 run `failure` | **11** | release **6** / prep **5** |
| └ 자기 정정 후 머지 | 7 | release 2 (#668 #829) / prep 5 (#592 #702 #912 #964 #1032) |
| └ **무정정 머지 (escape)** | **4** | **release 4 / prep 0** |
| **가드 미발화 (탐지 실패)** | **0** | 11/11 정상 발화 |

**escape 4건 전수** — 재실행 **0**, success run **0**. 빨간 X 를 단 채 머지됐고 오늘도 그대로다:

| PR | base ← head | 첫 run | 머지 | 간격 | run 수 |
| --- | --- | --- | --- | --- | --- |
| #636 | `main` ← `develop` | `failure` 2026-06-08T15:13:22Z | 15:24:16Z | 10분 54초 | 1 |
| #646 | `main` ← `develop` | `failure` 2026-06-10T07:19:45Z | 07:30:22Z | 10분 37초 | 1 |
| #652 | `main` ← `develop` | `failure` 2026-06-10T13:11:31Z | 13:24:37Z | 13분 06초 | 1 |
| #658 | `main` ← `develop` | `failure` 2026-06-10T17:05:15Z | 17:13:38Z | 8분 23초 | 1 |

⚠️ **이 4건은 본 ADR 이 §배경에서 이미 출력한 값이다** — `--check-corpus` 마지막 줄 `FAIL PR 4건: #658 × 7, #652 × 7, #646 × 7, #636 × 5` 가 그대로 이들이다. 초판은 **코퍼스 전수와 FAIL 축을 같은 문서 안에서 대조하지 않았다.** 4 PR 이 실제로 어떻게 머지됐는지 한 번만 조회했으면 드러났을 값이다.

**escape 구간은 3일에 국한된다** (2026-06-08 ~ 06-10). 마지막 escape #658 이후 릴리스 클래스 **96 PR** (#667 2026-06-11 ~ #1033 2026-08-13) 에서 escape **0건**.

원인은 본문 형태다 — #658 본문은 **14줄 / 7 phrase 전건 0 hit** (릴리스 서사만)인데 직후 #668 은 **51줄 / 7 phrase 전건 ≥ 1 hit** 이다 (술어: `printf '%s\n' "$(gh pr view <N> --json body -q .body)" | grep -c ''` — 후행 개행 제거 후 완전 줄 수. ⚠️ `wc -l` 은 **개행 수**라 본문이 개행으로 끝나지 않는 #658 에서 1 적게 나온다). 즉 이슈가 지목한 *"release PR 본문이 7 키워드 base 와 구조가 맞지 않는다"* 는 **이 구간에서 실재했고**, #668(2026-06-11)부터 작성자가 템플릿 체크리스트를 본문에 포함시키면서 사라졌다. §배경 정정 3 과 **같은 성격** — 도구 변경이 아니라 **작성 행위 변화**이고, 그래서 재발 가능하다.

#### 창 종속성 — 초판 헤드라인은 미고지 축소 창에서만 성립했다

축소 창 안의 수치 자체는 **참**이다. 그러나 선언 모집단으로 되돌리면 **분포가 뒤집힌다**:

| 창 | 첫 run `failure` | escape |
| --- | --- | --- |
| **선언 모집단 107 PR** | release **6** / prep **5** | **release 4 / prep 0** |
| 축소 창 `#902 이후` 34 PR | release 0 / prep **3** (#912 #964 #1032, 3/17 = **17.6%**) | release 0 / prep 0 |

⇒ **이슈 제목이 지목한 `release PR` 은 escape(실해) 축에서 정확하다.** 초판의 *"발생 위치가 이슈 제목과 다르다"* 는 **철회**한다. 정확한 서술은 두 문장이다:

1. **무정정 머지(실해)는 100% release PR** 에서 났고 **2026-06-10 에 멈췄다** — 이슈 제목이 맞다
2. **최근 창(#902~)의 첫 run `failure` 는 100% prep PR** 이고 **전건 자기 정정**됐다 (31초 / ~11분 / 7시간 44분) — **결정 4 가 겨냥하는 것은 이쪽**이다

본 ADR §재검토 조건 1-A 는 *"base rate 재산출 시 창을 명시한다"* 를 요구한다. **본문이 그 규칙을 먼저 지킨다** — 위 표가 두 창을 병기하는 이유다.

> **방법론 교훈 (자기 적용)**: 초판은 메인의 *"10 릴리스 표본 → 소멸"* 을 창 종속성으로 기각해 놓고, **같은 문서의 FAIL 축에서 같은 형태의 미고지 축소 창을 재도입**했다. 창을 쓰는 것 자체는 정당하다 — **선언하지 않은 것이 결함**이다.

### (a) 기각 근거를 정정한다 — ADR 971 인용은 오귀속이다

이슈 처리 과정에서 (a) 기각 근거로 *"가드에 base/head 분기를 넣는 것은 [20260807-971](20260807-971-required-status-checks.md) 이 경계하는 **축 증식**"* 이 제시됐다. **ADR 971 원문 대조 결과 이 인용은 성립하지 않는다.**

```text
$ grep -c "증식" docs/decisions/20260807-971-required-status-checks.md
0
```

ADR 971 의 *"축"* 논의는 **동일 이름 체크런이 한 SHA 위에서 ×N 으로 늘어나는 다중성 축**(event 축 / workflow 축 / event type 축 / PR 다중성 축)에 관한 것이며, 주제는 **required status check 하에서의 동명 해소 규칙**이다 (§2-11 / §2-12 / §10-1 한계 11~13). *"가드 로직에 조건 분기를 추가하는 것"* 을 경계하는 서술은 **ADR 971 에 존재하지 않는다.**

**(a) 의 기각 결론 자체는 유지되나 근거는 위 표 ②열(회전 원인 은폐)로 대체한다** — 이 근거는 인용이 아니라 본 ADR 의 749 셀 실측에서 직접 나온다.

> 참고로 ADR 971 에서 구조적으로 가장 가까운 서술은 §5 후보 (f) 기각 — *"cancelled 감지 시 자동 재실행"* 을 **CLAUDE.md §가드 설계 원칙의 "drift 가드에 fallback 분기 금지" 와 같은 구조** 로 기각한 대목이다. 그러나 이는 **fallback 분기 금지**이지 *"축 증식"* 이 아니며, 대상도 재실행 워크플로이지 판정 로직 분기가 아니다.

| **(iii) 별도 가드 신설** | **탐지 축에서 얻을 것이 없다** — 첫 run failure **11건 전부 가드가 정상 발화**했다 (탐지 실패 0). escape 4건은 **탐지 실패가 아니라 머지 게이트 부재**다(빨간 X 를 단 채 사람이 머지). 신규 가드도 required check 가 아닌 한 **탐지를 중복할 뿐 머지를 막지 못하고**, required 편입은 [20260807-971](20260807-971-required-status-checks.md) **결정 9-1** 이 본 가드 클래스를 명시 제외한 사안이다 ⇒ escape 4건에 대한 한계 수율 **0** | **기각** |

> ⚠️ **(iii) 기각 근거는 초판에서 교체됐다.** 초판은 *"머지된 빨간 X 0건 → 한계 수율 0"* 이라 적었는데 **전건이 거짓**이다(escape 4건). 그러나 결론은 유지된다 — 근거가 *"escape 가 없다"* 가 아니라 **"escape 는 탐지 축이 아니라 차단 축의 실패이고, 차단 축은 ADR 971 관할"** 이기 때문이다. §재검토 조건 3 이 이미 그 경로로 위임하고 있다. **거짓 전제를 지우고 참인 전제로 같은 결론에 도달한 것이지, 결론을 먼저 정하고 근거를 갈아끼운 것이 아니다** — 두 전제는 독립적으로 검증 가능하다 (탐지 실패 0 / ADR 971 결정 9-1 원문).

#### (ii) 채택의 실제 근거 — 규약은 이미 있었다. 없던 것은 **행위자에게 도달하는 경로**다

초판은 (ii) 를 *"`operational-friction.md` 가 본문 생성 경로를 지정하지 않던 공백"* 으로만 정당화했다. 그 서술은 **가장 강한 반론에 답하지 않는다** — `create-pr` 스킬 의무 규약은 **이미 5곳에 존재하고, 3건의 FAIL 보다 2~3개월 앞선다**:

```text
$ git grep -c 'PR 생성 시 반드시 `create-pr` 스킬 사용' -- .claude/agents/
.claude/agents/architect.md:1
.claude/agents/developer.md:1
.claude/agents/pm.md:1
.claude/agents/qa.md:1
.claude/agents/reviewer.md:1
$ git log --format='%h %ad' --date=short -S 'PR 생성 시 반드시 `create-pr` 스킬 사용' -- .claude/agents/
380a303 2026-05-16
```

규약이 5곳에 있는데도 #912(07-31) · #964(08-05) · #1032(08-13) 이 났다. 이 상태에서 6번째 산문 사본을 더하는 것은 표면상 *"이미 실패한 개입의 반복"* 이다.

**답은 청중이다 — 사본 5개가 전부 sub-agent 지시 파일인데, prep PR 을 만드는 주체는 메인 오케스트레이터다:**

```text
$ grep -c "create-pr" CLAUDE.md
0
$ grep -n "operational-friction" CLAUDE.md
245:… 표준 절차는 docs/ops/operational-friction.md 에 박제
```

메인의 지시 표면인 `CLAUDE.md` 에 규약이 **0건**이고, `operational-friction.md` 는 CLAUDE.md 가 릴리스 마찰 표준 절차로 **직접 가리키는** 문서다. ⇒ **결정 4 는 6번째 사본이 아니라 실패한 행위자에게 도달하는 첫 번째 사본이다.** 이것이 (ii) 채택의 주근거이며, *"왜 규약을 CLAUDE.md 본문이 아니라 릴리스 문서에 두는가"* 도 함께 답한다 (CLAUDE.md §예산 — 동일 주제 `docs/` 파일이 있으면 포인터만).

**(ii) 채택. 단 신규 문서·신규 절차를 만들지 않는다** — 이미 이 주제를 다루는 `operational-friction.md` §릴리스 부수 마찰 의 기존 불릿에 **본문 생성 경로 1줄**을 덧댄다. 강제력은 CI 가드가 이미 제공하므로 문서는 *지식 공백*만 메우면 된다.

> **YAGNI 와 "실해 0 이니 수용" 을 양쪽 다 경계한 결과다.** (iii) 은 수율 0 이라 YAGNI 에 걸리고, (i) 단독은 17.6% 를 0 으로 반올림한다. (ii) 는 비용 1줄 / 대상이 실측된 공백 / 강제력은 기존 가드 재사용이다.

## 재검토 조건

### 1-A. WARN 축 — (a)~(d) 재개봉 조건

> **연속 3 릴리스 사이클에서 WARN 셀 ≥ 1** 이면 (a)~(d) 를 재개봉한다.

기계 판정 술어 (정성 표현 없음):

```bash
# 1) 모집단 — 구조 조건으로 릴리스 클래스 추출
gh pr list --state merged --limit 300 \
  --json number,body,author,baseRefName,headRefName,mergedAt \
  | jq '[.[] | select(.baseRefName=="main" or (.headRefName|startswith("release/")))]' \
  > /tmp/rel.json

# 2) 판정 — 정본 스크립트에 위임 (판정식 재서술 금지, ADR 20260811-1010 결정 7)
node scripts/verify-pr-template-checklist.mjs --check-corpus /tmp/rel.json
```

> **`--limit 300` 의 구속 대상은 *과거 깊이* 이지 판정 창이 아니다** (cross-validate 보완). `gh pr list` 는 **최신순** 반환이라 판정에 필요한 *최신 3 사이클* 은 어떤 limit 값에서도 항상 포함된다 (실측: 300건이 2026-05-25 까지 도달해 릴리스 클래스 107 PR / 54 사이클을 덮는다). limit 을 올려야 하는 경우는 **base rate 를 재산출할 때뿐**이며, 그때는 위 §배경 표의 54 사이클을 기준선으로 삼고 창을 명시한다.

- **사이클 정의**: release PR (`base=main`) 1건 + 그 직전 prep PR (**`head^="release/"`** — 모집단 술어와 동일) 1건 = 1 사이클. 둘 중 **하나라도** WARN 셀 ≥ 1 이면 그 사이클을 WARN 으로 계상
- **발화 판정**: 최신 3 사이클이 **전부** WARN 사이클
- **재개봉 시 필수 입력**: WARN 키워드 서명. §배경 정정 2 대로 원인이 회전하므로, **3 사이클의 kw 집합이 동일한 경우에만** (a) 클래스 분기를 후보로 되살린다. 서명이 다르면 (a)/(b) 는 재차 기각이고 원인별 개별 처방으로 간다

> **사이클 술어는 모집단 술어와 동일해야 한다** (2026-08-13 정정 — reviewer N1). 초판은 사이클 정의만 `release/*-prep` 로 적어 모집단 술어(`release/*`)와 갈렸다. **`-prep` 접미는 #702 (2026-06-18) 부터의 관행**이라 53 prep 중 **10건**(#592 #635 #645 #651 #657 #667 #673 #679 #686 #691, 전부 `release/v0.NN.0` 형식)이 접미 없이 존재한다 — 마지막 구형은 **#691 `release/v0.28.0` (2026-06-16)** 이고, 첫 `-prep` 은 **#702 `release/v0.29.0-prep` (2026-06-18)** 이다. 두 술어로 base rate 가 갈린다:
>
> ```text
> head^="release/"       (모집단 술어, 채택) : 사이클 54 / WARN 19 (35.2%) / 최장침묵 17 / 말단 6
> head^="release/" ∧ -prep (초판 사이클 문언) : 사이클 54 / WARN 16 (29.6%) / 최장침묵 17 / 말단 6
> ```
>
> 결론 지표(최장침묵 17 / 말단 6)는 **불변**이라 판정은 바뀌지 않으나, 기준선 **35.2% 가 5.6pp 흔들린다**. 모집단 술어로 통일한다.

> ⚠️ **침묵을 소멸로 읽지 말 것.** 관측된 base rate: 54 사이클 중 WARN 사이클 **19 (35.2%)**, **최장 WARN=0 연속 17 사이클** (#792 2026-07-03 ~ #956 2026-08-04) 직후 **#965 에서 재발**. 따라서 *"N 사이클 조용했으니 클래스가 소멸했다"* 는 **N ≥ 18 이전에는 어떤 값으로도 성립하지 않는다.**

> ⚠️ **이 base rate 는 소급 재구성 값이다** (2026-08-13 부기 — reviewer N6). 가드 자체는 2026-05-17(`a1c1373`, #473) 부터 있으나 **3계급(WARN)은 2026-08-11(`ebd9866`, #1010) 도입**이다. 따라서 **#1000 이전 사이클에서 WARN 이 실발화한 적은 없고**, 35.2% 는 현재 판정식을 과거 본문 스냅샷에 **소급 적용**한 값이다 (가드가 출력 첫 줄에 `술어: … PR 본문 현재 스냅샷` 을 명시한다). 전 구간에 **동일** 술어를 균일 적용했으므로 *상대* 비교(말단 6 < 최장 17)는 유효하고 결론은 불변이다. 다만 1-A 가 이 값을 **미래의 실발화 WARN** 기준선으로 쓰므로 성격 차이를 병기한다. — 부수 효과로, 초판의 원 오판(*"WARN 이 v0.64.0 부터 소멸"*)이 **왜** 나왔는지도 설명된다: 소급 적용 값을 실발화로 읽었다.

### 1-B. FAIL 축 — 잔여 갭 처방 격상 조건

> **결정 4 (문서 1줄) 머지 이후** 릴리스 클래스 PR 의 첫 run `failure` 가 **30일 창에서 ≥ 2건** 이면 처방을 (ii) 문서 → **(iii) 별도 가드** 로 격상한다.

기계 판정 술어:

```bash
# 1) 모집단 — 30일 창의 릴리스 클래스 (1-A 필터 + mergedAt 창. 복붙 실행 가능하게 열거 단계 포함)
SINCE=$(date -u -v-30d +%Y-%m-%dT%H:%M:%SZ)   # GNU: date -u -d '30 days ago' +%Y-%m-%dT%H:%M:%SZ
gh pr list --state merged --limit 300 \
  --json number,baseRefName,headRefName,mergedAt \
  | jq -r --arg since "$SINCE" \
      '.[] | select((.baseRefName=="main" or (.headRefName|startswith("release/")))
                    and .mergedAt > $since) | .number' \
  > /tmp/rel30.txt

# 2) 각 PR 의 pr-template-checklist 첫 run conclusion → failure 건수 집계
while read -r N; do
  SHA=$(gh pr view "$N" --json headRefOid -q .headRefOid)
  C=$(gh api "repos/coseo12/astro-simulator/commits/${SHA}/check-runs?per_page=100" \
        --jq '[.check_runs[] | select(.name=="pr-template-checklist")]
              | sort_by(.started_at) | .[0].conclusion')
  [ "$C" = "failure" ] && echo "$N"
done < /tmp/rel30.txt | wc -l
```
