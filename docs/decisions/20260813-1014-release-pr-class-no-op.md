## 배경

이슈 #1014 는 *"`pr-template-checklist-guard` 가 release PR 클래스에서 **상습 발화**한다"* 로 (a)~(d) 택일을 요구했다. 착수 시점 실측 결과 **이슈 본문의 전제와 메인 오케스트레이터의 정정 코멘트가 둘 다 부분적으로 틀렸다.**

### 모집단을 구조 정의로 재수립했다

메인의 정정 코멘트는 v0.60.0~v0.69.0 **10 릴리스**만 봤다. 본 ADR 은 모집단을 **구조 조건**으로 재정의한다:

```text
release 클래스 ≔ (baseRefName == "main") ∨ (headRefName 이 "release/" 로 시작)
```

술어: `gh pr list --state merged --limit 300 --json number,body,author,baseRefName,headRefName,mergedAt` 산출물을 위 조건으로 필터 → **107 PR** (#592 2026-05-27 ~ #1033 2026-08-13), **54 릴리스 사이클**. 각 PR 본문에 대해 판정 정본 `node scripts/verify-pr-template-checklist.mjs --check-corpus <json>` 을 돌려 셀 계급을 센다 (7 kw × 107 PR = **749 셀**).

전수 결과: **PASS 671 / WARN 52 / FAIL 26**.

### 정정 1 — WARN 클래스는 "소멸" 하지 않았다. 간헐적이고, 이미 한 번 더 긴 침묵 뒤에 재발했다

사이클 단위 (prep PR + release PR 을 한 사이클로 묶고, 둘 중 하나라도 WARN 셀 ≥ 1 이면 그 사이클을 WARN 으로 계상):

| 구간 | 사이클 | WARN 사이클 |
| --- | --- | --- |
| 전체 (#593 ~ #1033) | 54 | **19 (35.2%)** |
| 최장 WARN=0 연속 | — | **17 사이클** (#792 2026-07-03 ~ #956 2026-08-04) |
| 현재 말단 WARN=0 연속 | — | **6 사이클** (#1001 2026-08-09 ~ #1033 2026-08-13) |

**결정적 관측**: 17 사이클 연속 WARN=0 이 있었고, 그 침묵은 **#965 (v0.60.0, 2026-08-05) 에서 깨졌다** — 이슈가 인용한 바로 그 클러스터다.

⇒ 메인이 *"연속 6 릴리스 소멸"* 을 소멸의 근거로 쓴 것은 **성립하지 않는다.** 같은 모집단이 과거에 그 3배 가까운 침묵(17) 뒤에 재발한 이력이 있으므로, 6 사이클은 관측 잡음 대역 안이다.

### 정정 2 — WARN 클러스터의 키워드 서명이 매번 다르다. 단일 클래스가 아니다

| 클러스터 | 사이클 | WARN 키워드 |
| --- | --- | --- |
| #593 (2026-05-28) | 1 | kw1 커밋 컨벤션 / kw2 불필요한 변경 |
| #616 (2026-06-04) | 1 | kw7 Test plan |
| #636 (2026-06-08) | 1 | kw4 SSoT / kw5 cross-validate |
| #703 ~ #708 (2026-06-18) | 2 | kw6 ADR 호환성 + kw7 |
| #736 ~ #748 (2026-06-22~25) | 3 | kw6 |
| #772 ~ #787 (2026-06-30~07-02) | 4 | kw6 |
| **#965 ~ #992 (2026-08-05~08)** | **4** | **kw3 보안 / kw4 SSoT** |

같은 자리에서 같은 이유로 반복되는 것이 아니라, **원인이 매번 회전한다.** kw 별 WARN 총계도 특정 키워드에 몰리지 않는다 — kw6 **20** / kw7 **10** / kw4 **9** / kw3 **8** / kw1 **2** / kw2 **2** / kw5 **1** 로 **7 키워드 전건에 분포**한다.

이것이 (a)/(b) 기각의 핵심 근거다 — 클래스 단위 예외·전용 템플릿은 **아직 관측되지 않은 미래의 원인까지 영구히 가린다.**

### 정정 3 — *"(c) 가 이미 구현돼서 WARN 이 끊겼다"* 는 인과 주장은 시간순으로 성립 불가다

메인은 `create-pr` 스킬이 템플릿을 직접 읽어 `[ ]` → `[x]` **in-place 갱신만** 하는 규약을 근거로 *"WARN 이 v0.64.0 에서 끊긴 것과 정합한다"* 고 했다. **그 규약의 도입 시점을 실측하면 정합하지 않는다.**

```text
$ git log --format='%h %ad' --date=short \
    -S '갱신만 허용 (라인 자체 변경·삭제 금지)' -- .claude/skills/create-pr/SKILL.md
94bf614 2026-05-16
```

`-S` 가 **단일 커밋**만 반환한다 — 이 규약 문언은 **2026-05-16 (`94bf614`, #471 / PR #478) 에 도입된 뒤 오늘까지 한 번도 변경되지 않았다.** 즉 위 표의 **7개 WARN 클러스터 전부가 이 규약이 이미 발효 중인 상태에서 발생**했다.

**상수는 변화를 설명할 수 없다.** #1010 의 PR (`ebd9866`, 2026-08-11) 역시 현재 침묵 구간의 시작(#1000, 2026-08-09)보다 **뒤**다.

⇒ **현재 WARN=0 침묵의 메커니즘은 미확인이다.** 본 ADR 은 이를 *"관행이 이미 고쳤다"* 로 서술하지 않는다 — 그렇게 박제하면 미래 관찰자가 존재하지 않는 방어를 믿게 된다.

### FAIL 축 — 재현했고, 발생 위치가 이슈 제목과 다르다

첫 run conclusion 을 독립 조회했다 (술어: `gh api repos/coseo12/astro-simulator/commits/<headRefOid>/check-runs`, `name=="pr-template-checklist"` 를 `started_at` 오름차순 정렬 후 첫 원소 — 사후 본문 편집으로 계급이 바뀌어도 첫 발화는 남는다).

#902 이후 릴리스 클래스에서 첫 run `failure` 는 **3건**:

| PR | 일자 | 종류 | 재발화까지 | 내용 |
| --- | --- | --- | --- | --- |
| #912 | 2026-07-31 | **prep** | **31초** | — |
| #964 | 2026-08-05 | **prep** | ~11분 | — |
| #1032 | 2026-08-13 | **prep** | ~8시간 | **FAIL 6 / PASS 1** — 체크리스트 통째 누락 |

**3건 전부 prep PR (head=`release/*-prep`, base=`develop`) 이고, release PR (base=`main`) 은 0건이다.** 이슈 제목이 *"release PR 본문"* 을 지목한 것과 실제 발생 위치가 다르다. 같은 창의 prep PR 은 17건이므로 **3/17 = 17.6%**.

**전건 자기 정정됐고, 빨간 X 인 채 머지된 릴리스 클래스 PR 은 0건이다.**

**판정 기준**: ① 현재 관측된 문제를 해결하는가 ② 아직 관측되지 않은 원인을 가리지 않는가 ③ 도입 비용 대비 실측 수율.

| 안 | 현재 문제 해결 | 미래 원인 은폐 | 실측 수율 | 판정 |
| --- | --- | --- | --- | --- |
| **(a)** release 전용 템플릿 + 가드가 base/head 로 클래스 분기 | 해결할 WARN 이 현재 0 | **전면 은폐** — 7 kw 전건에 분포한 회전 원인을 클래스째로 면제 | 0 | **기각** |
| **(b)** release PR 을 가드 대상에서 제외 (`head_ref != 'develop'`) | 〃 | **(a) 보다 심함** — FAIL 축까지 함께 소멸. #1032 (FAIL 6/7) 가 무신호로 머지됐을 것 | 음수 | **기각** |
| **(c)** `create-pr` 스킬이 7 키워드 base 를 자동 병합 | **이미 구현됨** (`94bf614`, 2026-05-16 — 규약 / `ebd9866`, 2026-08-11 — WARN 회피 명문) | — | 추가분 0 | **이미 이행 — 신규 작업 없음** |
| **(d)** 현행 유지 + WARN 을 release 클래스 정상 상태로 수용 | 수용할 WARN 이 현재 0 | 수용 선언 자체가 미래 WARN 을 사전 정당화 | 0 | **기각** |
| **★ 현행 유지 (채택)** | 현재 문제 없음 | 은폐 없음 — WARN 이 회전 원인을 매번 포착해 왔다 | 0 코드 변경 | **채택** |

### (a) 기각 근거를 정정한다 — ADR 971 인용은 오귀속이다

이슈 처리 과정에서 (a) 기각 근거로 *"가드에 base/head 분기를 넣는 것은 [20260807-971](20260807-971-required-status-checks.md) 이 경계하는 **축 증식**"* 이 제시됐다. **ADR 971 원문 대조 결과 이 인용은 성립하지 않는다.**

```text
$ grep -c "증식" docs/decisions/20260807-971-required-status-checks.md
0
```

ADR 971 의 *"축"* 논의는 **동일 이름 체크런이 한 SHA 위에서 ×N 으로 늘어나는 다중성 축**(event 축 / workflow 축 / event type 축 / PR 다중성 축)에 관한 것이며, 주제는 **required status check 하에서의 동명 해소 규칙**이다 (§2-11 / §2-12 / §10-1 한계 11~13). *"가드 로직에 조건 분기를 추가하는 것"* 을 경계하는 서술은 **ADR 971 에 존재하지 않는다.**

**(a) 의 기각 결론 자체는 유지되나 근거는 위 표 ②열(회전 원인 은폐)로 대체한다** — 이 근거는 인용이 아니라 본 ADR 의 749 셀 실측에서 직접 나온다.

> 참고로 ADR 971 에서 구조적으로 가장 가까운 서술은 §5 후보 (f) 기각 — *"cancelled 감지 시 자동 재실행"* 을 **CLAUDE.md §가드 설계 원칙의 "drift 가드에 fallback 분기 금지" 와 같은 구조** 로 기각한 대목이다. 그러나 이는 **fallback 분기 금지**이지 *"축 증식"* 이 아니며, 대상도 재실행 워크플로이지 판정 로직 분기가 아니다.

## 잔여 갭 — 스킬 우회 경로

스킬의 pre-flight 는 **스킬을 탈 때만** 작동한다. #1032 는 `gh pr create --body-file` 직접 호출로 체크리스트를 통째로 누락했다. 이 잔여를 어떻게 처리할 것인가.

| 안 | 근거 | 판정 |
| --- | --- | --- |
| **(i) 수용** — CI 가드가 이미 backstop | 빨간 X 인 채 머지 **0건**. 실해 상한이 낮다 ([20260807-971](20260807-971-required-status-checks.md) 결정 9-1 — required 아님) | **부분 기각** — 실해가 0 이 아니다. 3/17 = **17.6%** 이고 #1032 는 릴리스 흐름을 ~8시간 끊었다 |
| **(ii) 스킬 사용 강제 규약** | 릴리스 의례 문서 [`docs/ops/operational-friction.md`](../ops/operational-friction.md) §릴리스 부수 마찰 은 *"release prep PR 필수"* 를 규정하면서 **본문 생성 경로를 지정하지 않는다.** 내용 요건(7 키워드 + 체크박스 구조)은 있으나 *"어떻게 만드는가"* 가 비어 있다 — 3건의 FAIL 이 전부 이 공백에서 났다 | **채택** |
| **(iii) 별도 가드 신설** | CI 가드가 이미 backstop 이고 포착률 100% (머지된 빨간 X 0건). 신규 가드의 한계 수율 = **0** | **기각 — YAGNI** |

**(ii) 채택. 단 신규 문서·신규 절차를 만들지 않는다** — 이미 이 주제를 다루는 `operational-friction.md` §릴리스 부수 마찰 의 기존 불릿에 **본문 생성 경로 1줄**을 덧댄다. 강제력은 CI 가드가 이미 제공하므로 문서는 *지식 공백*만 메우면 된다.

> **YAGNI 와 "실해 0 이니 수용" 을 양쪽 다 경계한 결과다.** (iii) 은 수율 0 이라 YAGNI 에 걸리고, (i) 단독은 17.6% 를 0 으로 반올림한다. (ii) 는 비용 1줄 / 대상이 실측된 공백 / 강제력은 기존 가드 재사용이다.

## 결정

### 1. 구현 변경 없음 — NO-OP

가드 스크립트 / 워크플로 / PR 템플릿 / 판정식을 **변경하지 않는다.** (a) (b) (d) 전건 기각, (c) 는 2026-05-16 부터 이미 이행 중이다.

### 2. *"관행이 고쳤다"* 를 박제하지 않는다

현재 6 사이클 WARN=0 의 **메커니즘은 미확인**이다 (§배경 정정 3). 확인되지 않은 인과를 방어 기제로 기록하면 미래 관찰자가 존재하지 않는 보호를 신뢰한다. 본 ADR 은 침묵을 **관측 사실로만** 기록한다.

### 3. 회귀 감시는 신규 가드 없이 기존 자산으로 한다

새 가드를 만들지 않는다. 이미 존재하는 결정적 가드가 본 판정의 회귀 감시 지점이다:

| 감시 대상 | 기존 자산 | 성격 |
| --- | --- | --- |
| kw3 체크박스 → `### 보안` 헤더 침식 (#965~#992 클러스터의 정확한 재현) | `verify-pr-template-checklist.mjs --self-test` **픽스처 F2** | 결정적 · `project-guards.yml` 배선됨 |
| 계급 비대칭 (kw6 를 체크박스로만) | 〃 **F5** | 결정적 |
| 스킬 우회 (체크리스트 통째 누락 — #1032 클래스) | `pr-template-checklist-guard.yml` (CI backstop) | 실 PR 발화 · 포착률 100% |
| 클래스 전수 재현 | `--check-corpus` | 1회성 증거 (CI 미배선 — 네트워크 의존) |

**#1014 가 요구한 *"release PR 1건에서 실제 run 결과로 재현 확인"* 은 본 ADR 의 749 셀 전수 + 첫 run conclusion 조회로 충족된다** (1건이 아니라 54 사이클 전수).

### 4. 릴리스 의례 문서에 본문 생성 경로를 명시한다 (잔여 갭 (ii))

`docs/ops/operational-friction.md` §릴리스 부수 마찰 의 *"release prep PR 필수"* 불릿에 본문 생성 경로 1줄을 추가한다. **문서 변경 1줄이 전부이며 코드·워크플로 변경은 없다.**

### 5. 선행 ADR §재검토 조건 1항을 기계 판정 가능하게 대체한다

[20260811-1010](20260811-1010-measurement-c-verdict-tiers.md) §재검토 조건 1항의 *"연속 3 릴리스에서 **지속 발화**"* 는 (ㄱ) 술어 미정의 (ㄴ) base rate 미기록으로 **침묵을 소멸로 오독할 여지**가 있었다 — 실제로 그 오독이 이 이슈 처리 중에 발생했다. 아래 §재검토 조건 1-A / 1-B 가 대체 문언이며, ADR 1010 에는 본 ADR 로의 포인터를 Amendment 로 박제한다.

## 재검토 조건

### 1-A. WARN 축 — (a)~(d) 재개봉 조건

> **연속 3 릴리스 사이클에서 WARN 셀 ≥ 1** 이면 (a)~(d) 를 재개봉한다.

기계 판정 술어 (정성 표현 없음):

```bash
# 1) 모집단 — 구조 조건으로 릴리스 클래스 추출
gh pr list --state merged --limit 300 \
  --json number,body,author,baseRefName,headRefName,mergedAt \
  | jq '[.[] | select(.baseRefName=="main" or (.headRefName|startswith("release/")))]' \
  > /tmp/rel.json

# 2) 판정 — 정본 스크립트에 위임 (판정식 재서술 금지, ADR 20260811-1010 결정 7)
node scripts/verify-pr-template-checklist.mjs --check-corpus /tmp/rel.json
```

- **사이클 정의**: release PR (`base=main`) 1건 + 그 직전 prep PR (`head=release/*-prep`) 1건 = 1 사이클. 둘 중 **하나라도** WARN 셀 ≥ 1 이면 그 사이클을 WARN 으로 계상
- **발화 판정**: 최신 3 사이클이 **전부** WARN 사이클
- **재개봉 시 필수 입력**: WARN 키워드 서명. §배경 정정 2 대로 원인이 회전하므로, **3 사이클의 kw 집합이 동일한 경우에만** (a) 클래스 분기를 후보로 되살린다. 서명이 다르면 (a)/(b) 는 재차 기각이고 원인별 개별 처방으로 간다

> ⚠️ **침묵을 소멸로 읽지 말 것.** 관측된 base rate: 54 사이클 중 WARN 사이클 **19 (35.2%)**, **최장 WARN=0 연속 17 사이클** (#792 2026-07-03 ~ #956 2026-08-04) 직후 **#965 에서 재발**. 따라서 *"N 사이클 조용했으니 클래스가 소멸했다"* 는 **N ≥ 18 이전에는 어떤 값으로도 성립하지 않는다.**

### 1-B. FAIL 축 — 잔여 갭 처방 격상 조건

> **결정 4 (문서 1줄) 머지 이후** 릴리스 클래스 PR 의 첫 run `failure` 가 **30일 창에서 ≥ 2건** 이면 처방을 (ii) 문서 → **(iii) 별도 가드** 로 격상한다.

기계 판정 술어:

```bash
# 릴리스 클래스 PR 의 pr-template-checklist 첫 run conclusion
SHA=$(gh pr view <N> --json headRefOid -q .headRefOid)
gh api "repos/coseo12/astro-simulator/commits/${SHA}/check-runs?per_page=100" \
  --jq '[.check_runs[] | select(.name=="pr-template-checklist")]
        | sort_by(.started_at) | .[0].conclusion'
```

- **기준선 (본 ADR 시점)**: 3건 / 13일 (#912 · #964 · #1032) — 전건 prep PR
- **임계값 근거**: 기준선 밀도(≈1.6/주)를 결정 4 가 **절반 이하로** 떨어뜨리지 못하면 문서 처방이 실패한 것이다. 30일 창 ≥ 2건 = 문서 개정이 무효였다는 기계 증거
- **격상 시 후보**: prep PR 생성 시점 로컬 pre-commit / `release/*-prep` 브랜치 push 훅 등. **단 (b) 계열(가드 대상 제외)로는 절대 격상하지 않는다** — 방향이 반대다

### 2. 침묵의 메커니즘이 식별되면 결정 2 를 갱신한다

현재 6 사이클 WARN=0 의 원인은 미확인이다 (§배경 정정 3). 원인이 식별되면 (예: 특정 커밋·절차 변경과의 시점 정합이 실측되면) 결정 2 를 그 사실로 대체하고, 그 방어 기제의 회귀 가드를 신설할지 재판정한다.
