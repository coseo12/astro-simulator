## 통합·분리 판정 — 한 ADR 로 합친다 (#1064 완료 기준 3항)

#1064 완료 기준이 명시적으로 요구한 판정이다. **통합**한다.

**축은 실제로 다르다** — #1031 은 *"인용 **식별자**(CI run id / 커밋 SHA)를 API 로 대조"*, #1064 는 *"박제 **술어**를 재실행해 박제값과 대조"* 다. 그럼에도 합치는 근거 4항:

1. **판정이 갈리지 않았다.** 두 축이 각각 독립 측정으로 **같은 결론(기각)** 에 도달했고, 잔여 처방도 **같다**(SSoT 수렴 — 아래 §결정 5). 판정이 갈렸다면(한쪽 채택 / 한쪽 기각) 분리가 **의무**였다. 이 반례 조건을 명시해 둔다
2. **측정 인프라가 공유된다.** 두 축 모두 같은 코퍼스(`docs` `.claude` `CLAUDE.md` `CHANGELOG.md`)를 같은 rev 에서 스캔했고, 기각 근거의 뼈대인 **시간 종속 5분류**(`T0`~`T4`)는 두 축에 공통 적용된다
3. **분리하면 본 ADR 이 겨누는 결함을 스스로 생성한다.** 두 문서가 서로의 수치를 인용해야 하고, 그 순간 [`20260808-983`](20260808-983-measurement-recording-convention.md) 오기록 4(부분 재측정)·6(술어 비교환)의 **다문서 판본**이 만들어진다. 규약을 만들면서 그 규약이 잡아낼 대상을 남기는 자기모순은 #983 초판이 이미 밟은 경로다
4. **[`README.md`](README.md) §규약 11 (_"1 ADR = 1 결정"_) 과 정합한다.** 본 ADR 의 결정은 **하나** — _"커밋된 산출물 안의 「검증 가능한 거짓」에 대해 기계 대조 가드를 도입하지 않는다"_ 다. #1031·#1064 는 그 결정의 **두 인스턴스**(식별자 축 / 술어 축)이지 두 결정이 아니다. #1031 스코핑 질문 5번이 #1064 의 일반형이라는 계보가 이 동일성의 방증이다

### Forensic 변형 판정 — 일반 ADR 로 쓴다

CLAUDE.md §Forensic ADR 변형 5조건 중 **3항 충족**(가설 N≥2 / runtime 측정 필수 / 5±2 옵션 비교)이라 형식상 문턱(3개 이상)에 닿는다. 그럼에도 **일반 ADR** 을 택한다.

## 배경

PR [#1023](https://github.com/coseo12/astro-simulator/pull/1023) 의 블로킹 4건과 PR [#1061](https://github.com/coseo12/astro-simulator/pull/1061) 의 수치 오류 4라운드는 **한 클래스**다 — *"커밋된 산출물 안의, 검증 가능한 거짓"*. 코드 동작은 매번 정상이었고 틀린 것은 **근거·수치 문장**이었다.

### PR #1061 이 이 공백의 비용을 4라운드로 실측했다

| 라운드 | 형태 | 검출자 |
| --- | --- | --- |
| 1 | delta(`39`)를 감시값(계수) 자리에 | reviewer |
| 2 | 디렉토리 전체 파일수(`42`)를 PNG 계수 자리에 | reviewer |
| 3 | **술어를 적었는데 실행하면 `0`** — `git ls-files 'docs/{a,b}/'` 는 작은따옴표가 brace expansion 을 죽여 git 이 리터럴 pathspec 으로 읽는다 | 메인 독립 재현 |
| 3 | 자기참조 계수 노화(`hit 2` 가 자기 편집으로 `4`) / 술어 없는 절대수 | 메인 독립 재현 |

**결정적 비대칭** — 손으로 센 계수는 **4/4 틀렸고**, 기계가 뱉은 계수(`--population` / `prettier --file-info` / 가드 출력)는 **0/4 틀렸다**.

**라운드 3 이 설계상 가장 중요하다.** 라운드 2 의 처방이 *"술어를 명시하라"* 였는데 **그 명시된 술어가 실행되지 않았다.** 즉 [`20260808-983`](20260808-983-measurement-recording-convention.md) (iv) 의 표기 규약화는 **필요조건이지 충분조건이 아니다** — *"적은 술어가 그 값을 실제로 낸다"* 가 남는다. 이 잔여가 #1064 의 발의 근거다.

### 두 이슈가 지목한 공백은 같은 문장으로 표현된다

[`20260808-983`](20260808-983-measurement-recording-convention.md) §(ii)·(iv) 는 **규범으로 존재하지만 발화 지점이 0** 이라 매번 주의력에 의존한다. 이것은 PR #1061 이 `.prettierignore` 에서 고친 결함(*"선언은 있는데 동작이 0"*)과 **같은 형태**이며, 본 ADR 은 이 사실 자체를 결론과 무관하게 박제한다 (아래 §결정 6).

## 술어 정본 규약 (본 ADR 의 자기 적용)

본 ADR 은 *"박제 술어가 그 값을 내는가"* 를 다룬다. **자기 자신이 그 규약을 위반하면 그 자체로 결함**이므로 아래 3항을 스스로 지킨다.

1. **모든 절대수에 재현 가능한 술어를 동반한다.** 술어는 **rev 를 인자로 받는 형태**로 적는다 — 산문에 rev 를 적고 명령은 워킹트리 형태로 두면 결속이 자연어 대용(anaphora)이 되어 기계 재현이 성립하지 않는다 (이 실패가 아래 §측정 3 의 핵심 발견이다)
2. **박제 전에 술어를 추출해 그대로 실행하고 값이 재현되는지 확인했다.** 본 문서의 모든 rev 고정 술어는 작성 중 1회 실행됐다
3. **네트워크 조회분은 rev 를 갖지 않는다.** GitHub API GET 결과는 조회 일자(2026-08-14)로만 고정되며, 위 1항의 재현 보장 **밖**이다. 이 경계를 명시하지 않으면 *"재현 가능"* 이 과대 주장이 된다

각 술어를 **(a) 그 ADR 이 산문에 고정한 rev** 와 **(b) 현재 `38b6c8a`** 에서 실행했다.

| --- | --- | --- | ---: | ---: |
| 1 `983:255` | `2 hits / 2 files` | `aeb6c07` (§측정 헤더) | **2** ✅ | **3** ✗ |
| 2 `958:142` | `63` | `7ca1cd1` (헤더 §측정 rev) | **63** ✅ | **63** ✅ |

이탈 2건의 원인은 각각 다르고, 둘 다 **구조적**이다.

- **3번은 트리 시간 종속이다.** `CHANGELOG.md` 에 새 entry 가 들어오면 계수가 증가한다. 이탈은 정상 운영의 부산물이다

### 측정 3-1 — rev 결속은 자연어 대용(anaphora)이라 기계가 잇지 못한다

3번의 rev 결속 경로를 전수 추적하면 **4-hop 자연어 사슬**이다:

```text
982 헤더 :9   "측정 rev: `5651980` (origin/develop tip, 2026-08-14)"
   → :34     "격리 재현 (본 rev 워크트리, …)"
   → :84     "술어 (본 rev 워크트리, `pnpm install --frozen-lockfile` 후):"
   → :106    "세 후보 술어를 같은 rev 에서 CHANGELOG.md 에 적용한 결과"
   → :118    (펜스 — 명령 자신에는 rev 가 없다)
```

_"본 rev"_ · _"같은 rev"_ 는 선행사 해소를 요구하는 **대용 표현**이다. 이것을 기계가 잇는 것은 [`20260808-983`](20260808-983-measurement-recording-convention.md) §Amendment 2 가 _"판정 = 의미론이라 기계 불가"_ 로 마감한 것과 **같은 벽**이다.

> **더 결정적인 사실 — rev 를 술어 안에 넣으면 명령 형태 자체가 달라진다.** 위 2번을 rev 고정으로 재실행하려면 `git ls-files …` 가 아니라 **`git ls-files --with-tree=7ca1cd1 …`** 여야 하고, 1·3번은 `git grep <패턴> <rev>` 로 인자가 하나 더 붙는다. 즉 현행 관행(_"산문에 rev, 명령은 워킹트리 형태"_)은 **표기만 고쳐서 기계화되는 대상이 아니라 술어 자체를 다시 써야 하는 대상**이다. 소급 대상 3건 전부가 재작성을 요구한다.

### 측정 4 — 실행 안전성: 동기가 된 술어 자신이 allowlist 를 통과할 수 없다

#1064 스코핑 질문 3의 답이다.

2번 술어는 `git ls-files docs/… | awk -F/ 'NF>3'` 이며, `awk` 는 *"중첩(깊이 2+)"* 이라는 **술어의 정의 그 자체**를 담당한다. 파이프를 떼면 술어가 성립하지 않는다. 그런데 `awk` 는 `system()` 을 보유한 튜링 완전 언어이므로, **`awk` 를 allowlist 에 넣는 것은 임의 명령 실행을 허용하는 것과 동치**다.

- **명령 이름 allowlist 는 이 축을 막지 못한다** — 첫 토큰이 `git ls-files` 여도 파이프 뒤가 임의 코드다
- **파이프 금지 allowlist 는 동기가 된 술어를 배제한다** — 3건 중 1건이 즉시 탈락하고, 남는 2건은 이미 §측정 3 에서 오탐 2건을 낸 쪽이다
- 참고로 `docs` 의 셸 펜스에서 파이프·명령 치환·리다이렉트를 포함하는 비율은 과반이다 (1회성 분류기 관측 — 위 ⚠️ 와 같은 한정자가 붙는다)

> ⚠️ **과잉 일반화 금지 지점 (#1031 코멘트 명시).** 라운드 3 의 교훈은 *"따옴표를 다 벗겨라"* 가 **아니다**. git pathspec 의 `*` 글로브는 git 이 직접 처리하므로 따옴표가 **오히려 안전**하다 (`git ls-files 'docs/reports/*/*.md'`). 셸 확장이 필요한 것은 **brace 뿐**이다. 그리고 [`20260814-958`](20260814-958-prettier-live-docs-scope.md)`:146` 이 이미 이 구분을 적었다 — _"따옴표만 벗기는 대안은 셸 의존이라 또 다른 재현 함정을 만든다"_. 채택된 처방은 **경로 나열**이었다. allowlist 설계가 이 구분을 잃으면 처방이 결함을 재생산한다.

### 측정 5 — diff 스코프 변형 (가장 유망한 변형 — 역시 0)

전수 대신 **추가행만** 검사하는 변형은 [`20260808-983`](20260808-983-measurement-recording-convention.md) §Amendment 2 (5) 가 *"가장 유망"* 으로 평가한 형태이므로 별도 측정한다. 직전 **30 non-merge 커밋**, 경로 `docs` `.claude` `CLAUDE.md` `CHANGELOG.md`:

```bash
git log --no-merges -n 30 --format=%H 38b6c8a | while read c; do
  git show --format= --unified=0 "$c" -- docs .claude CLAUDE.md CHANGELOG.md
done | grep '^+[^+]' | wc -l                 # 추가행 3439
```

| 축 | 값 | 미해석 / 위반 |
| --- | ---: | ---: |
| 신규 고유 hex 토큰 (a-f 강제) | 46 | **0** |
| 신규 CI run id | 2 | **0** (`31604809249` `31604814344` 전건 API 해석) |
| 신규 셸 펜스 개시행 | 36 | 진짜 쌍 유입률 ≈ `0.1/커밋` (§측정 2 의 3건이 모두 최근 구간 산물) |

**diff 스코프 축 A 는 30 커밋에서 발화 `0`.** 발화하지 않는 가드는 회귀를 막지 못하며, 유일한 효과는 CI 네트워크 의존 추가다.

### 측정 6 — FAIL/WARN 방향별 계급: *"감소 = 회귀 신호"* 가 실측 반증됐다

#1064 스코핑 질문 4의 답이다. [`20260814-982`](20260814-982-changelog-tilde-guard.md) §후속 감시는 _"증가는 정상 … **감소는 `.prettierignore` 회귀 신호**"_ 라는 비대칭을 규정했고, #1064 는 이를 `20260811-1010` 3계급 선례에 태울 수 있는지 물었다.

모집단(`prettier ignored: false` 인 `*.md`)의 이력 변동을 직전 **250 non-merge 커밋**(2026-05-25 ~ 2026-08-14)에서 측정했다. 현행 `.prettierignore` live-set 정의를 과거 트리에 소급 적용한 값이다:

```bash
RE='^(CHANGELOG\.md|README\.md|packages/[^/]+/README\.md|docs/(benchmarks|phases|reports)/.*\.md|docs/retrospectives/(.*/)?[^/]*-retrospective\.md)$'
git log --no-merges -n 250 --format=%H 38b6c8a | while read c; do
  git ls-tree -r "$c" --name-only | grep -cE "$RE"
done | uniq -c            # 45×76 / 46×47 / 45×62 / 44×65  (최신 → 과거)
```

- **[실측]** 파일 집합 멤버십은 git 이력에서 직접 도출됐고, HEAD 값 **45** 는 `node scripts/verify-md-tilde.mjs --population` 실측(`prettier ignored: false : 45`)과 **일치**해 근사식의 타당성이 확인된다
- **[가정]** 과거 구간은 현행 `.prettierignore` 를 소급 적용한 **반사실 값**이다. 실제로는 #958 이전 negation 이 죽어 있어 관측값이 `5` 로 고정돼 있었다. 미래 변동률의 예측치로만 쓴다

**전이 3회 / 250 커밋 = `1.2%`.** 낮다 — [`20260808-983`](20260808-983-measurement-recording-convention.md) §기각 1 이 경계한 *"정상 변경마다 문서를 고쳐야 발화가 멎는 의례"* 는 성립하지 않는다.

**그러나 유일한 감소가 오탐이다.** `46 → 45` 전이의 원인 커밋은 `0c316f0` (**#905 감사 P0 위생 — 고아 정리**, PR #906) 이며, 삭제된 live-set 파일은 `docs/benchmarks/newton-1000y.md` · `p11-b-bench-20260424.md` · `p11-b-osculating-observation-20260424.md` **3건의 정당한 고아 문서**다. `.prettierignore` 회귀가 아니다.

> ⚠️ **위 술어의 `RE` 는 rev `38b6c8a` 시점 `.prettierignore` 게이트의 파생이다.** PR [#1072](https://github.com/coseo12/astro-simulator/pull/1072)([#1063](https://github.com/coseo12/astro-simulator/issues/1063))가 `docs/retrospectives/` 게이트를 `**/*-retrospective.md` → `**/*.md` 로 통일하므로, 머지 후 재실행하려면 `RE` 의 마지막 대안을 `docs/retrospectives/.*\.md` 로 바꿔야 한다 (그 결과 계수는 `45` → `49`, 편입 4건 = `README.md` · `P1-a11y.md` · `P1-browser-compat.md` · `P1-perf.md`). **술어를 갱신하지 않고 재실행하면 표가 재현되지 않으며**, 그것이 PR [#1069](https://github.com/coseo12/astro-simulator/pull/1069) 가 [`20260811-1010`](20260811-1010-measurement-c-verdict-tiers.md)`:200` 에서 발견한 것과 같은 형태다. 아래 결론은 **파일 삭제/추가 이력** 위에 서 있어 게이트 정의 변경에 영향받지 않는다.

> **⇒ *"감소 ⇒ 회귀"* 는 관측된 유일 사례에서 반증된다. 방향별 FAIL 계급의 정밀도는 `0/1`.**
> [`20260811-1010`](20260811-1010-measurement-c-verdict-tiers.md) 의 WARN 축이 성립한 이유는 `phraseHits ≥ 1 ∧ structureHits = 0` 이라는 **관측 가능한 중간 상태가 실재**했기 때문이다. 본 건의 *"감소"* 는 중간 상태가 아니라 **정상과 회귀가 같은 관측값을 공유**하는 구간이며, 계급을 가를 축이 없다.

### 측정 7 — 살아 있는 drift: 관측 도구 자신이 틀린 기대값을 출력한다

설계 중 발견한 **현행 결함**이다.

```bash
node scripts/verify-md-tilde.mjs --population
#   prettier ignored: false : 45          ← 실측 (정확)
#   ADR 박제값은 5 다.                     ← 하드코딩 (틀림)
```

- ADR 정본 감시값은 **45** ([`20260814-982`](20260814-982-changelog-tilde-guard.md) §Amendment 2026-08-14)
- 스크립트는 **`5`** 를 두 곳에 하드코딩한다 — `scripts/verify-md-tilde.mjs:62` (헤더 주석) / `:390` (출력 문자열)
- exit code 는 `0` 이고 어떤 경고도 없다

**#1064 가 *"감시값이 문서에만 있다"* 고 적었으나, 실제로는 더 나쁘다 — 감시값이 문서와 스크립트 **두 곳에** 있고 이미 갈렸으며, 관측 도구가 틀린 기대값을 옳은 실측값 **바로 옆 줄에** 출력하면서 아무것도 발화하지 않는다.** 이것은 산문 술어 실행 문제가 아니라 **SSoT 중복** 문제이며, volt [#120](https://github.com/coseo12/volt/issues/120) (_"drift 감지보다 중복 출처 제거가 근본"_)의 관할이다.

> **독립 재현 (병행 PR)** — PR [#1072](https://github.com/coseo12/astro-simulator/pull/1072) 가 같은 drift 를 독립 발견하고 **누락 횟수까지 실측했다**: 하드코딩 `5` 는 `5` → `45`([#958](https://github.com/coseo12/astro-simulator/issues/958)) · `45` → `49`([#1063](https://github.com/coseo12/astro-simulator/issues/1063)) **두 갱신에서 연속 2회** 누락됐다. 이 `n=2` 가 §결정 5 의 방향 판정을 (f-A)에서 (f-B)로 뒤집은 결정적 증거다 — **사본을 옮기면 세 번째 누락이 스크립트 쪽에서 나고, 사본을 없애야 누락 자체가 불가능해진다.** ⚠️ 위 `45` 는 rev `38b6c8a` 기준이며, #1072 브랜치는 `.prettierignore` 게이트를 통일해 같은 술어가 **`49`** 를 낸다 — 두 값은 **모집단 정의가 다르므로 병치 시 관계를 명시한다** ([`20260808-983`](20260808-983-measurement-recording-convention.md) (iv) 확장, 술어 비교환).

### 측정 8 — #1031 경미 사항: `--limit` 미명시 (채택 여부와 무관)

[`20260812-970`](20260812-970-pr-base-rule-guard.md) §8-1 5-b 의 GraphQL 교차 확인 술어 `gh pr list --state all` 은 `--limit` 을 명시하지 않아 기본값 `30` 으로 동작한다.

```bash
gh pr list --state all --limit 2000 --json number --jq 'length'                       # 636
BOT='^chore/(r1-baseline-linux|baseline-remeasure)-[0-9]+$'
gh pr list --state all            --json headRefName \
  --jq "[.[] | select(.headRefName | test(\"$BOT\"))] | length"                       #  0
gh pr list --state all --limit 1000 --json headRefName \
  --jq "[.[] | select(.headRefName | test(\"$BOT\"))] | length"                       # 30
```

저장소 PR **636** 건 기준, 기본 limit 로는 봇 패턴이 **`0` 건** 잡혀 *"두 경로가 셀 단위로 일치"* 가 재현되지 않는다. `--limit 1000` 을 명시하면 **`30`** 으로 ADR 박제값과 일치한다. 본 PR 에서 정정한다.

> ⚠️ **#1031 본문은 이를 _"봇 패턴 22건만 잡혀"_ 로 적었는데 실측은 `0` 이다.** 재현 불가 술어를 다루는 이슈가 **재현 불가 수치를 인용**했다 — 본 ADR 이 다루는 클래스의 세 번째 자기 사례이며 (앞선 둘: #983 초판의 자기 위반 / #1006 본문의 라벨↔술어 불일치), *"발화 지점 없는 규범은 주의력에만 의존한다"* 의 증거를 하나 더 보탠다.

> **박제된 감시값과 실측의 대조 주체는 사람이다.** 대조 시점은 (i) 해당 ADR 의 재검토 트리거가 발동했을 때 (ii) 그 감시값을 인용·수정하는 PR 의 reviewer 단계 두 곳이며, 기계는 **관측값 출력까지만** 담당한다 (§결정 5-3·5-4).

> ⚠️ [`20260808-983`](20260808-983-measurement-recording-convention.md) §(ii)·(iv) 는 **발화 지점이 0 이며 주의력에만 의존한다.** PR #1061 은 그 상태에서 **4라운드 연속** 수치 오류를 냈고, 4건 모두 **손으로 센 계수**였다(기계 출력 계수 오류 `0/4`). 본 ADR 은 그 발화 지점을 만들 수 없다고 판정했을 뿐, **공백이 없다고 주장하지 않는다.** 이 문장이 지워지면 다음 관찰자는 *"검토했더니 문제 없었다"* 로 오독한다

### 6-1. 기각한 대안 — «현행값은 항상 `--population` 실행값» 재구조화

§결정 5·6 의 **정반대 극**이라 같은 결정 공간에 속한다. 발의는 PR [#1072](https://github.com/coseo12/astro-simulator/pull/1072) dev 가 남긴 판단 여지(_"[`20260814-982`](20260814-982-changelog-tilde-guard.md) 가 Amendment 를 계속 쌓느니 §재검토 조건 자체를 «현행값은 항상 실행값» 형태로 재구조화하는 안"_)이고, reviewer 가 _"#1064 와 같은 뿌리 — 별도 이슈 금지"_ 로 본 ADR 에 회부했다. 이 대안은 #1064 스코핑 질문 1(대조 대상 범위)의 **단일 대상 채택안**이자 질문 4(방향별 계급)의 부속 판정이며, §결정 6(_"대조 주체는 사람"_)이 그 반대극이다 — **양극이 모두 본 ADR 안에 있으므로 여기서 닫는다.**

**기각한다.** 근거 3항이며 1항은 논증, 2·3항은 실측이다.

1. **대조가 항등식이 되어 재검토 트리거 자체가 소멸한다.** [`20260814-982`](20260814-982-changelog-tilde-guard.md) 의 트리거 문언은 둘 다 **2항 관계**다 — §재검토 조건 1 _"`ignored: false` markdown 이 **5개를 넘으면**"_ / §후속 감시 _"계수가 **`45` 에서 이탈**할 때"_. 기준항을 *"실행값"* 으로 정의하면 기준항 ≡ 현재항이므로 **이탈은 항상 거짓**이다. 트리거를 없애는 것이 목적이라면 정직한 방법은 §재검토 조건 1 을 **폐기**한다고 적는 것이지, 정의를 항등식으로 바꿔 **트리거가 살아 있는 것처럼 보이게 두는 것**이 아니다

2. **«이탈» 기준을 다른 데 보존하는 두 경로는 각각 독립된 이유로 닫힌다.** 항등식은 기준항을 트리 어딘가에 남기면 피할 수 있고, 이 저장소에 **두 선례가 실재**하므로 가짜 후보가 아니다:
   - **(C1) baseline 파일** — `scripts/verify-fps-baseline.mjs:54` 가 `docs/benchmarks/fps-lowend-baseline.json` 을 기준으로 삼고 `bench-set-baseline.mjs` 가 갱신하는 패턴. 항등식은 피하지만 **박제값이 사라지지 않고 거처만 바뀐다** — §결정 5 의 (f-A) 기각 논거가 **그대로 재적용**된다(사본의 이동 ≠ 사본의 제거). 더 나쁜 점은 baseline JSON 이 *"왜 그 값인가"* 를 담지 못해 **값 ↔ precision 논거**라는 새 drift 쌍이 생긴다는 것이다
   - **(C2) diff 스코프 방향 판정** — 기준을 base ref 에서 **실행 시점에 계산**하므로 박제값이 완전히 사라진다 (`verify-md-tilde.mjs:655` 의 `--base <sha>` / `ci-diff-scope.mjs` 가 이미 쓰는 형태). 그러나 **§측정 6 이 이미 기각했다** — 250 커밋의 유일한 감소가 정당한 고아 정리였다(정밀도 `0/1`). 게다가 이 규약이 겨눈 **원 사건**([#907](https://github.com/coseo12/astro-simulator/issues/907) — 선언은 재포함인데 동작이 `ignored: true`)은 *"감소"* 가 아니라 **«증가가 일어나지 않음»** 이라 방향 판정으로는 **원리적으로 미검출**이다. 즉 (C2) 는 정밀도만 낮은 게 아니라 **재현율이 원 사건에 대해 `0`** 이다

3. **실측 반례 — 트리거의 산출물은 «숫자 갱신» 이 아니라 «precision 논거의 재검증» 이다.** 발의의 전제는 *"Amendment 가 쌓이는 것이 비용"* 인데, 쌓인 두 Amendment 가 실제로 무엇을 낳았는지 보면 전제가 깨진다:

   | 발동 | 계수 | Amendment 가 실제로 산출한 것 |
   | --- | --- | --- |
   | [#958](https://github.com/coseo12/astro-simulator/issues/958) | `5` → `45` | 편입 40 파일 **`~~` 0 hit** 재측정 + `docs/**` 의도분 48 발생과 **disjoint** 확인 |
   | [#1063](https://github.com/coseo12/astro-simulator/issues/1063) | `45` → `49` | 편입 4 파일 **`~~` 0 hit ∧ 단일 `~` 0 hit** + churn 실측(**1 파일 / 1 행**) |

   두 번 다 산출물은 **_"소유 모집단 안의 의도된 취소선 = 0"_ 이라는 결정 전체를 지탱하는 명제의 재검증**이었다. 대안 (C) 였다면 실행값이 조용히 `45` → `49` 가 되고 **그 재검증은 트리거되지 않는다.** 즉 (C) 가 없애는 것은 Amendment 라는 **형식**이 아니라 그 안에 든 **측정**이다. Amendment 축적은 비용이 아니라 **`20260814-982` §정밀도의 출처 가 아직 참임을 매번 확인한 기록**이다

> **판정 요지 한 줄** — «현행값 = 실행값» 은 *"박제값이 낡는다"* 는 증상을 없애지만, 그 박제값이 **낡을 때만 발동하는 재검증**을 함께 없앤다. §결정 5(f-B)가 이미 **사본 0** 을 달성하므로 증상은 해소돼 있고, (C) 는 그 위에 **트리거 소멸**만 얹는다.
