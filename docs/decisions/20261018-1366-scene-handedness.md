## 배경

장면은 오른손 황도 데이터 성분을 Babylon 왼손계 (`scene.useRightHandedSystem` 미사용) 에 그대로 넣었다. 그래서 화면이 황도면 기준 **거울상**이었다 — 데이터 축 → 시청자 (오른쪽 · 위 · 시청자 쪽) 행렬식 `−1` (architect 실측). 기본 카메라가 데이터 황도 **남쪽**에 있고 화면도 거울이라 두 번 뒤집혀, 2D 배치 (공전 반시계) 만 보면 드러나지 않았다. 드러나는 것은 깊이 쪽이다 — 궤도 경사 방향 · 달 황위 · 식 그림자 위치.

- 2026-10-18 00:00 UT 달 직하점 적위: 장면 `−19.01°` (실제 `−25.70°`)
- 2024-04-08 일식 그림자 축 지표 교점: 위치 모델 참 지점에서 `4,727 km` (남미 쪽)

## 결정

1. **장면 경계에서 z 하나를 뒤집는다** — 헬퍼 `packages/core/src/coords/scene-handedness.ts` 로 일원화한다.
   - 극벡터: `toScene` · `toSceneZ` (데이터 → 장면), `fromScene` · `fromSceneZ` (장면 → 데이터). `S_z` 는 자기 역원이지만 방향을 이름으로 남긴다.
   - 축벡터: `axialToScene(v) = (−x, −y, z)` (`det(S_z)·S_z`). 장면에서 극벡터와 다시 외적하는 혜성 궤도 법선 (먼지 휨 `ĥ × axis`) 이 이 경로다.
   - GLSL 사본 (`belt-particles.ts` 정점 셰이더) 은 `SCENE_Z_SIGN` 을 문자열로 주입받는다.
2. **순수 함수는 데이터 공간에 둔다** — `sampleOrbitPoints` · `cometOrbitNormal` · `lunarEclipseShadowUniforms` · `beltKeplerPositionF32` · `getPhysicalLocal`. 반전은 장면에 쓰는 지점에서만 한다.
   - 데이터 → 장면: 메시 위치 (`updateAt` · `setTier`) · 광원 · 궤도선 위치와 정점 · trail · 거리 자 · 소행성대 (CPU · GPU) · 달 `uSunDirection` 기준점 · 월식 uniform `a` · `axis` · 혜성 궤도 법선.
   - 장면 → 데이터: free-fly origin safety net · LOD 패스 카메라 위치 · web tier 판정 (`sim-canvas.tsx` `cameraFromSunMeters`). LOD 패스의 `screenCoverageRadius` 입력은 장면 공간이라 `toSceneZ` 를 쓴다.
   - 자동 정합 (변경 0): 메시 위치에서 파생되는 값 — `uSunDirection` (달 외) · 구름 · 혜성 머리 · 코로나 · 라벨 · 피킹 · 사건 시점 (`viewDirection`).
3. **지구 방향 식 · 마스크 규약은 바꾸지 않는다** — 지구 회전은 장면 공간에서 정의되고 반전은 위치에만 들어간다. 장면에서 지구 local `+Y` 는 장면 `(0, sin ε, −cos ε)` = 데이터 `(0, sin ε, cos ε)` (실제 천구 북극) 이다 (ADR 756 §A13.3 갱신).
4. 신규 가드 · 하네스는 만들지 않는다 (사용자 결정). 헬퍼 단위 테스트 1개와 기존 테스트 기대값 갱신 (7 파일 18건 — PR 본문 근거 표) 만 둔다.

- 교점 측정 방법: 장면 메시 방향 (지구 → 달 · 지구 → 태양) 에 물리 거리를 곱해 그림자 축을 만들고, 지구 구 (`6,371 km`) 와의 교점을 지구 메시 world 행렬로 local 에 되돌려 위경도를 읽는다 (마스크 규약 `lon = atan2(z, x)`). 「모델 참」 은 같은 위치 모델의 교점을 황도 → 적도 → ERA 로 바꾼 지리 좌표다. 같은 ERA · ε 를 쓰므로 남는 차는 #1362 식 잔차 수준이다.
- NASA 최대식 지점까지의 차 (`1,237 km`) 는 #1354 위치 모델 한계다 (ADR 1360 §1-D) — 렌더로 줄지 않는다.
- 고리 · 다른 천체 자전축: 메시와 장면 회전은 그대로이지만 극 방위를 모델링하지 않아 (world X 축 주위 obliquity 근사) 장면 극이 가리키는 실제 방향이 바뀐다. 장면 극 (프로젝트 `computeRotationState` · `computeSpinQuaternion`) ↔ IAU WGCCRE J2000 극 선 각도: 토성 `54.5° → 5.0°` · 해왕성 `22.7° → 50.8°` · 천왕성 `19.8° → 12.2°` · 목성 `1.4° → 5.2°` (PR #1368 리뷰 실측을 같은 함수로 재현). 극 방위 모델링 (IAU 극) 은 범위 밖이다.

### 재검토 조건

1. `scene.useRightHandedSystem` 을 켜거나 마스크 경도 규약을 바꾸면 본 결정과 ADR 756 §A13.5 재검토 1 을 함께 다시 유도한다.
2. 장면에 데이터 위치 · 방향을 쓰는 새 경로가 생기면 이 헬퍼를 거쳐야 한다 — 빠지면 그 요소만 거울에 남는다 (예: 궤도선만 반대로 기움 · LOD 오판). 실회귀가 관측되면 그때 가드를 검토한다.
3. 장면에서 다시 외적하는 축벡터 (각운동량 · 자전축을 데이터에서 가져오는 경로) 가 생기면 `axialToScene` 을 쓴다.
4. 극 방위 (IAU 극) 를 모델링하면 그 극은 데이터 공간 축벡터로 넣고 `axialToScene` 으로 장면에 옮긴다 — 위 고리 각도 차 (해왕성 `50.8°` 등) 는 그때 함께 닫힌다.

## 교차검증 반영 사항

**claude-only analysis completed — 단일 모델 편향 노출 미확보.** cross-validate (agy) 는 #1363 (외부 모델 단계 무응답 3회 연속) 으로 실행하지 않았다. 경량 모델 폴백은 하지 않았다. 아래는 developer 단독 재검토다.

1. **대수 정합** — `(S_z a) × (S_z b) = −S_z (a × b)` 를 헬퍼 단위 테스트가 직접 단언한다. 혜성 먼지 휨은 런타임에서 3 혜성 전부 운동 반대쪽 (`lag · v < 0`, 역행 핼리 포함) 이다.
2. **누락 지점 위험** — 반전 누락은 그 요소만 거울에 남기는 형태로 나타난다. 런타임에서 궤도선 ↔ 메시 (위성 · 왜소행성 · 혜성), trail 머리 ↔ 메시, 거리 자 ↔ 메시, LOD ↔ 투영, 월식 uniform ↔ 메시 기하가 모두 정합했다 (§결과).
3. **지구 식 불변** — 직하점 (2024-04-08 태양 `7.449°N 93.951°W`) 이 #1362 단위 테스트 값과 같다. 회전 quaternion 은 장면 공간 값이고 본 변경은 위치에만 들어간다.
