# ADR 20260817-1103 — 머지 충돌 마커 전수 가드

- **상태**: **Accepted** (cross-validate agy 2026-08-17 — §교차검증 반영 사항 4축 통합 완료). 원 박제: `Provisional`
- **날짜**: 2026-08-17
- **이슈**: [#1103](https://github.com/coseo12/astro-simulator/issues/1103)
- **관련**: ADR [`20260814-982`](20260814-982-changelog-tilde-guard.md) (같은 뿌리, 다른 모집단) / [#1040](https://github.com/coseo12/astro-simulator/issues/1040) (확정 구간 소급 편집 예외)

> 표기 규약 — 본 문서는 충돌 마커를 **리터럴로 적지 않는다.** `open` / `base` / `sep` / `close`
> 대역 이름만 쓴다 (각각 부등호·파이프·등호·부등호 7연속). 가드가 자기 근거 문서를 유일한
> hit 으로 잡는 사고의 전례가 있다 ([#995](https://github.com/coseo12/astro-simulator/issues/995) —
> 그 가드는 12.57배 거짓 근거 주석을 놓친 채 자기 자신만 찾고 있었다).

## 배경

`origin/develop` 에 머지 충돌 마커가 **실제로 커밋됐다** — `fa497b6` (PR [#1095](https://github.com/coseo12/astro-simulator/pull/1095) 머지분) 의 `CHANGELOG.md` `[Unreleased]` 구간. 메인 오케스트레이터와 dev(#1079) 가 **서로 모르는 상태에서 독립적으로** 같은 결함에 도달했다.

머지 해소 때마다 행 선두 앵커로 마커 `0` 을 확인해 왔는데도 통과한 이유는, **커밋 직전에 `lint-staged` 의 `prettier --write` 가 마커를 마크다운 문법으로 정규화**하기 때문이다. 검사 시점의 형태와 커밋물의 형태가 다르다.

ADR `20260814-982` 와 **뿌리가 같다** — *"손상은 작성자가 타이핑하지 않는다. 포맷터가 쓴다."* 그리고 `prettier --check` 로도 탐지되지 않는다: `--write` 가 만든 형태는 prettier 기준으로 **정답**이라 이후 `--check` 도 초록이다.

### 실측 매트릭스 — **3축**

rev `b64c66c` / prettier `3.9.6` / 격리 픽스처.

> ⚠️ **초판은 이것을 「2축」이라 단정했고 그것이 거짓이었다.** 축 3 을 모른 채 술어를 짰기 때문에 가드에 **관통 경로가 남아 있었다** — PR [#1123](https://github.com/coseo12/astro-simulator/pull/1123) reviewer 가 실제 prettier 산출물로 반증했다 (B1). 아래 축 3 은 그 반증을 반영한 것이다.

**축 2 — 앞줄 상태** (마커가 리스트 항목 바로 밑에 오면 lazy continuation 이 붙는다)

| 마커 | 앞줄이 **빈 줄** | 앞줄에 **텍스트 인접** |
| --- | --- | --- |
| `open` | 그대로 | 그대로 |
| `base` (diff3) | 그대로 | **선행 2칸 들여쓰기** |
| `sep` | 그대로 | **선행 2칸 + 백슬래시 escape** |
| `close` | **blockquote 정규화** | **blockquote 정규화** |

1. **선행 공백은 `sep` 만의 문제가 아니다.** `base` 에도 들여쓰기가 붙는다. 이슈 본문이 제안한 술어는 행 선두 앵커라 **리스트 안에서 난 충돌을 통째로 놓친다**.
2. **`sep` 의 escape 는 조건부다.** 이슈 본문 표는 무조건으로 적었으나, 실사고 형태(빈 줄 분리)에서는 `sep` 이 원형 그대로 남아 있었다. 반대로 `close` 는 앞줄과 **무관하게 항상** 변형된다.

**축 3 — 컨테이너 컨텍스트** (마커가 blockquote 나 표 **안**에 놓인다)

| 원본 문맥 | prettier 통과 후 |
| --- | --- |
| 앞 줄이 blockquote | `"> "` + 마커 — 인용 안으로 **흡수** |
| 표 행 안 | `"| "` + 마커 + `" |"` |

3. **이 축은 `^\s*` 로 덮이지 않는다.** `>` 와 `|` 는 공백이 아니라서 원형 4술어가 통째로 관통된다.
4. **인위적 주입이 아니다.** git 은 마커를 항상 컬럼 `0` 에 쓰지만, `CHANGELOG.md` 처럼 blockquote·표를 상시 쓰는 파일에서는 `prettier --write` **1회**로 도달한다 — 실사고 `fa497b6` 과 **같은 파일 클래스**다.
5. **그 상태의 가드는 「초록인 채 마커를 통과」시킨다.** fail-fast 가드의 정상 사용법이 *"보고된 `file:line` 을 지운다"* 이므로, 3건 중 2건만 보고하면 사용자는 나머지 1건을 남긴 채 exit `0` 을 받는다. 예외 시나리오가 아니라 **주 경로**다.

> ⚠️ 이 매트릭스는 **기계로 재유도했다.** 손으로 적은 변형형을 술어에 넣고 그 술어로 같은 문자열을 검사하면 자기 충족이다. 실제 `prettier --write` 산출물을 가드에 통과시키는 e2e 로 확인한다.
>
> ⚠️ **그럼에도 초판의 e2e 는 축 3 을 못 잡았다** — 4조건(merge/diff3 × 빈줄/인접)만 돌렸고 그 조건 집합 안에서는 *"주입 수 = 검출 수"* 가 참이었기 때문이다. **테스트한 조건에서만 참인 명제를 전칭으로 적으면 그 자체가 오박제다.** reviewer 의 26조건 sweep 에서 8조건이 `주입 > 검출` 이었다.
>
> ⚠️ **2판도 같은 함정을 반복했다** — 축 3 을 self-test 에 넣었지만 그 픽스처가 **내가 손으로 적은 변형형**이었다. 술어가 그 문자열을 잡는다는 것만 보이고 prettier 가 **실제로 무엇을 만드는지**는 보이지 않았다. 3판은 컬럼 `0` 마커만 주입하고 변형을 전적으로 prettier 에 맡긴다.
>
> ⚠️ **그러나 「e2e 가 없어서 B2 가 통과했다」 는 서술은 틀렸다** (reviewer 라운드 3 U1 이 변이 테스트로 반증). 3판 e2e 를 **B2 결함 보유판에 그대로 돌리면 14/14 통과**한다 — 표 컨텍스트의 충돌 «내용» 을 리스트 항목으로 썼기 때문에 GFM 표가 `sep` 전에 끝나 마커가 표 밖으로 나왔다. **표 케이스를 돌리는 시늉만 하고 실제로는 평문을 재고 있었다.** 실제 B2 보호는 같은 커밋의 **손으로 쓴 분류기 픽스처**였다.
> 4판에서 컨텍스트별 «내용» 을 정합시켜 판별력을 만들었고(결함판에서 `sep` 소실 → 검출), **두 층을 모두 유지**한다 — 분류기 픽스처를 「e2e 와 중복」이라며 지우면 B1·B2 보호가 조용히 사라진다.
>
> ⚠️ 판정식도 바꿨다. **「주입 줄 수 = 검출 줄 수」는 틀린 기준**이다 — prettier 가 마커 뒤 내용까지 같은 blockquote 로 흡수하면 마커 하나가 여러 줄로 번지고, 가드는 그 줄들을 전부 보고한다(과보고 = fail-loud). 물어야 할 것은 **「주입한 마커 종류가 하나라도 사라졌는가」** 다. 이 정정 자체를 e2e 가 실행 중에 드러냈다.

### (a) 를 기각한 근거 — 모집단이 다르다

`verify-md-tilde.mjs` 의 모집단은 `prettier --file-info` 가 `ignored: false` 로 판정하는 md 다. 충돌 마커는 **prettier 가 손대지 않는 파일에도 (원형 그대로) 남을 수 있어** 소유 여부가 경계가 되지 못한다. 실측 (rev `b64c66c`): tracked md `245` 중 **소유 `50` / 미소유 `195`**. ⚠️ `docs/**` 를 통째로 «미소유» 라고 적으면 부정확하다 — `.prettierignore` 가 `docs/**` 를 제외한 뒤 `docs/benchmarks/` · `docs/phases/` · `docs/reports/` · `docs/retrospectives/` **4 서브트리를 재포함**한다 (ADR [`20260814-958`](20260814-958-prettier-live-docs-scope.md)). 미소유 쪽에서 난 충돌은 정규화를 겪지 않을 뿐 결함인 것은 같고, **재포함된 4 서브트리는 축 3 의 모집단**이다.

한 스크립트에 모집단이 다른 두 계약을 넣으면 §주석 계약 ↔ 구현 drift 의 생성원이 된다.

### (c) 를 기각한 근거 — "고칠 수 없는 존량" 범주가 없다

`verify-md-tilde.mjs` 가 diff 로 좁힌 이유는 확정 릴리스 구간의 존량 21줄을 #1040 판정 전까지 손댈 수 없어, 전수가 *"고칠 수 없는 것을 매번 보고하는 가드"* 가 되기 때문이다 ([#766](https://github.com/coseo12/astro-simulator/issues/766) alert fatigue 계보).

**충돌 마커에는 그 범주가 없다.** 마커는 확정 구간에 있든 어디에 있든 결함이고, 발견 즉시 제거가 정답이다. 유예해야 할 «의도된 마커» 라는 것이 존재하지 않는다. 그래서 diff 로 좁히면 얻는 것 없이 **이력 커밋에서 재유입되는 경로만 열어둔다**.

## 결정

1. **`scripts/verify-md-conflict-marker.mjs` 를 신설한다** (후보 b). `verify-md-tilde.mjs` 는 손대지 않는다.
2. **술어 6형태.** 원형 4형태(`open`/`base`/`sep`/`close`)는 **전 파일**, prettier 변형 2형태(`sep` escape / `close` blockquote)는 **`.md` 한정**. 변형은 markdown 파서를 거칠 때만 생기므로 다른 확장자에서 찾는 것은 순수 오탐 표면이다.
3. **원형 술어 전체에 선행 공백을 허용한다.** `sep` 만이 아니라 `base` 에도 들여쓰기가 붙기 때문이다 (§축 2-1).
4. **컨테이너 접두는 술어가 아니라 전처리로 덮는다** (§축 3). `containerVariants()` 가 blockquote `>` / 표 셀 `|` 를 **한 겹씩** 벗기며 매 단계를 검사한다. 통째로 잘라 셀 배열을 만들지 **않는** 이유는 그러면 `base` 마커(파이프 `RUN` 개) 자체가 쪼개져 사라지기 때문이다. 벗기기는 **markdown 한정**이다 — 다른 확장자에서 `>`/`|` 는 셸 리다이렉트·파이프라 순수 오탐 표면이 된다.
5. **전수 스코프.** diff 로 좁히지 않는다 (§후보 비교 (c)).
6. **fail-fast.** `|| true` · soft-exit · allowlist · 예외 경로를 두지 않는다 (CLAUDE.md §가드 설계 원칙).
7. **자기 참조 회피.** 스크립트·본 ADR·CHANGELOG 는 마커를 리터럴로 적지 않는다. 술어는 문자 반복으로 조립하고, 설명은 대역 이름을 쓴다. 기계 검사로 강제한다 (§DoD 5).
8. **배선 2곳.** `.husky/pre-commit` (lint-staged **다음 줄** — 손상 주체가 그 줄이므로 가장 이른 검출 지점) + `ci.yml` (self-test 상시 + 본검사 상시).

### 인터페이스 (종료 코드 · 벗기기 사양)

> ⚠️ 이 절은 cross-validate 가 **없어서 오해한** 두 지점을 ADR 안으로 끌어온 것이다. 구현에는 처음부터 있었으나 **ADR 만 읽는 독자에게는 보이지 않아** 독립 검토자가 「단일 겹만 벗기는가」·「리포팅 포맷이 있는가」를 결함 후보로 올렸다. ADR 은 구현과 별개로 읽히는 문서다.

| 종료 코드 | 의미 |
| :---: | --- |
| `0` | 위반 `0` (또는 `--self-test` 성공) |
| `1` | 위반 발견 — `file:line [형태] "원문"` 을 stderr 에 열거 |
| `2` | 실행 에러 (잉여/누락 인자 · git 실행 실패 · prettier 부재 등 환경·상태 오류) |

**벗기기 사양은 두 컨테이너가 다르다:**

- **blockquote (`>`)** — 마커가 드러날 때까지 **반복** 벗긴다 (`MAX_CONTAINER_DEPTH` 상한). 중첩 인용은 깊이가 임의라 한 겹으로는 부족하다.
- **표 셀 (`|`)** — 여는 쪽은 같은 루프가 처리하고, **닫는 쪽은 한 겹만** 뗀다 (§의도적 비-범위 U4 근거).

### 의도적 비-범위

- **코드 펜스 안도 검사한다.** 마커를 예시로 보여주려는 문서가 걸릴 수 있으나 방향이 **과보고**(fail-loud)라 그대로 둔다. 예시가 필요하면 결정 7 의 대역 표기를 쓴다 — 존재 불가 형태로 적으면 구조적으로 무해하다 ([#999](https://github.com/coseo12/astro-simulator/issues/999) 전례).
- **`.md` 외 파일의 prettier 변형형은 보지 않는다** (결정 2).
- **`conflictStyle` 은 `merge`/`diff3`/`zdiff3` 를 구분하지 않는다.** 마커 **문자**가 4종으로 같기 때문이며, `zdiff3` 형태(공통 조상 구간 표기가 다른 변형)를 실제 prettier 에 통과시켜 **4형태 전건 검출**을 확인했다 (cross-validate 가 지적한 미검증 축).
- **살아있는 표 안의 diff3 `base` 는 「미검출」이 아니라 「부재」다** (U6). prettier 가 파이프 `RUN` 연속을 **빈 셀들로 분해**해 문자열 자체가 소멸하므로 잡을 대상이 남지 않는다. 나머지 3종이 발화해 exit `1` 은 유지되므로 실피해가 없다 — self-test e2e 도 표 컨텍스트에서만 `base` 기대를 면제한다.
- **`CONTAINER_SUFFIX` 는 닫는 구분자를 한 겹만 뗀다** (U4). 셀이 여럿인 행(`"| a | (sep) | b |"`)은 못 잡지만 **git 은 마커를 컬럼 `0` 에 단독으로 쓰므로** prettier 를 거치면 항상 단일 셀 행이 된다 (30조건 sweep + multipass fixpoint 로 도달 불가 확인). 여러 겹을 떼면 정상 표 행이 오탐 표면으로 들어온다.
- **바이너리는 제외한다** — NUL 바이트 포함 파일 (`git grep -I` 와 같은 기준). 검산: tracked `746` − 검사 `658` = `88` = tracked PNG 전량 `88` (rev `b64c66c`).
