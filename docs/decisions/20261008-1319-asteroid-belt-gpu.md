## 배경

현행 소행성대(`packages/core/src/scene/asteroid-belt.ts`, #99)는 `?belt=N` 옵트인만 있고 기본 화면에 없다. 사용자는 띠를 **기본 켜짐**으로 원하되, **성능이 확보될 때만**으로 조건을 걸었다. 이슈 본문은 비용 원인을 「매 시간 위상마다 CPU Kepler × N + 행렬 버퍼 재업로드」로, 입자 크기를 「≈ 0.2px (추정)」으로, Floating Origin 우회를 「잠재 결함 (미실측)」으로 적었다. 설계 전에 셋을 실측했다.

### 실측 (2026-10-08, architect)

측정 환경: 로컬 macOS · `next start` prod 빌드 (빌드 시점 이후 `asteroid-belt.ts` 변경 0 — `git log` 확인) · Playwright headless · viewport 1280×800 DPR 1. 렌더러 축 2개 — `--use-angle=swiftshader` (WebGL2, `__isSoftwareRenderer=true` — CI 와 같은 소프트웨어 래스터) / `--use-angle=metal` (WebGPU, 하드웨어). 측정 스크립트는 일회성 (커밋 안 함, volt #67 패턴).

**1-A. 비용 귀속 — 원인은 CPU Kepler 가 아니라 소프트웨어 래스터의 정점 수다.** 재생(`?belt=N`) 과 일시정지(`?belt=N&speed=0` — 행렬 버퍼가 갱신되지 않음을 같은 세션에서 확인: 0.8 s 간격 `m[12]` 불변) 를 비교했다. 일시정지에서는 CPU Kepler 가 돌지 않는다.

| 렌더러 | N | 재생 fps | 일시정지 fps |
| --- | ---: | ---: | ---: |
| swiftshader | 0 | 46.9 | 46.2 |
| swiftshader | 200 | 27.1 | 27.3 |
| swiftshader | 1000 | 10.7 | 9.3 |
| swiftshader | 2000 | 6.0 | — |
| metal (WebGPU) | 0 / 200 / 1000 / 5000 | 119.9 / 120.2 / 120.2 / 120.0 | 120.0 / 120.2 / 120.2 / 122.7 |

재생 ≈ 일시정지 → 하락분은 **렌더 쪽**이다. 템플릿 구는 정점 `153` · 인덱스 `768` (실측) 이고 소프트웨어 래스터에서 입자당 ≈ 70~80 µs 다 (N=200 `+15.6` ms · N=1000 `+71.8` ms/프레임). 하드웨어 GPU 는 N=5000 에서도 vsync 상한(120)에서 차이가 없다. CPU Kepler 단독 비용은 Node 마이크로벤치로 N=200 `0.057` ms · 1000 `0.282` · 5000 `1.473` · 10000 `2.969` ms/프레임 (`positionAt` + 버퍼 쓰기, 데스크톱 1코어) — 하락 원인이 될 크기가 아니다.

**1-B. 입자 크기.** 기본 진입 화면(solar tier, 카메라 radius `35` scene unit, fov `0.8`)에서 N=1000 입자의 투영 지름 중앙값 **`0.156` px** (최소 `0.111` / 최대 `0.248`). 사실상 보이지 않는다. (측정식은 thin instance 위치 · 카메라 거리 · 구 지름 `0.008` 에서 계산)

**1-C. Floating Origin 결함 — 재현됨, 그리고 결함이 둘이다.**

- **(가) origin 미차감**: 재생 중 달 focus (body tier, origin = 달 world) 에서 띠 무게중심이 태양 mesh 에서 `2.95e6` scene unit (≈ 0.79 AU) 떨어져 **장면 원점(=달) 주위**에 그려졌다. 화성 focus (inner tier, origin `[0,0,0]`) 에서는 정상.
- **(나) 일시정지 중 tier 전환 시 스케일 고착**: `?speed=0` 에서 달 focus 로 body tier 에 들어가도 띠 최대 반경이 `46.93` scene unit — **solar tier 스케일 그대로** — 였다. 띠 갱신이 `updateAt`(시간 위상) 에만 묶여 있어서 tier·origin 이 바뀌어도 다시 쓰이지 않는다 (ADR 1205 가 LOD 에서 닫은 축과 같은 축). 그 결과 띠가 반경 ≈ 47 unit 고리로 달(body tier 반경 ≈ 43.6 unit) 주위를 감싼다.

두 결함 모두 현재는 입자가 0.03 px 이하라 화면에 안 보인다 — **입자를 보이게 만드는 순간 둘 다 화면에 나온다.** ADR 422 `:65` 의 「매 프레임 덮어쓰므로 shift 영향 없음」 은 덮어쓰기만 보고 **무엇으로** 덮어쓰는지(origin 미차감)는 보지 않은 판단이다.

**1-D. GPU 셰이더 경로 가용성 — 양 백엔드 실동작.** GLSL `ShaderMaterial` (`vertexSource`/`fragmentSource`) + 사용자 정의 정점 속성 2개(`orbitA`·`orbitB`, vec4) + 정점 셰이더 Newton 4회 Kepler 풀이 + 화면 고정 px 쿼드 + 로그 depth 기록 POC 를 실제 장면에 주입했다. WebGL2(swiftshader) · WebGPU(metal) 모두 `isReady=true` · 컴파일 오류 0 · 콘솔 오류 0, 스크린샷에서 띠 입자 확인. 비용:

| 렌더러 | 기존 구 (N) | GPU 쿼드 (N) |
| --- | --- | --- |
| swiftshader (기준 N=0 `46.8`) | 1000 → `10.7` · 2000 → `6.0` | 1000 → `44.4` · 2000 → `43.5` · 5000 → `39.3` · 10000 → `33.5` |
| metal WebGPU | 5000 → `120` | 1000 / 5000 → `120.2` / `120.2` |

**1-E. 커크우드 간극은 위치 스냅샷에서 보이지 않는다.** 간극은 장반경 `a` 의 결손이다. 합성 표본 200,000 개로 간극 중심 ±0.01 AU 의 밀도를 이웃 대비 비율로 쟀다 (`1.0` = 간극 안 보임):

| 이심률 분포 | 3:1 (2.50) a / r | 5:2 (2.82) a / r | 7:3 (2.95) a / r |
| --- | --- | --- | --- |
| 실제 근사 (Rayleigh σ 0.09, 평균 ≈ 0.11) | 0.22 / **1.02** | 0.33 / **0.98** | 0.39 / **0.99** |
| e 축소 (σ 0.02) | 0.22 / 0.89 | 0.32 / 0.94 | 0.40 / 0.95 |
| e 극소 (σ 0.005) | 0.23 / 0.37 | 0.33 / 0.52 | 0.39 / 0.57 |

`r`(태양 거리) 에서는 이심률이 `a(1±e)` 로 번져 실제 근사 분포에서 간극이 완전히 사라진다. 반면 **힐다(삼각형)·트로이(L4/L5 구름)** 는 위치 공간의 구조라 보인다.

**1-F. 카이퍼 프레이밍.** 부팅 카메라 기울기(beta `1.257`)에서 황도면 원이 화면 안에 드는 비율:

| 카메라 radius (unit) | 카메라 거리 | 30.1 AU | 39.4 AU | 45 AU | 48 AU |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1000 (현 `SOLAR_ZOOMOUT_LIMIT`) | 79.6 AU | 100% | 79% | 61% | 56% |
| 1300 | 103.5 AU | 100% | 100% | 85% | 82% |
| 1600 | 127.3 AU | 100% | 100% | 100% | 100% |

이슈의 「줌아웃 상한 ≈ 80 AU」 는 **카메라 거리**이고, 그 거리에서 보이는 반경은 세로 ≈ 33.6 AU 다 — 카이퍼 고전대는 현 상한에서 화면에 다 들어오지 않는다.

## 결정

**결정 1 — 렌더 경로 (C).** 띠 입자는 「N 개 쿼드 = 4N 정점」 단일 메시 + GLSL `ShaderMaterial` 1개로 그린다 (그룹당 메시 1 · draw call 1). 정점 속성 `position`(쿼드 모서리 xy) · `orbitA = (a[AU], e, i, M0)` · `orbitB = (Ω, ω, n[rad/day], 밝기)`. uniform `uDays` · `uScale` · `uOrigin` · `uPxToClip` · `logDepthConstant` 만 매 bind 갱신 — **프레임당 CPU 작업 O(1)**. 불투명 큐 · depth write on · `discard` 원형 · 로그 depth 문장은 `LOG_DEPTH_FRAGMENT_WRITE_GLSL` SSoT 재사용 · `alwaysSelectAsActiveMesh = true` (정점 셰이더가 위치를 정하므로 bounding 무의미) · `isPickable = false`. 인스턴싱(thin instance + 인스턴스 속성) 변형은 미실측이라 채택하지 않는다 (재검토 조건 5).

- **시간 정밀도** — `uDays = jd − epochBase` (float32). `|uDays| > BELT_EPOCH_REBASE_DAYS` 이면 CPU(double)에서 `M0` 를 새 epoch 로 다시 써 속성 버퍼를 1회 재업로드한다. 1900~2100 슬라이더 범위의 float32 오차는 [추정] 무시 가능하나 `?t=` 극단 JD 를 막는 것이 목적.
- **`?beltNbody=1` 은 현행 CPU 구 경로를 유지**한다 (N-body 적분 위치는 Kepler 셰이더로 표현 불가). 이 경로도 결정 2 의 기준계 스냅샷으로 origin 을 차감한다.

**결정 2 — 기준계 계약: 띠는 body mesh 와 「같은 프레임 기준계」를 쓴다.** `solar-system-scene.ts` 가 body `mesh.position` 을 쓰는 두 지점 — `updateAt` 루프(`:1645-1659`, 진입 시 스냅샷한 `ox/oy/oz`) 와 `setTier` 즉시 재계산(`:1368-1378`) — 에서 사용한 `(origin, scale)` 을 한 헬퍼로 기록하고, 띠 셰이더는 bind 시 **그 기록값**을 읽는다. `floatingOrigin.originOffset` 을 bind 시점에 다시 읽지 않는다 — 가드 C(#380) 순서상 그 값은 이미 다음 프레임 origin 이라 body 와 한 프레임 어긋난다 (`:1160-1167` 주석과 같은 함정). 1-C 의 두 결함이 이 계약 하나로 닫힌다: (가) origin 차감, (나) tier·origin 이 바뀌면 다음 draw 에 반영 (시간 위상 비의존).

**결정 3 — 소프트웨어 렌더 게이트 (ii).** `detectSoftwareRenderer` 가 참이면 띠·카이퍼 메시를 만들지 않는다. 숫자 `?belt=N` 은 **강제 생성**이다 (bench 스윕 · `verify:belt-nbody` · `verify:webgpu` 호환). 표시 패널의 두 토글은 소프트웨어 렌더에서 `aria-disabled` + 사유 (ADR 1265 결정 5 의 별 배경과 같은 표현).

**결정 4 — 분포 (b).** 순수 함수 `generateBeltPopulation(seed, counts, planets)` (core, Babylon 비의존 — 단위 테스트 대상) 가 그룹별 궤도 요소를 만든다. 목성·해왕성의 `a`·`λ(epoch)`·`n` 은 `solar-system.json` → 로더 → `orbitMu` 경로에서 읽는다 (숨은 상수 금지 — volt #69).

| 그룹 | a | 공명·위상 | e · i |
| --- | --- | --- | --- |
| 주 띠 | 2.1~3.3 AU, 간극 노치 3:1 `2.502` · 5:2 `2.825` · 7:3 `2.958` · 2:1 `3.279` (기각 표본추출) | `n = √(μ/a³)` | e Rayleigh σ 0.09 (상한 0.3) · i Rayleigh σ 8° |
| 힐다 | 3.97 ± 0.05 | `n = 1.5 n_J` · φ = 3λ_J − 2λ − ϖ = 0 ± 30° | e σ 0.15 · i σ 8° |
| 트로이 L4 / L5 | `a_J` | `n = n_J` · λ = λ_J ± 60° + N(0, 12°) · L4:L5 = 1.6:1 | e σ 0.06 · i σ 10° |
| 카이퍼 고전대 | 42~48 AU | `n = √(μ/a³)` | e σ 0.05 (상한 0.15) · i 냉 60% σ 2° / 온 40% σ 12° |
| 플루티노 | 39.4 ± 0.2 | `n = (2/3) n_N` · φ = 3λ − 2λ_N − ϖ = 180° ± 40° | e σ 0.15 · i σ 10° |

정확도 수준은 **「통계적 형태 + 공명 위상 고정, 2체 Kepler (섭동·칭동 없음)」** 이다. 커크우드 간극은 `a` 분포에 넣되 화면에서 보인다고 약속하지 않는다 (1-E). 기본 입자 수: 주 띠 3000 · 힐다 300 · 트로이 600 · 카이퍼 고전대 1200 · 플루티노 300 = **5400** (사용자 결정 대상).

**결정 5 — 입자 크기: 화면 고정 물리 px, tier 무관.** 지름 `BELT_PARTICLE_PX = 3` (물리 px, #623 기준) · 밝기는 입자별 0.6~1.0 · 색은 주 띠 웜 그레이 / 카이퍼 쿨 그레이. 근거 — POC 에서 지름 2 px 는 별과 구분이 안 됐고 3 px 는 색으로 구분됐다 (좌하단 340×280 영역 웜 픽셀 수: 지름 1.5 → `106` / 2 → `223` / 3 → `539` / 4 → `952`). 대표 천체(#1318 — body, glow marker 4.5 px · 고휘도)보다 작고 어둡게 둬 계층을 지킨다. 최종 값은 실 Chrome 육안 승인(D-T2)으로 확정한다.

**결정 6 — 토글 · URL.** 토글 표(`display-toggles.ts`)에 2행 — `belt` (소행성대 = 주 띠 + 힐다 + 트로이) · `kuiper` (카이퍼 벨트 = 고전대 + 플루티노). URL 은 ADR 1265 결정 5 규약 그대로: `?belt=off` · `?kuiper=off` (ON = 키 삭제). 숫자 `?belt=N`: `N ≥ 1` → 소행성대 그룹 총수를 N 으로 (그룹 비율 유지) + 강제 생성 / `?belt=0` → 꺼짐 (현행 의미 보존). 파서는 순수 함수 `parseBeltParam` 하나 (#850 계약 — `apps/web/src/core/parse-*.ts`). core 는 렌더러를 모른다 — 게이트는 web 이 한다 (ADR 1265 결정 1 과 같은 레이어 분리). 꺼진 상태에서 처음 켤 때 지연 생성, 이후 `setEnabled` 토글.

**결정 7 — 카이퍼 프레이밍.** `SOLAR_ZOOMOUT_LIMIT` 를 `1000` → `1600` 으로 올린다 (1-F — 45·48 AU 원 100% 프레임 안). 기본 진입 화면(radius 35)은 바꾸지 않는다 — 카이퍼는 줌아웃했을 때 보인다.

**결정 8 — 기본 켜짐 전환은 성능 판정 후 별도 PR 에서.** 판정 기준은 이슈 설계안 §DoD 의 성능 항목 (하드웨어 A/B · CI 스윕). 미달이면 기본 꺼짐으로 두고 사용자에게 재결정을 요청한다.

## 결과·재검토 조건

- **기대 효과** — 소프트웨어 래스터에서 N=1000 띠 비용 `46.9 → 10.7` fps 에서 `46.8 → 44.4` fps 로 (1-A/1-D). 하드웨어에서 프레임당 CPU 띠 비용 O(N) → O(1). Floating Origin 결함 (가)(나) 구조적 해소. 힐다·트로이·카이퍼가 처음으로 화면에 나온다.
- **받아들인 비용** — GLSL 셰이더 1종 유지 (WebGPU 는 Babylon 의 GLSL→WGSL 변환 의존). `?beltNbody=1` 은 구 경로라 두 경로가 공존한다. CI 기본 경로는 띠를 그리지 않으므로 「기본 켜짐」 성능은 하드웨어 측정으로만 판정된다 (결정 3 의 대가).
- **재검토 트리거**
  1. CI `bench:scene:sweep` 에서 `?belt=1000` 셀이 `play-1y` baseline × 0.7 (= `64.3` fps) 미만 → 결정 1 재검토 (인스턴싱 · N 축소).
  2. 하드웨어 A/B (기본 vs `?belt=off`) 에서 어느 셀이든 −10% 초과 하락 → 결정 8 에 따라 기본 꺼짐 + 사용자 재결정.
  3. 모바일 실기기에서 띠 켠 상태 fps 가 끈 상태 대비 −10% 초과 → tier-c 에서 N 축소 도입 (현재 미도입 — 실측 전 임계 발명 금지).
  4. 소프트웨어 렌더가 CI 외 사용자 환경에서 유의미하게 관측되면 (예: 사용자 보고) → 결정 3 (ii) → (iii) 재검토.
  5. 셰이더 준비 시간이 부팅 단계 마크(`scene:asteroid-belt`)에서 체감 지연으로 측정되면 → 인스턴싱 또는 지연 생성 재검토. (POC 의 `isReady` 대기 ≈ 4 s 는 100 ms 폴링 루프 측정이라 [추정 — 계측 artefact 가능, 미분리])
  6. 사용자가 커크우드 간극의 「화면 가시성」을 요구 → 1-E 대안 (e 축소 = 데이터 왜곡 / `a`-공간 시각화 별도 모드) 을 별도 ADR 로.

## 교차검증 반영 사항

agy (architecture 모드, 2026-10-08, 로그 `.claude/logs/cross-validate-architecture-20261008-233901.log`). 메인이 재분석해 4축으로 분류했다.

### 합의

- 결정 1 (GPU Kepler 쿼드) · 결정 2 (body mesh 와 같은 `(origin, scale)` 스냅샷) 를 둘 다 타당하다고 판정. Newton 4회 고정 반복은 e < 0.3 대역에서 무한 루프 위험 없음.

### 이견 수용 (구현 계약에 추가)

1. **수명주기** — 띠·카이퍼 메시와 `ShaderMaterial` 은 장면 dispose 시 함께 해제한다. 토글 OFF 는 `setEnabled(false)` (결정 6 — dispose 아님). PR1 범위.
2. **CI 기본 켜짐 성능의 사각** — 결정 3 으로 CI 기본 경로는 띠를 그리지 않아 「CI 통과 → 하드웨어 사용자 프레임 하락」 경로를 CI 가 못 본다는 지적을 수용한다. **기존** `verify-fps-baseline.mjs` 에 `?belt=5400` 강제 셀을 하나 추가한다 (PR3). 판정은 그 가드의 기존 규칙(baseline 대비 ≥ 30% 저하 · 절대 < 30 fps) 그대로 — **새 임계 0**. 1-D 실측 swiftshader N=5000 `39.3` fps 라 절대 30 fps 와의 여유가 크지 않으니 PR3 에서 CI 실측값을 먼저 보고 baseline 을 박제한다. 하드웨어 nightly 러너는 기반이 없어 기각.
3. **epoch rebase 실행 위치** — `|uDays|` 검사는 `uDays` 를 만드는 시간 위상(`updateAt`) 에서 한다. `BELT_EPOCH_REBASE_DAYS` 값은 새로 발명하지 않고 PR1 DoD 의 「JS 미러 vs `positionAt` ≤ 1e-4 AU」 를 만족하는 `|uDays|` 상한에서 도출해 근거를 주석에 남긴다.
4. **`uPxToClip` 리사이즈·DPR** — bind 시 엔진의 현재 렌더 폭·높이에서 계산한다 (캐시하지 않음) → 리사이즈 이벤트 연동이 따로 필요 없다.
5. **core / web 경계** — 결정 3 의 게이트 판정(`detectSoftwareRenderer`) 은 web 이 하고, core 에는 `{ enabled, count, force }` 같은 순수 옵션으로만 전달한다 (결정 6 「core 는 렌더러를 모른다」 와 같은 뜻 — 결정 3 문장이 core 가 판정하는 것처럼 읽힐 수 있어 명시).
6. **생성기 불변식** — `generateBeltPopulation` 출력 전 요소가 `0 ≤ e < 1` · `a > 0` · 유한값임을 단위 테스트로 단언 (PR2).

### 기각

- **`MAX_BELT_PARTICLES = 20000` 신설** — 상한은 이미 있다 (`sim-canvas.tsx` · `asteroid-belt.ts:137` 의 `10_000` clamp). 새 경로도 그 값을 그대로 승계한다.
- **그룹별 drawRange 예약 · N-body 경로 폐기 로드맵** — 비목표 (미래 요구 가정). N-body 경로 공존은 §받아들인 비용에 이미 기록.
- **`discard` 의 TBDR early-Z 비용 · body tier 컬링** — 5400 입자 × 지름 3 px ≈ 화면 4만 px 수준이라 overdraw 근거가 실측 없이 성립하지 않는다. 모바일·하드웨어 하락은 재검토 트리거 2·3 이 이미 잡는다 (실측 전 최적화 발명 금지).
- **GPU 출력 픽셀을 읽는 CPU–GPU golden test** — 신규 비교 하네스라 범위 밖. 대신 PR1 의 JS 미러 단위 테스트 + **트로이 L4 가 목성보다 앞(+60°), L5 가 뒤** 에 보이는지 qa 육안 확인으로 회전 순서·부호를 종단 검증한다 (아래 고유 발견).
- **공명군 「케플러 제3법칙 위반」 · 교육 안내 문구 · 모의 칭동 항** — 공명 천체의 **시간 평균 평균운동이 행성과 정확히 정수비** 인 것이 공명의 정의이므로 `n` 고정은 위반이 아니라 그 평균 성질이다. 힐다 `a` ±0.05 AU 가 만드는 Kepler `n` 차이는 ±1.9% 로, 실제 공명 천체의 `a` 진동과 같은 크기다. 칭동 항은 진폭·주기 파라미터를 새로 들여와야 해 기각. 안내 문구는 토글 표에 설명 필드가 없어 (label 만) 별도 UI 작업이 되므로 범위 밖.

### 고유 발견 (Claude)

- 트로이 구름은 `λ_J ± 60°` 로 위상이 고정되므로, **화면에서 L4 가 목성 공전 방향 앞에 있느냐**가 셰이더의 회전 순서(Ω → i → ω)·부호가 CPU 와 같은지를 보는 가장 싼 종단 증거다. PR2 qa 항목에 넣는다.

### Claude 편향 셀프 체크

- 지적 12건 중 6건 수용 · 5건 기각 · 1건 부분 수용(golden test → 대체 수단)으로, 기각 비율이 높다. 기각 5건은 각각 **기존 코드에 이미 있음**(clamp) / **비목표** / **실측 근거 없음** / **신규 하네스** / **물리 전제 오류** 로 근거가 서로 다르고, 「architect 설계를 지키려는」 단일 사유로 묶이지 않음을 확인했다. 가장 큰 지적(CI 사각)은 수용했다.
