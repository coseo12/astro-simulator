**1-A. 위치 쓰기 경로 [정적 판독].**

- body `mesh.position` 을 쓰는 곳은 두 곳이다 — 시간 위상 `updateAt` 루프 (`solar-system-scene.ts` `updateAt`, 진입 시 스냅샷한 `ox/oy/oz`) 와 `setTier` 즉시 재계산. 두 곳 모두 `recordBodyFrame` · `syncOrbitLinePositions` · `syncSunLightPosition` 을 같은 `(origin, scale)` 으로 부른다 (ADR 1319 결정 2 · #1318 · #1204).
- `setFocusOrigin` 은 origin 만 옮기고 `mesh.position` 을 다시 쓰지 않는다. 일시정지 중에는 다음 `updateAt` (또는 `setTier`) 까지 메시는 이전 기준계에 있다.
- `updateAt` 은 `timeChanged` 바인딩이라 일시정지 (`!running || scale === 0`) 에서는 등록 시 1회 (#1308) 외에 돌지 않는다. `timeChanged` 는 재생 tick 과 점프 (`jumpToDate` · `jumpToJulianDate` — 스크러버 · 「지금」 · 날짜 선택 · 시나리오) 를 **구분하지 않는다** (`simulation-core.ts` 명령 라우터).
- 배속 부호는 `TimeController.scale` 에만 있고 scene 은 모른다. 변경은 `timeScaleChanged` 이벤트로 나간다 (`core-adapter.ts` 가 구독).
- Kepler 경로의 위성 world 좌표는 `parentWorld + local × getOrbitVisualScale(parentId, id)` 다 (`updateAtKepler` → `resolveWorld`). **Newton · Barnes-Hut · WebGPU 경로는 엔진 `positions()` 를 그대로 쓰고 시각 배율을 곱하지 않는다** — 코드 판독만이며 화면 실측은 하지 않았다 (범위 밖, §비-범위).
- 궤도선은 진근점각 등간격 64 seg (e ≥ 0.6 은 256) `LineSystem` 이고, 정점은 모체 원점 기준 · tier renderScale 을 곱한 장면 단위다. tier 전환마다 `rebuildOrbitLines` 로 재생성된다.
- `FloatingOrigin.onOriginShift` 는 「미래 Trail/Particle 모듈」 용 계약으로 주석에 박제돼 있고 구독자는 0 이다. 발화 시점은 `updateAt` 의 mesh 루프 **뒤** (가드 C, #380) 와 `setTier` · `setFocusOrigin` 안이다.

## 결정

### trail (PR1)

**결정 T1 — 점 출처: Kepler 해석해, 이심근점이각 등간격, 무상태.** 천체 i 의 창 `W_i = P_i × f` (`P_i` = `orbitalPeriod(a, orbitMu)`, `f` = Q-T2). 머리 `E_h = E(jd)`, 꼬리 `E_t = E(jd − s · W_i)` (`s` = 결정 T5 의 방향 부호, E 는 공전 횟수까지 펼친 연속값) 를 풀고, 사이 점은 `E_h + (E_t − E_h) · k / N` 에서 궤도 요소로 직접 계산한다. 점 수 `N` = 48 (e ≥ 0.6 은 128 — 궤도선의 고이심률 예외와 같은 임계. 근일점 부근 다각형 꺾임은 [추정], 육안 승인에서 확인). **머리 정점은 샘플이 아니라 scene 의 `worldPositions` 값 그대로** (메시와 동일 출처). 과거 상태를 저장하지 않으므로 점프 · 역재생 · 배속 변경 · 엔진 복귀에 리셋 규칙이 필요 없다 — trail 은 `(jd, 방향)` 의 순수 함수다.

**결정 T2 — 기준계: 위성은 모체 상대.** 위성 trail 점 = `parentWorld(지금) + local(E_k) × getOrbitVisualScale(parentId, id)`. 태양 직속 천체는 태양 기준 (Kepler 경로에서 태양 world = 원점). 근거 1-E — 태양 상대로 그리면 시각 배율 ×30 ~ ×500 이 공전 속도를 같은 배수로 키워 실제에 없는 고리 모양 궤적이 생긴다. 모체 상대 trail 은 위성 궤도선 위에 놓인다. (Q-T3)

**결정 T3 — 정점 표현 · 쓰기 지점.** 정점은 절대 장면 좌표 `(world − origin) × scale` (float64 계산 → `Float32Array`). 기록은 body `mesh.position` 을 쓰는 **두 지점에서만** — `updateAt` (진입 스냅샷 `ox/oy/oz`, `recordBodyFrame` 과 같은 인자) 과 `setTier` 즉시 재계산. `onOriginShift` 는 쓰지 않는다 (축 T2 (c) 기각). 이 결정으로 ADR 20260422 §2 의 「미래 Trail 모듈」 계약은 소비자 없이 남는다 — PR1 이 `floating-origin.ts` · `solar-system-scene.ts` 의 해당 주석을 「trail 은 이 경로를 쓰지 않는다 (ADR 1341 결정 T3)」 로 갱신한다 (주석 계약 drift 방지). 대상 집합은 계수가 아니라 술어로 정한다 — `git grep -n "Trail" -- packages/core/src/coords/floating-origin.ts packages/core/src/scene/solar-system-scene.ts` 의 매칭 중 Trail 모듈의 `onOriginShift` 소비를 전제한 서술 전부 (2026-10-15 실측 매칭 6행).

**결정 T4 — 위상: 시간 위상 멤버, 프레임 위상 아님.** trail 은 카메라에 의존하지 않는다 — ADR 1205 결정 2 의 조건 1 을 통과하지 못하므로 프레임 위상에 넣지 않는다. 같은 이유로 거리 자 선도 넣지 않는다. 따라서 ADR 1205 재검토 조건 3 (멤버 2개째) 은 발화하지 않는다.

**결정 T5 — 역재생 방향.** trail 은 화면에서 **지나온 쪽**에 그린다 — `s = sign(timeScale)`, 배속 0 · 일시정지는 직전 부호 유지. scene 은 배속을 모르므로 `setTrailDirection(sign)` 핸들을 두고 web (`sim-canvas`) 이 `timeScaleChanged` 와 초기 store 값으로 부른다. 방향이 바뀌면 다음 시간 위상에서 반영된다 (일시정지 중 배속 부호만 바꾸면 다음 `updateAt` 까지 이전 방향 — 정지 화면의 trail 은 정의상 「지나온 쪽」 이 없다). (Q-T6)

**결정 T6 — 렌더.** `LinesMesh` 1개 (전 천체 선 묶음, 인덱스 선분), 정점 위치 `updatable`, 정점 색은 **인덱스 기반 고정 페이드** (머리 1 → 꼬리 0, 생성 시 1회 — 프레임마다 색 버퍼 갱신 없음). 색은 천체 `colorHint` (Q-T8). 블렌딩 `ALPHA_ADD` · depth write 없음 — 1-F 에서 가림 픽셀 집합은 블렌딩과 무관했고, 가산이면 trail 이 궤도선 위에서 궤도선을 덮어 끊지 않고 더한다. 궤도선과의 깊이 경합 (1-F `7.6 %`) 은 현행 깊이 그대로 두고 육안 승인에서 판정한다 (Q-T7). `isPickable = false`.

**결정 T7 — 가시성은 명령에서만.** trail 메시의 `setEnabled` 는 (i) 표시 토글 (ii) 엔진 전환 (결정 T8) 에서만 바꾼다. **observer · 시간 위상 · 프레임 위상 어디서도 `isVisible` · `setEnabled` 를 쓰지 않는다** (ADR 1329 교차검증 수용 1 — observer 에서 자기 메시를 끄면 Babylon 이 active mesh 에서 빼고 observer 자체가 다시 돌지 않는다). observer 는 아예 등록하지 않는다 (갱신은 결정 T3 의 두 지점). 처음 켤 때 지연 생성, 이후 `setEnabled` 만 (ADR 1319 결정 6 · 1265 결정 3 과 같은 수명, dispose 는 장면 dispose 때만).

**결정 T8 — N-body 엔진 (Newton · Barnes-Hut · WebGPU · auto→N-body).** 해석해가 엔진 위치와 다르므로 trail 을 그리지 않는다 — core 가 `activeEngine !== 'kepler'` 면 메시를 끄고 (명령 경로 — `setPhysicsEngine` 안), Kepler 로 돌아오면 사용자 의도대로 다시 켠다. web 토글은 그동안 `aria-disabled` + 사유 문구 (`N-body 엔진에서는 궤적을 표시하지 않습니다` — 문구 확정은 dev). (Q-T4)

**결정 T9 — 대상: 궤도선과 같은 집합.** `R_PHASE_BODY_ALLOWLIST` ∩ 궤도 보유 = 현 데이터 35 천체 (sun 제외 전부 — 행성 8 · 위성 16 · 왜소행성 5 · 혜성 3 · 소행성 3). 정점 수 `32 × 49 + 3 × 129 = 1,955`. (Q-T1)

**결정 T10 — 토글 · URL.** 토글 표에 `trails` 행 (라벨 「궤적」). **기본 꺼짐** · `?trails=on` 옵트인 (Q-T5). 토글 표는 기본 켜짐 전제이므로 행에 `defaultVisible` 을 추가하고 `serializeDisplayToggle(visible, defaultVisible)` 로 일반화한다 — 기본값과 같으면 키 삭제, 다르면 `on`/`off`. 기존 9행은 `defaultVisible: true` 로 출력 불변 (round-trip 단위 테스트가 고정). 파서 `parse-trails-mode.ts` (미지정 · 알 수 없는 값 → 꺼짐 + `console.warn`). 소프트웨어 렌더 게이트는 두지 않는다 — 1 px 선이고 기본 꺼짐이라 옵트인이다 (swiftshader 비용은 DoD 에서 잰다 — 재검토 조건 2).

### 거리 자 (PR2)

**결정 R1 — 선택: 기준점 + 현재 선택 천체.** 정보 카드 (관찰) · 우 패널 (연구) 에 「기준점으로」 버튼 → 기준점 A = 그 시점의 선택 천체. 이후 **현재 선택 천체 (`selectedBodyId`) 가 B** 다. 선택 경로 5종 (클릭 · 라벨 · 검색 · 메뉴 · 트리) 을 가로채지 않는다 — 모두 지금처럼 `focusOn` 이고 카메라도 지금처럼 B 로 간다. 줌아웃하면 둘을 한 화면에 볼 수 있다 (포커스 유지). `ui-architecture` §3.2 「기준점 설정」 과 같은 개념이다. (Q-R1)

- B 가 없거나 (자유시점 · reset) A 와 같으면 선을 끄고 수치 자리에 안내 문구.
- 해제: 수치 행의 「기준점 해제」 (×). Esc 는 현행 의미 (자유시점) 그대로 — 선택이 `null` 이 되어 선만 사라지고 기준점은 남는다.

**결정 R2 — 화면 선: 3D `LinesMesh` 2 정점.** 끝점 = A · B 의 `mesh.position` 과 같은 값, 쓰기 지점은 결정 T3 와 같은 두 곳 + 기준점 · 선택 변경 명령 시 1회. 단색 · 불투명 · `isPickable = false`. 가시성은 명령 (`setRuler(aId, bId)` — null 이면 끔) 에서만 (결정 T7 과 같은 규칙).

**결정 R3 — 수치: 물리 거리, 엔진 상태 우선.** `body-distance.ts` 에서 모체 체인 world 계산을 `computeBodyWorldPosition` 으로 분리 export 하고 (`computeBodyDistances` 가 재사용 — 동작 불변), 거리 = `|world(A) − world(B)|`. 시각 배율 미적용, `getBodyState` 우선 · Kepler 폴백 — 카드 거리와 같은 출처 · 같은 4 Hz 주기 (`DISTANCE_REFRESH_MS`). 표시 요소에 원값 `data-distance-m` 을 둔다 (검증용).

**결정 R4 — 표시 자리: 정보 카드 · 우 패널의 한 행.** 관찰 모드 카드 (#1281) 와 연구 모드 우 패널에 「{A}까지 거리」 행을 더한다 — 새 떠 있는 요소 0. 카드를 접으면 행도 접히고 선은 유지된다 (카드 접힘이 포커스를 유지하는 현행 계약과 같은 방향). (Q-R3)

**결정 R5 — 단위.** `≥ 0.01 AU` → `x.xx AU · y억 km` (`formatSunDistance` 재사용), `< 0.01 AU` → km 만 (`formatKmKo` — 지구–달 `38.4만 km` 형식). 연구 모드는 광시간을 덧붙인다 (`d / SPEED_OF_LIGHT`, 분·초). (Q-R4 · Q-R6)

**결정 R6 — 시각 배율 고지.** A · B 중 위성이 있으면 행 아래 한 줄: 「화면의 {위성} 위치는 모체로부터 ×N 떨어져 그려집니다」 (N = `getOrbitVisualScale` — 하드코딩 금지). 근거 1-E. (Q-R5)

**결정 R7 — URL.** `?ruler=<A id>` (`history: 'replace'`). B 는 기존 `?focus=` 가 정한다. 파서는 allowlist 밖 · 빈 값을 무시 + `console.warn`. (Q-R7)

## 결과·재검토 조건

- **기대 효과** — 재생 중 각 천체의 진행 방향과, 이심 궤도 (혜성) 에서 근일점 부근 빠른 이동이 꼬리 길이로 보인다. 두 천체 거리가 시간에 따라 갱신되는 수치로 읽힌다. 기본 화면은 바뀌지 않는다 (둘 다 옵트인).
- **받아들인 비용** — trail 은 Kepler 엔진에서만 (결정 T8). 궤도선 위에서 trail 화소 일부가 궤도선에 가려진다 (1-F). 기준점 모델은 「두 천체를 제3의 시점에서」 측정하려면 줌아웃이 필요하다.
- **재검토 트리거**
  1. 사용자가 trail 기본 켜짐을 원하면 → ADR 1319 결정 8 의 문턱 (하드웨어 A/B −10 %) 으로 측정 후 결정.
  2. D11 에서 swiftshader 켬 상태 증분이 하드웨어 대비 한 자릿수 이상 크면 → 소프트웨어 렌더 게이트 (ADR 1319 결정 3 방식) 재검토.
  3. N-body 엔진 trail 요청 → 히스토리 버퍼 (축 T1 (a)) 를 별도 ADR 로. 그때 `timeChanged` 의 점프 구분 (1-A) 이 선행 과제다.
  4. 육안 승인에서 궤도선 겹침 (Q-T7) 이 거슬린다는 판정 → (b) Amendment.
  5. 사용자가 「카메라를 고정한 채 두 천체 측정」 을 요구 → 결정 R1 (b) 로 Amendment (5 선택 경로 분기).

### 합의 (수용 — 구현 계약 · DoD 추가)

1. **명령 시 즉시 1회 동기** (agy Q3-1 Critical · Q3-2) — 결정 T3 의 쓰기 지점은 `updateAt` · `setTier` 두 곳뿐이라, 일시정지 중 (`updateAt` 미동작) 처음 켜면 지연 생성된 메시의 정점이 채워지지 않는 경로가 본문에 막혀 있지 않았다. 계약 추가: **`setTrailsVisible(true)` · `setTrailDirection` · `setRuler` 명령 핸들러는 메시를 켠 직후 「마지막으로 메시에 쓴 `(origin, scale, jd)`」 로 1회 동기한다** — 새 기준계를 만들지 않고 메시가 지금 쓰고 있는 값을 그대로 쓰므로 머리 이음 (D4) 은 유지된다. 그 결과 결정 T5 의 「일시정지 중 방향 전환은 다음 `updateAt` 까지 이전 방향」 은 「즉시 반영」 으로 바뀐다. DoD D4 상황에 **「일시정지 중 처음 켬」 · 「일시정지 중 역재생 방향 전환」** 2종을 더한다.
2. **`onOriginShift` 구독 0 단언** (agy Q5) — D8 은 가시성 쓰기만 본다. 결정 T3 기각안 (c) 가 몰래 들어오는 결함을 막도록 D8 에 「trail · 자 모듈의 `onOriginShift` 구독 0」 정적 단언을 더한다.
3. **E 연속값의 경계 사례를 D1 에 명시** (agy Q1-1) — 본문 결정 T1 이 이미 「E 는 공전 횟수까지 펼친 연속값」 으로 정했으므로 지적한 wrap-around 는 설계상 막혀 있다. 다만 D1 의 시각 3종이 근일점 통과 직후를 포함한다는 보장이 없어, **D1 에 「꼬리 창이 근일점 (M = 0) 을 가로지르는 시각」 을 천체별 1개 이상 포함**하도록 명시한다.

### 이견 (기각 — 근거)

1. **「일시정지 중 포커스 이동 시 trail 이 엉뚱한 위치로 튄다」** (agy Q2-1 High) — 1-A 대로 `setFocusOrigin` 은 body 메시도 다시 쓰지 않는다. trail 은 메시와 같은 지점에서만 쓰므로 그 프레임에서 **trail 과 메시는 같은 (이전) 기준계에 함께 있다** — 서로 어긋나지 않는다. 다음 `updateAt` 에서 함께 옮겨진다. D4 「일시정지 중 포커스 이동 후 재생 1 프레임」 이 이 경로를 잰다.
2. **「근일점에서 ΔE 증폭으로 점 간격이 벌어진다」** (agy Q1-2) — ΔE 가 커지는 것은 E 등간격 샘플이 **근일점에서 시간 등간격보다 촘촘한** 이유다 (같은 ΔM 이 많은 E 점을 얻는다). 꺾임 여부는 본문이 이미 [추정] 으로 두고 D12 육안 확인 대상으로 남겼다 — 새 사실이 아니다.
3. **`TrailSampler` 인터페이스 선제 추상화** (agy 1.4) — N-body trail 은 재검토 트리거 3 이 별도 ADR 로 다룬다. 지금 추상화 경계를 만들 소비자가 없다 (YAGNI).
4. **거리 자 선을 점선 · 반투명으로** (agy Q4-1) — 시각 배율 고지는 결정 R6 이 맡는다. 선 스타일은 육안 승인 (E9) 에서 조정할 수 있는 rendering 선택이며 결정이 아니다.

### 고유 발견 (사용자 결정에 전달)

1. **Q-T7 (b) 권고** — 궤도선 깊이 경합 (1-F `7.6 %`) 을 육안 판정으로 미루지 말고 trail 이 켜진 동안 궤도선 depth write 를 끄라는 권고. 본문 권고 (a) 와 갈리므로 사용자에게 함께 제시한다.
2. **Q-T2 시간 창 상한** — 혜성 (P ≈ 76 년 → 창 6.3 년) · 포보스 (창 약 38 분) 의 시간 폭 차이를 이유로 상한을 두라는 권고. 결정 T2 (a) 는 **각도 (평균 근점각 30°) 를 고정**하는 설계라 화면상 호 길이는 천체 간 비슷하고, 시간 상한은 새 임계를 만든다 — 메인은 동의하지 않지만 사용자 선택지로 전달한다.
3. **Q-T1 tier 연동** — 개요 화면에서는 태양 직속 천체만, 행성계로 줌인하면 위성 trail 을 켜라는 권고. 사용자 선택지로 전달한다.
4. **페이드가 시간 비례가 아니다** (agy Q1-3) — 정점 색이 인덱스 기반이고 점은 E 등간격이라 이심 궤도에서 페이드가 시간에 비례하지 않는다. 사실이다. 결정 T6 은 비용 (색 버퍼 갱신 0) 을 위해 이를 받아들이며, D12 육안 확인 항목에 「혜성 근일점 페이드」 를 더한다.
