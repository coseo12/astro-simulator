## 배경

PR #551 의 WCAG 2.2 AA 자동 측정 가드 baseline 첫 측정 (`docs/benchmarks/a11y-baseline.json`, 2026-05-24) 에서 3 격차 확정:

| # | 항목 | viewport | 임계 | 현재값 | 마진 |
|---|---|---|---|---|---|
| 1 | axe `serious:target-size` (WCAG 2.2 2.5.8) | desktop + mobile | 버튼 ≥ 24×24 CSS px | < 24 | FAIL |
| 2 | shortcut bar fontSize (실용 권고) | desktop + mobile | ≥ 12 px | 10 px | -2 px |
| 3 | moon orbit `MOON_ORBIT_COLOR_DEFAULT` 명도 대비 (WCAG AA 1.4.11 non-text) | (배경 무관) | ≥ 3:1 | 2.32:1 | -0.68 |

> 참고: `MOON_ORBIT_COLOR_EARTH_FOCUS` 는 10.02:1 PASS — 본 ADR 비대상.

본 ADR 은 [R4 ADR cross-validate](20260520-r4-earth-moon-visualization.md) 의 Gemini 고유 발견 2 ("저시력 사용자에게 불편") 가 실측으로 확정된 후속 처리. 사용자 환경에서 a11y 영향 확인된 사례는 없으나 WCAG 2.2 AA 정합 차원에서 baseline 동결 직후 처리 (medium 우선순위).

## 후보 비교

### 결정점 1 — axe target-size (WCAG 2.2 2.5.8)

| 후보 | 변경 | 모바일 너비 영향 | 결과 |
|---|---|---|---|
| (a) padding 증가 (`px-2 py-1.5`) | 버튼 hit-area ≥ 24×24 px 확보 | **9 × 42 px + 8 × 4 px = 410 px > 375 px (overflow)** | **기각** — R4 §결정 5 의 320 px margin 55 px 안전대 파괴 |
| **(b) `min-w-6 min-h-6` CSS 명시** | hit-area ≥ 24×24 강제 (Tailwind = 6 × 4 = 24 px) | 한글 2글자 width 의존 — fontSize 결정과 결합 | **선택** — padding 보존 + 강제 최소 hit-area |
| (c) WCAG 2.5.8 exception 활용 | "인라인 essential text-link" exception 적용 | shortcut bar 는 핵심 인터랙션, exception 부적합 | **기각** — exception 조건 미충족 |

### 결정점 2 — shortcut bar fontSize 10 px → ≥ 12 px

| 후보 | 변경 | 모바일 너비 영향 | 결과 |
|---|---|---|---|
| (a) 모바일만 `text-xs` (12 px), 데스크톱은 보존 | viewport 분기 신규 도입 | 정책 비대칭 (데스크톱 < 모바일 fontSize) | **기각** — 정책 일관성 위반 + viewport 분기 비용 |
| **(b) `--text-mini` 자체를 12 px (0.75rem) 로 갱신** | globals.css 1 줄 변경, shortcut bar 전역 영향 | 한글 2글자 width 22 → 24~28 px 증가 → 버튼 너비 30 → 34~38 px → 9 × 38 + 8 × 4 = **374 px (margin 1 px)** | **선택 (조건부)** — min-w-6 와 결합 시 hit-area 24 px 강제 + 모바일 안전 마진 1 px (실측 검증 의무) |
| (c) 버튼 텍스트 축약 ("Mercury" → "M") | 텍스트 정보 손실 + 한글 라벨 ("수성" → "수") 부자연 | 정보 손실 | **기각** — R4 §결정 5 의 한글 자연 라벨 정책 (mental model 보존) 파괴 |

**모바일 안전 마진 1 px 실측 의무**: 후보 (b) 채택 시 한글 라벨 (`태양`/`수성`/`금성`/`지구`/`달`/`목성`/`해왕성` + `reset` 영문 + `탐색`) 의 실제 fontSize 12 px 렌더 width 가 추정치 (14 px/글자) 를 초과하면 mobile 375 px overflow 위험. developer 단계 D-T2 실측 → `apps/web/scripts/r1-ui-regression-guard.mjs` PX_RATIO 회귀 가드 통과 + mobile 375 px viewport 좌우 마진 ≥ 0 확인 의무.

**R4 §결정 5 충돌 검증**: R4 박제 `9 × 32 + 8 × 4 = 320 px (margin 55 px)` 의 32 px 추정은 text-mini 10 px 기준. text-mini 가 12 px 로 갱신되면 32 px → 34~38 px 로 자연 증가. R4 §결정 5 의 "모바일 너비 수용" 목표는 보존되지만 안전 마진이 55 → 1~37 px 로 축소. **R4 §결정 5 의 본질 (overflow 차단) 은 보존**, 다만 R6 jupiter 진입 시 발동 트리거 임계 (392 px > 375 px) 가 앞당겨질 수 있음 — 본 ADR 의 R5+ extension 항목으로 박제.

### 결정점 3 — moon orbit `MOON_ORBIT_COLOR_DEFAULT` 2.32:1 → ≥ 3:1

WCAG 1.4.11 non-text contrast 계산 (relative luminance, sRGB 0~1 입력 / 배경 `#000000`):

| 후보 RGB (sRGB 0~1) | 대비비 | sun 시점 시각 noise |
|---|---|---|
| (현재) `Color3(0.25, 0.28, 0.4)` | 2.32:1 | FAIL — 의도된 저명도 |
| (a-1) `Color3(0.30, 0.35, 0.50)` | **3.06:1** | PASS — 명도 26% 상향 |
| (a-2) `Color3(0.33, 0.38, 0.55)` | 3.46:1 | PASS — 명도 50% 상향 |
| (a-3) `Color3(0.35, 0.40, 0.58)` | 3.75:1 | PASS — 명도 60% 상향 (정합 안전대) |
| (a-4) `Color3(0.38, 0.43, 0.62)` | 4.22:1 | PASS — 과도 (sun 시점 noise 가능성) |
| (참고) `EARTH_FOCUS Color3(0.65, 0.7, 0.85)` | 10.02:1 | PASS (비대상) |

| 후보 | 결과 |
|---|---|
| **(a-1) `Color3(0.30, 0.35, 0.50)` — 3.06:1** | **선택** — 최소 임계 충족 + sun 시점 시각 noise 최소화 (명도 26% 상향에 그침). 톤 (R:G:B 비율) 보존으로 EARTH_FOCUS 와 자연 그라데이션 유지 |
| (a-2) ~ (a-4) | 기각 — 임계 충족 마진은 크나 sun 시점 시각 noise 증가. **Visual Fidelity 원칙 §의무 체크리스트 4항목 첫 적용** 검증 후 D-T2 미통과 시 후속 Amendment 로 전환 (트리거 박제) |
| (b) 배경 대비 보장은 R5+ visualization 결정과 결합 | 분리 — R5+ scene rendering 결정 (별도 ADR) 범위 |

### 결정점 4 — Visual Fidelity 원칙 §의무 체크리스트 4항목 첫 적용

`docs/architecture/principles.md` §1 (Visual Fidelity 원칙, #541 명문화) 의 §의무 체크리스트 4항목을 본 ADR 의 moon orbit 색상 변경에 첫 적용:

- [x] **데이터 SSoT 보존 확인** — 변경 대상 `MOON_ORBIT_COLOR_DEFAULT` 는 `packages/core/src/scene/solar-system-scene.ts:482` 의 **scene rendering 상수** (Color3 인스턴스, mesh material 의존). `solar-system.json` (NASA/JPL Fact Sheet 인용) 직접 수정 0. 본 색상은 시각 표현용 — 데이터 SSoT (`moon.radius`, `semiMajorAxisAU`) 영향 0
- [x] **rendering 시점 분리** — `packages/core/physics-engine` (Rust+wasm) 은 `MOON_ORBIT_COLOR_DEFAULT` 에 의존 0 (`grep -rn "MOON_ORBIT_COLOR" packages/core/physics-engine` empty). 적분기는 색상 무관 — P11-A heliocentric m 좌표 계약 보존
- [x] **사용자 D-T2 가이드** — focus 패널 / Info 패널은 색상값을 표기 0 (실측값 표기 의무 무관 — 색상은 시각 표현 only). 본 변경은 시각 표현 강도 (명도) 만 조정, 데이터 표기 영향 0
- [x] **점유율 / 사실 비율 baseline 박제** — 본 ADR §Forensic 측정 결과 (절차 step) 에 변경 전/후 대비비 박제: **2.32:1 → 3.06:1** (sun 시점 시각 noise 검증은 D-T2 의무). `docs/benchmarks/a11y-baseline.json` 의 `moonOrbitContrast.default.contrastRatio` 필드 갱신

## 결정

### 결정 1 — target-size: `min-w-6 min-h-6` CSS 명시 (후보 b) + 컨테이너 가로 스크롤 안전망 (cross-validate 제안 A 수용)

`apps/web/src/components/layout/focus-quick-buttons.tsx` 의 3 `<button>` 클래스에 `min-w-6 min-h-6` 추가 (Tailwind `6 × 4 = 24 px`) + 부모 컨테이너 `<div>` 에 `overflow-x-auto whitespace-nowrap` 안전망 도입.

```diff
- <div className="flex items-center gap-1" data-r1-region="shortcut-bar">
+ <div className="flex items-center gap-1 overflow-x-auto whitespace-nowrap max-w-full" data-r1-region="shortcut-bar">
    ...
-   className={`num text-mini px-1 py-0.5 rounded-sm border ...`}
+   className={`num text-mini min-w-6 min-h-6 shrink-0 px-1 py-0.5 rounded-sm border ...`}
```

- focus-button (R-Phase allowlist), reset-button, free-fly-button 3 곳 모두 `min-w-6 min-h-6 shrink-0` 적용
- 부모 컨테이너 `overflow-x-auto whitespace-nowrap max-w-full` → **R4 §결정 5 위험 #2 (모바일 viewport 수용) 영구 해결** + i18n locale 텍스트 길이 폭발 위험 흡수 + R6 jupiter 진입 trigger 자연 해소
- padding (`px-1 py-0.5`) 보존 — 정상 viewport 에서는 스크롤 발동 0 (현재 한국어 + 12 px 기준 마진 1 px 있음, 다른 locale / R6+ 에서만 자연 발동)
- hit-area ≥ 24×24 px 강제 → axe `serious:target-size` 위반 0

**cross-validate 제안 A 수용 근거**:
- §위험 1 (모바일 1 px 마진 한계) + cross-validate ⑥ (i18n locale 텍스트 길이 폭발) 결합 위험을 본 PR 시점에 영구 해결
- 본 ADR scope 내 — fontSize 12 px 갱신 (결정 2) 이 직접 야기한 마진 축소이므로 동일 PR 에서 안전망 도입 합리
- R4 §결정 5 후보 B (horizontal scroll) 의 부분 채택 — R6 trigger 박제 의무가 자연 해소되며 후속 ADR 부담 감소

**Visual fidelity 변형**: 안전망은 정상 viewport (한국어 + 12 px) 에서 발동 0 — 시각 변화 없음. 스크롤 발동 시에만 부분 가시화 (다른 locale / R6 mars+jupiter 진입 시).

## 위험 / 미해결

### 위험 1 — 모바일 안전 마진 1 px 한계 (cross-validate ④ + ⑥ 영구 해결)

후보 (b) 채택 시 9 × 38 + 8 × 4 = **374 px (margin 1 px)**. 한글 라벨 width 추정치 (14 px/글자) 가 실측보다 클 경우 mobile 375 px overflow 위험.

**영구 해결 (cross-validate 제안 A 수용)**:
- 결정 1 에 부모 컨테이너 `overflow-x-auto whitespace-nowrap max-w-full` 안전망 도입
- 정상 viewport (한국어 + 12 px) 에서는 스크롤 발동 0 (시각 변화 없음)
- 다른 locale / R6+ jupiter 진입 시 자동 스크롤 발동 → 영구 안전 (1 px 마진 위험 + i18n 텍스트 길이 폭발 + R6 trigger 동시 해소)

**근거**: R4 §결정 5 박제 `9 × 32 + 8 × 4 = 320 px (margin 55 px)` 의 32 px 는 text-mini 10 px 기준 추정. text-mini 12 px 갱신 시 자연 증가 32 → 34~38 px (한글 12 px font × 2 글자 + padding 8 + border 2). 본 ADR 의 `overflow-x-auto` 안전망이 미래 모든 변형 (locale / R6+) 를 흡수.

### 위험 2 — sun 시점 moon orbit 시각 noise 증가

후보 (a-1) `Color3(0.30, 0.35, 0.50)` 채택 시 명도 26% 상향. 의도된 저명도 (sun 시점에서 moon orbit 가 너무 눈에 띄지 않도록) 가 변화 → sun 시점 시각 noise 증가 가능.

**사전 완화**:
- 명도 상향 최소화 (후보 a-2~a-4 대비 가장 보수적인 a-1 선택)
- 톤 보존 (R:G:B 비율) 으로 EARTH_FOCUS 자연 그라데이션 유지
- D-T2 사용자 인지 검증 (Visual Fidelity §의무 체크리스트 의무 4항목 적용)
- D-T2 미통과 시 후속 Amendment 트리거 (예: background fade-out alpha 도입 — R5+ scene rendering 결정 분리)

### 미해결 1 — R6 jupiter 진입 시 모바일 overflow trigger (영구 해소)

R4 §결정 5 박제: R6 진입 시 11 버튼 × 32 px + 10 gap × 4 px = 392 px > 375 px → horizontal scroll 또는 2단 발동. 본 ADR 의 text-mini 12 px 갱신 시 11 × 38 + 10 × 4 = **458 px** → trigger 임계 더 빠르게 도달.

**해소**: 결정 1 의 `overflow-x-auto whitespace-nowrap` 안전망이 R6+ 모든 진입을 흡수. R6 진입 ADR 에서 별도 레이아웃 결정 의무 0 (자연 스크롤). 단 R6 진입 시 사용자 D-T2 1 회 검증 의무 (스크롤 UX 가 자연스러운지 확인) 박제.

### 미해결 2 — Visual Fidelity §의무 체크리스트 첫 적용 학습

본 ADR 이 #541 명문화 이후 **첫 본 인스턴스화**. 4항목 적용이 본 ADR 의 색상 변경 (시각 표현 강도 조정) 에는 직관적 PASS 하나, 향후 더 복잡한 시각 결정 (예: R5+ saturn ring shader, jupiter cloud pattern) 에서 적용 정밀도 검증 의무.

**조치**: 본 ADR 의 적용 결과를 향후 R-Phase ADR 의 reference 로 cross-link 박제. 적용 difficulty 가 드러나면 #541 추가 Amendment 트리거.
