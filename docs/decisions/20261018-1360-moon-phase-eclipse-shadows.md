## 배경

이슈 #1360 의 목표는 (1) 월식 — 달이 지구 그림자에 들어가 어두워지고 개기 때 붉어짐 (2) 일식 — 달 그림자가 지구 표면에 떨어짐 (3) 달 위상 — 현재 조명이 태양–지구–달 기하와 맞는지 확인하고 맞지 않으면 바로잡기다. #1354 가 식 날짜 · 종류 판정 (`eclipse-geometry.ts`) 을 넣었고, 그림자 · 위상 렌더는 그 ADR 의 비목표였다.

설계의 핵심 쟁점은 **어떤 기하로 그림자를 그리는가**다. 장면의 달은 지구로부터 실제 거리 ×30 에 그려지고 (`orbit-visual-scale.ts`), 천체 반경은 bodyScale 로 과장된다.

### 실측 (2026-10-18, architect — 앱 코드 변경 0, 페이지 주입 POC)

측정 환경: develop `99194931` dev 서버 · 1280×720 · DPR 1. 백엔드 3종 — **SwiftShader WebGL2** (Playwright headless · `ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device …))`) / **ANGLE Metal WebGL2** (실 Chrome headful · `ANGLE Metal Renderer: Apple M1 Pro`, `navigator.gpu` 제거로 강제) / **WebGPU Metal** (실 Chrome headful · adapter `apple / metal-3`). 위치 · 기하는 core `dist` 의 `resolveBodyChainPosition` · `lunarEclipseGeometry` · `solarEclipseGeometry` 를 그대로 호출했다.

**1-B. 달 위상 [실측].** 관측자 = 지구 중심. 물리 `k_phys` 는 배율 미적용 위치, 화면 `k_scr` 는 달을 `local × 30` 에 둔 위치로 계산했다. 픽셀 `k_px` 는 SwiftShader 에서 카메라를 지구→달 선 위 (달 반경의 60배, fov 3°) 에 두고 달만 그린 뒤 `lum > 100` 픽셀 수 / 디스크 면적이다 (`?rotate=off`).

| JD | `k_phys` | `k_scr` | `k_px` | `k_px − k_scr` |
| --- | --- | --- | --- | --- |
| 2451545 | 0.2306 | 0.2607 | 0.2382 | −0.0225 |
| 2451552 | 0.0277 | 0.0325 | 0.0228 | −0.0097 |
| 2451559.5 | 0.6595 | 0.6911 | 0.6734 | −0.0177 |
| 2451566 | 0.9757 | 0.9788 | 0.9753 | −0.0035 |
| 2461331.5 | 0.4389 | 0.4782 | 0.4585 | −0.0197 |

- 셰이더 위상은 **화면 기하**를 따른다 — `k_px` 는 `k_scr` 보다 일관되게 `0.004 ~ 0.023` 작고 (휘도 임계 100 이 soft terminator 안쪽을 자르는 편향), 이 편향이 `k_px` 를 우연히 `k_phys` 쪽으로 당긴다. 그래서 **픽셀 `k` 는 화면 기하 결함을 판별하지 못한다** (현행 `|k_px − k_phys|` 최대 `0.0196`).
- 2년 (`0.37` 일 간격) 스윕에서 `|k_scr − k_phys|` 최대 **`0.0399`**, 위상각 차 최대 **`4.576°`**. 삭망 근처 (식 시각) 에서는 차가 작다 (위 표 2451552 · 2451566).

**1-C. 지구 자전축 · 자전 위상 [실측 — 범위 밖 발견, Q-O].** `?rotate` 기본 (켬), 지구 mesh world 행렬로 local `+Y` (마스크 규약상 북극) 와 태양 직하점의 local 위경도 (`lon = atan2(z, x)`, ADR 756 §A4.3 규약) 를 쟀다.

| 시각 | 장면 자전축 (world) | 장면 태양 직하 위도 | 실제 |
| --- | --- | --- | --- |
| 2024-06-20 20:51 UT (하지) | `(0, −0.3978, 0.9175)` | **−23.44°** | +23.44° |
| 2024-12-21 09:20 UT (동지) | 같음 | **+23.44°** | −23.44° |
| 2017-08-21 18:26:40 | 같음 | −11.96° | +11.86° (NASA 태양 Dec `+11°51′43″`) |

실제 북극 방향은 황도 좌표 `(0, +sin ε, cos ε)` 다. 장면은 `y` 부호가 반대라 **지구의 계절이 뒤집혀 있다** — 6월에 남반구가 여름이다. 원인은 `self-rotation.ts` 의 `tilt = RotationX(π/2 + ε)` (축 방위각 world X 고정 근사 — ADR 756 Amendment 2 §결정 3 · #1130 범위 밖) 이다. 또 자전 위상은 `(jd − 2451545) × ω` 이고 ω 는 `rotationPeriodHours = 23.9345` 에서 나온다 (GMST 와 무관). ADR 756 §A4.3 이 이미 「특정 jd 의 sub-solar 경도는 천문 정확하지 않다」고 적었다.

그 결과 일식 그림자 축이 지표에 닿는 점을 **장면 지도** 위로 옮기면 2017-08-21 은 `11.0°N 173.0°W` (태평양), 2024-04-08 은 `12.0°N 159.0°E` 다. NASA 최대식 지점은 각각 `36°58.0′N 87°40.3′W` · `25°17.5′N 104°07.2′W` 다 (출처 §기준값).

**1-D. 일식 본영 지표 위치 — 위치 모델 한계 [실측].** 지구 방향과 무관하게, #1354 위치 모델 (B9) 의 그림자 축 지표 교점을 실제 GMST (IAU 1982 식, ΔT = NASA 표기값) 로 지리 좌표로 바꿔 NASA 와 비교했다.

| 일식 | NASA 최대식 시각의 모델 교점 | NASA 최대식 지점까지 | 모델 경로의 최근접 거리 (시각 차) | NASA 경로 폭 |
| --- | --- | --- | --- | --- |
| 2017-08-21 | `38.62°N 96.45°W` | 792 km | **200 km** (+19.5 분) | 114.7 km |
| 2024-04-08 | `31.30°N 92.79°W` | 1,293 km | **387 km** (−29 분) | 197.5 km |

모델 본영 경로의 중심선이 NASA 최대식 지점에서 경로 반폭 (57 · 99 km) 보다 멀다 — **렌더가 완벽해도 「NASA 경로 안」 기준은 #1354 위치 모델 때문에 성립하지 않는다.** 이 기준은 렌더 정확도를 재지 않는다.

**1-E. 화면 기하 [실측 — 이슈 전제 정정].** 이슈 본문은 「화면의 달이 지구 본영 길이 (`~1.38e6 km`) 보다 멀어 화면 기하로는 월식이 성립하지 않는다」고 적었다. 물리 반경 기준으로는 맞다 (본영 길이 `1,371,423 ~ 1,396,053 km` 대 화면 달 거리 `11,103,691 ~ 12,059,829 km`). 그러나 **장면의 렌더 반경**을 `lunarEclipseGeometry` 식에 그대로 넣으면 (태양 렌더 반경이 상대적으로 작아) 본영 원뿔 `320,786` 장면 단위가 지구–달 장면 거리 `294,676` 보다 길어 **월식이 성립한다** — 대신 크기가 틀린다.

| 2022-11-08 최대식 | σ | 본영 `Ru` | 반영 `Rp` | 달 시반경 | 종류 |
| --- | --- | --- | --- | --- | --- |
| 물리 (판정식) | 0.234° | 0.677° | 1.215° | 0.254° | 개기 |
| 화면 렌더 반경 | 0.234° | 1.234° | **28.380°** | 0.918° | 개기 |

같은 방식으로 2025-03-14 는 물리 개기 → 화면 부분, 2023-05-05 는 물리 반영 → 화면 부분이다. 지구 → 달 **방향**이 배율과 무관하므로 σ 는 같고, 반경이 틀린다.

**1-F. 렌더 방식 POC [실측].** 절차 셰이더 fragment 에 그림자 함수를 문자열 주입했다 (`Effect.ShadersStore` 원문 + `ShaderMaterial.shaderPath` 를 소스 객체로 교체, submesh `drawWrapper.defines` 무효화로 재컴파일). 합성은 `shade -= sunShade * occ; shade += glow * umbra;` — `occ = 0`, `umbra = 0` 이면 연산이 정확한 항등이 되는 형태다. **양성 대조** (전 표면 머티리얼에 전면 차폐) 로 주입이 실제로 살아 있음을 함께 확인했다 — 초회 시도에서 양성 대조 diff `0` 이 나와 주입 무효 (submesh 별 effect 저장) 를 잡았다.

### 축 S — 판정식 SSoT 공유 가능성

- **월식**: `lunarEclipseGeometry` 가 이미 σ · `Ru` · `Rp` · `S☾` 를 반환한다. uniform = `(σ/S☾)·ĉ` (그림자 중심 → 달 중심 방향, 하늘면) · `Ru/S☾` · `Rp/S☾` — **출력 그대로**로 충분하다.
- **일식**: fragment 마다 그림자 축 거리 `z` 에서 `l1(z) = z·tan f1 + R☾·sec f1`, `l2(z) = z·tan f2 − R☾·sec f2` 가 필요하다. 현행 `solarEclipseGeometry` 는 `f1` · `f2` 를 내부에서만 쓴다 → **원뿔 파라미터를 반환하는 함수를 추출해 판정과 uniform 이 함께 쓴다** (판정 결과 비트 동일 — 기존 E1 ~ E5 테스트가 가드).

## 결정 (Provisional — Q 표 권고안 기준)

### 기하 · SSoT

1. **G1 — 그림자는 물리 기하 (축 G (a)).** uniform 의 입력은 판정식과 같은 「지구 중심 달 · 태양 물리 위치 [m] + `EclipseRadii`」 이다.
2. **G2 — 판정식 공유.** `eclipse-geometry.ts` 에서 일식 원뿔 파라미터 (`axis` · `tanF1` · `tanF2` · `R☾·sec f1` · `R☾·sec f2`) 를 반환하는 순수 함수를 추출하고 `solarEclipseGeometry` 가 그것을 쓴다. 월식 uniform 은 `lunarEclipseGeometry` 출력에서 만든다. uniform 빌더는 `events/` 옆 순수 함수 (Babylon 무의존) 로 둔다.
3. **G3 — 물리 위치의 출처 = 장면이 이번 프레임에 쓴 「배율 전」 값.** Kepler 경로는 `localPositions` (`resolveWorld` 가 ×N 을 곱하기 **전**), N-body 경로는 엔진 `positions()` 의 `moon − earth` · `sun − earth`. 한 함수 (`physicalLocal(id)`) 가 두 경로를 감싼다.
   - ⚠️ **위성 배율 · N-body 와의 관계를 「독립」 으로 적지 않는다** (#1354 교훈). 이 함수는 **배율이 어디서 곱해지는지에 의존한다** — 현재 Kepler 만 곱하고 N-body 는 곱하지 않는다 (ADR 1341 Amendment 3). N-body 경로가 배율을 곱하게 바뀌면 이 함수의 N-body 분기도 「배율 전」 값을 읽도록 함께 바뀌어야 한다. 단위 테스트가 「배율 30 ↔ 1 에서 uniform 동일」 을 단언해 이 의존을 고정한다 (DoD D2).
4. **G4 — 위상 보정 (Q-P).** 달의 `uSunDirection` 기준점을 메시 위치에서 **물리 위치** `earthMesh + physicalLocal(moon) × renderScale` 로 바꾼다 (달 전용 — 다른 위성은 `StandardMaterial` · `PointLight` 라 같은 화면 기하 위상이지만 범위 밖). 장면 달 위상의 `|Δk|` 최대 `0.040` 이 사라지고, 그림자 (물리) 와 위상 (물리) 의 기하가 하나가 된다.

### 렌더

5. **R1 — 해석 그림자 uniform (축 R (a)).** 절차 셰이더에 uniform 5개 (`uEclMode` · `uEclA` · `uEclAxis` · `uEclK` · `uEclGlow`) 와 함수 하나. 합성은 **차감 · 가산 형태** — `shade -= sunShade * occ; shade += glow * umbra;` (`occ = umbra = 0` 이면 항등. 1-F 에서 3 백엔드 바이트 동일 실측). `#define` 분기는 쓰지 않는다 — define 변경은 effect 재생성이고 Babylon `ShaderMaterial.isReady` 가 새 effect 컴파일 전 `false` 를 반환해 그 동안 메시가 그려지지 않는다 [정적 판독 — `shaderMaterial.pure.js` `isReady`].
6. **R2 — 모드는 머티리얼별.** 그림자를 받는 머티리얼은 달 (월식) · 지구 (일식) 두 개의 high · mid 변형 + 지구 구름뿐이다. 그 밖의 절차 머티리얼 (화성 · 목성 · 천왕성 · 해왕성) 은 `uEclMode = 0` 고정. 식이 아닐 때 (월식 `σ ≥ Rp + S☾`, 일식 `γ ≥ 1 + l1`) 는 달 · 지구도 `0` 이다.
7. **R3 — 합성 순서 (지구).** 직사광 차폐는 `shade` 단계 (절차 변조 × 명암 곱 전) 에 넣는다. **rim 은 같은 `occ` 로 줄이고** (rim 은 산란된 햇빛 — `rim -= rim * occ`), **야간 불빛은 건드리지 않는다** (`nightFactor` 는 `ndl` 만 보므로 낮면 그림자에서 불빛이 켜지지 않는다 — 실제로는 본영 안 도시 불빛이 보이지만 #1226 계약 「낮면 불변」 을 깨지 않는 쪽을 택한다). **구름 셰이더에 같은 함수를 넣는다** (Q-C) — 함수 텍스트는 사본 2벌이 되므로 #1215 의 노이즈 계약 (`sun-shader.test.ts` `NOISE_CONTRACT_LINES`) 과 같은 방식으로 텍스트 동일성을 테스트로 묶는다.
8. **R4 — 반영 모델 (Q-M).** 거리 선형 `vis = clamp((s − ru) / (rp − ru), 0, 1)`. 태양 원반 가림 면적 정확식은 쓰지 않는다.
9. **R5 — 월식 색 (Q-L).** Danjon L = 2 표현을 고정 미학 상수로 둔다 — 본영 안에서 붉은 빛 (`glow`) 을 더하고 **본영 가장자리 쪽을 밝게** (L = 2 서술). 세기는 사용자 육안 승인에서 확정하며 DoD 하한은 R/G (D3).
10. **R6 — 일식 본영 크기 (Q-U).** 물리 그대로. 지구 화면 반경 257 px 에서 본영 핵 대역 (on/off 휘도비가 최솟값 + 0.02 이하인 픽셀) 이 58 ~ 92 픽셀 (1-F) 이고, 반영이 주된 시각 신호다. 지구 화면 크기가 bodyScale 로 과장돼도 그림자는 **지구 반경 단위**로 계산되므로 (uniform `A = 달 위치 / R⊕`, fragment 는 world normal) 지표에서 차지하는 각 영역은 실제와 같다.

### 연계 · 경계

11. **C1 — 비용 · 측정.** CI fps 셀을 신설하지 않는다 — 기본 화면은 절차 표면 픽셀이 0 이라 (1-F 양성 대조 diff 0) 이 기능의 fragment 비용이 들어갈 자리가 없다. 비용은 PR 에서 백엔드 3종 실측으로만 적는다 (DoD D7).
12. **C2 — 검증용 토글.** core 장면 핸들에 `setEclipseShadowsEnabled(boolean)` (기본 `true`). UI 토글은 두지 않는다 (Q-T). 같은 프레임 on/off 대조가 이 setter 로 이뤄진다.
13. **C3 — 식 선택 카메라 (Q-S, ADR 1354 Q-S Amendment).** 월식 선택 → `focusOn('moon')` + 시점을 달의 지구 쪽 반구로. 일식 선택 → `focusOn('earth')` + 시점을 지구의 태양 쪽 반구로. `FocusTarget` 에 선택적 시점 방향을 추가한다. 거리 자 · 배율 고지는 1354 그대로.
14. **C4 — 지구 방향 (Q-O).** 계절 반전 · 자전 위상 (1-C) 은 **별도 이슈로 분리하고 일식 PR 보다 먼저** 처리한다 (권고). 그때까지 일식 위치 DoD 는 관성계 기준 (D4) 이다.
15. **C5 — 비-대상 경로.** `?surface=off` (`StandardMaterial`) · LOD low (glow marker) 는 그림자 · 위상 보정 없음. N-body 는 G3 대로 동작한다 (사건 패널은 ADR 1347 D8 대로 비활성).

- **기대 효과** — 식 사건을 고르면 달 · 지구 표면에 판정식과 같은 기하의 그림자가 보이고, 시간을 움직이면 그림자가 지나간다. 식이 아닌 시각의 화면은 바이트 동일.

### 단독 재검토 (질문별)

1. **물리 기하 그림자의 시각적 모순** — 화면의 달은 지구로부터 ×30 거리에 있어 지구 본영 원뿔 「밖」 처럼 보이는 위치에서 어두워진다. 그림자 원뿔 자체는 그리지 않으므로 화면에서 직접 모순되는 기하가 보이지는 않는다. 「왜 어두워졌는가」 는 1354 배율 고지와 사건 선택 문맥이 설명한다. 축 G (b) (화면 기하) 의 결함 (보름 +1일에도 감광 · 일식 그림자가 지구 97 ~ 98 % 덮음) 이 더 크다. 결론 유지.
2. **그림자 0 바이트 동일** — 차감 · 가산 형태 (`shade -= x*0`) 는 IEEE 에서 항등이지만, 셰이더 컴파일러가 식 구조를 재배열하면 결과 비트가 바뀔 수 있다. 본문 §구현 인계가 이미 이를 적고 「PR 마다 다시 잰다」 로 막았다 (D5 (iii)). 추가 처방 없음.
3. **지구 자전축 부호 반전 판정** — Babylon 좌표계 (left-handed) 와 장면 황도 좌표 매핑 차이로 오판했을 가능성을 검토했다. 그러나 본문 1-C 의 판정량은 **장면 안에서 잰 태양 직하 위도** (2024-06-20 하지 `−23.44°`) 라 좌표계 손잡이와 무관하다 — 같은 장면의 축과 같은 장면의 태양 방향 사이 각이다. 다만 「북극」 이 어느 극인지는 셰이더 위도 정의와 표면 마스크 (야간 불빛 — 실제 지리) 방향에 달려 있으므로, 별도 이슈에서 **마스크 지리의 북쪽 = 장면 +축** 을 먼저 실측으로 확정하라 (구현 계약).
4. **일식 DoD 관성계 기준** — 본영 핵 ↔ 판정식 축 교점 거리는 화면 기하 결함판 (0.48 · 0.57 R) 과 정상 (0.0012 · 0.0143 R) 을 40배 이상 가른다. 지구 방향과 무관한 축이라 Q-O 처리 전에도 유효하다. 결론 유지.
5. **위상 보정 ↔ #782 광원 계약** — G4 는 달의 `uSunDirection` 기준점만 바꾸고 world normal 경로는 그대로라 #782 계약 (광원 world normal) 과 충돌하지 않는다. 다른 위성은 범위 밖으로 「미처리」 라고 명시돼 있다 (§비-범위).
6. **Q 표** — 권고안에 반대할 항목은 없다.

### PR3 구현에서 정한 것 (결정과 충돌 없음 — 범위 안 구체화)

1. **빌더의 「달이 태양 쪽」 조건** — `solarEclipseGeometry` 의 경계식은 삭 근처에서만 부르는 식이라, 망 (달이 지구 뒤) 에서는 기본면 거리 `z < 0` 로 `|l2|` 가 커져 「개기」 를 낸다 (단위 테스트 실측 — 2022-11-08 월식 시각). 장면은 매 프레임 그림자를 계산하므로 `solarEclipseShadowUniforms` 가 `moon·axis ≥ 0` 이면 그림자 없음으로 막는다. 판정식 자체는 바꾸지 않았다 (#1354 E1 ~ E5 · PR1 동결 사본 대조 불변). 결정 R2 의 「식이 아닐 때 (`γ ≥ 1 + l1`) 는 0」 에 이 조건이 더해진 꼴이다.
2. **밤 반구 게이트** — 일식 분기는 `n·axis > 0` (축 기준 밤 반구) 에서 0 이다. 그림자 원기둥은 지구를 관통해 반대편에서도 「축 근처」 가 되는데, 그곳은 지구 자신에 가려 달 그림자와 무관하다. 직사광은 밤면에서 이미 0 이라 이 게이트가 바꾸는 것은 밤면 쪽 rim 띠 (`rimNdlLo < ndl < 0`) 뿐이다. POC 의 `z < 0` 조기 반환은 지구에서 발동하지 않으므로 (달이 ~60 R 앞) 이 게이트로 대체했다.
3. **구름은 같은 상수 보간** — 결정 R3 은 함수 텍스트 사본 2벌을 테스트로 묶으라고 했으나, 구름 fragment 가 `ECLIPSE_SHADOW_GLSL` 을 그대로 보간하므로 사본이 생기지 않는다 (`cloud-layer.ts` 가 이미 `procedural-planet-shader.ts` 를 import 한다). 테스트는 구름 fragment 가 그 상수를 포함하는지와 합성 위치를 단언한다.
4. **C3 일식 = 지구 포커스 + `facing-parent`** — 사건 종류 데이터에 `focusBodyId` (생략 = 주체) 를 두고 일식 행만 `'earth'` 다. 지구의 모체가 태양이라 PR2 의 `facing-parent` 시점 (위로 15°) 이 그대로 「지구의 태양 쪽 반구」 가 된다. 거리 자 기준점 지구 (ADR 1354 결정 E5) 는 그대로라, 지구를 고른 상태에서는 거리 자가 안내 문구로 바뀐다 (종전 일식 선택은 지구–달 거리). 달을 기준점으로 바꾸면 지구–달 선이 그림자 중심 (달 직하점 근처) 에서 화면 아래로 그어져 그림자를 가린다 — 그래서 기준점은 바꾸지 않았다.
5. **지리 고지** — Visual Fidelity 체크리스트 3항의 「일식 그림자의 지리 위치를 고지할지는 Q-O 결과에 따른다」: #1362 · #1366 이후 렌더 그림자 (본영 핵 픽셀) 중심은 위치 모델 참 지점에서 `0.4 ~ 1.5` km 다 (PR3 실측 — SwiftShader 근접 시점 6건, `0.0014` R/px). 남는 차이는 위치 모델 ↔ NASA (§1-D `200` · `387` km) 이고 렌더와 무관하므로 새 고지는 두지 않았다.
