# CLAUDE.md 비대화 방지 상세 프로토콜

> **요지**: CLAUDE.md 는 매 세션·매 턴 전량 어텐션 대상이다. 크기가 커질수록 각 규칙의 상대적 비중이 희석되어 "많이 적어도 지켜지지 않는" 역설이 발생한다. 본 가이드는 CLAUDE.md 의 **각인층** 기능을 보호하는 운영 프로토콜이다.
>
> 본문 1줄 요약은 CLAUDE.md `## 원칙 > ### CLAUDE.md 비대화 방지` 참조. 본 문서는 상세 실행 절차.

---

## 1. 용도 구분 (각인층 / 참조층)

### 1.1 각인층 (CLAUDE.md 본문)
세션 시작 즉시 상기돼야 **행동이 바뀌는** 규칙만 본문에 남긴다.

- CRITICAL DIRECTIVE (절대 규칙)
- 원칙 한 줄 요약 — "무엇을 우선할지" 판정
- 금지/강제 규칙 — "하지 마라 / 반드시 해라"
- 트리거 조건 — "이 상황이면 이렇게"
- **근거 링크 (볼트·이슈 번호)** — §1.4. `grep` 으로 도달 불가능한 **유일 회수 키**라 참조층으로 강등할 수 없다

### 1.2 참조층 (`docs/` 포인터)
필요 시 탐색 가능한 상세는 참조층으로 분리한다.

- 프로토콜 스텝 / 플로우차트
- 매트릭스, 표, 체크리스트
- JSON 스키마, 코드 블록
- 근거 **서술** (재현 시퀀스, 과거 사례 상세, 실측 수치표) — 근거 **링크**(볼트/이슈 번호)는 각인층, §1.4
- 예시 시나리오, 사례 비교

### 1.3 판정 질문
블록을 본문에 인라인할지 `docs/` 로 옮길지 애매할 때:

> "이 블록을 읽지 않으면 다음 응답에서 즉시 잘못된 행동을 할 것인가?"

- **예** → 각인층. 한 줄로 압축 가능한지 먼저 확인
- **아니오** → 참조층. 본문에는 "무엇을 하라" 1~3 줄 + `docs/` 링크

### 1.4 경계 사례 — 근거 **링크**는 남기고, 근거 **서술**은 옮긴다 (#962 / #980)

"링크조차 분량 부담인가?" 의 답:

- **근거 링크(볼트/이슈 번호)는 각인층.** 링크 1개 ≈ 40~80자로 비용이 낮다.
- **근거 서술(3~5줄)은 참조층.** *"800%+ CPU / 52 좀비 / ETIME 3h17m"* 같은 재현 수치는 규칙을 **강화하지 않고 분량만 차지**한다. 단 규칙에 해당하는 **임계값**(예: ETIME 30분)은 링크가 아니라 규칙이므로 별개로 남는다.

> **왜 링크는 남기는가 (#980 축 B 정정)**: **볼트 번호는 저장소 `grep` 으로 도달 불가능한 유일한 회수 키**이기 때문이다. 규칙 문장·명령 리터럴·임계값은 잊혀도 코드/문서를 `grep` 하면 되찾을 수 있지만, `volt #79` 같은 **외부 저장소 이슈 번호는 본문에 적혀 있지 않으면 어떤 검색으로도 복원되지 않는다** — 그 규칙이 어떤 사고에서 나왔는지 확인할 경로가 영구히 끊긴다.
>
> 이전 근거였던 *"근거를 모르면 규칙이 임의 완화되므로 링크가 억제력을 갖는다"* 는 **폐기**한다. **읽지 않은 URL 은 억제력이 없다** — 억제력은 규칙 문장 자체의 명령형(금지/의무)에서 나온다. 약한 논거를 세워 두면 미래 다이어트 작업이 그 논거를 반박하며 링크를 잘라낼 수 있으므로, 근거를 **회수 가능성**으로 교체한다 ([#962](https://github.com/coseo12/astro-simulator/issues/962) 축 A reviewer 판정 → [#980](https://github.com/coseo12/astro-simulator/issues/980) 축 B 집행).

## 2. 추출 기준 (블록 추가/수정 시 체크)

다음 중 **하나라도** 해당하면 `docs/` 로 추출한다:

| 기준 | 임계 |
|---|---|
| 표/매트릭스 행 수 | 3 행 이상 |
| JSON/코드 블록 라인 수 | 5 라인 이상 |
| 프로토콜 스텝 수 | 3 단계 이상 + 각 단계 보조 설명 포함 |
| 근거 이슈 링크 수 | 2 개 이상 연결 |

> 마지막 행은 **블록을 추출하라**는 트리거이지 *"링크를 지우라"* 가 아니다. 추출 후에도 근거 링크는 잔여 본문에 남는다 — §1.4.

### 2.1 남기는 본문 포맷
추출 후 CLAUDE.md 본문에는 다음 포맷으로만 남긴다:

```markdown
### <주제>
- <원칙 1~3 줄>
- 근거: volt [#N](<url>) — 한 줄 요약
- 상세: [docs/<path>.md](docs/<path>.md)
```

`근거:` 줄은 **볼트·이슈 유래가 있는 블록에서 고정 요소**다 (§1.4). 형식은 **`근거:` 또는 `상세:` 줄 중 한 곳에 1회 존재**하면 충족으로 본다 — 실측상 지배 패턴이 `상세:` 이기 때문이다.

#### 매칭 관례 (정본 — [#990](https://github.com/coseo12/astro-simulator/issues/990) 축 C)

충족 판정은 **줄머리 라벨 + 콜론** 술어 하나로 고정한다.

| 술어 | 정규식 | 판정 |
|---|---|---|
| strict | `^- (근거\|상세):` | **정본** |
| loose (접두 매칭) | `^- (근거\|상세)` | 기각 |

두 술어는 `- 상세 (라운드 이탈 / …):` 처럼 **콜론 앞에 괄호 수식어**가 붙은 줄에서 갈린다. strict 를 정본으로 삼는 근거 셋:

1. **선언 포맷과의 동일성** — 위 포맷 블록과 CLAUDE.md `## 실전 교훈` 머리말 컨벤션이 **둘 다 콜론이 붙은 줄머리 라벨 형태**를 선언한다 (머리말은 `근거:`, 포맷 블록은 `근거:` / `상세:`). 하중을 지는 것은 *"콜론이 붙어 있다"* 이고 그건 양쪽 다 참이다 — 라벨 **집합**의 어긋남은 별개 문제였고 [#1047](https://github.com/coseo12/astro-simulator/issues/1047) 이 아래 §라벨 집합 판정 으로 종결했다. 술어가 선언 포맷보다 넓으면 측정 대상이 규범이 아니라 그 **상위집합**이 되며, 이는 #980 이 고친 *"라벨과 술어가 다르다"* 와 같은 클래스다.
2. **오탐 차단** — loose 는 `- 근거를 모르면 …` 같은 **산문 불릿**도 계수한다 (3줄 픽스처 실측: loose 3 / strict 1). 두 술어 모두 오차가 있으나 — strict 는 괄호형을 놓치고 loose 는 산문을 주워담는다 — 놓친 쪽은 아래 3항으로 비용 없이 회수되는 반면 주워담은 쪽은 값을 부풀린 채 남는다.
3. **포용의 실익이 없다** — 괄호형은 수식어를 콜론 뒤로 옮기면 **정보 손실 0 / 문자 순증 0** 으로 해소된다. loose 채택으로 얻는 것은 편집 1회 회피뿐이다. 실제로 #990 축 D 에서 해당 1건을 재배치했고, **현재 코퍼스에서 두 술어는 동값(18 줄)** 이다. ⚠️ **동값은 축 D 가 갈림 사례를 없앤 결과이지 관례 고정이 불필요하다는 뜻이 아니다** — 괄호형 블록이 새로 쓰이는 순간 다시 갈리고, 그때 정본이 없으면 착수 시점의 `12` vs `13` 이 그대로 재발한다. 즉 이 절은 **현재를 설명하는 게 아니라 다음 갈림에 대비**한다.

> **관례 미명시의 대가는 이 이슈 착수 시점에 재현됐다** — #990 본문은 strict 로 센 `12` 를 적었는데 착수 측정의 첫 술어(loose)는 `13` 을 냈고, 본문이 나열한 *"미충족 5블록"* 목록도 strict 에서만 정확했다 (loose 에서는 4건). **목록의 정오 자체가 관례에 의존**한 것이 축 C 가 필요한 이유다.

> **실측 (`CLAUDE.md` `## 실전 교훈` 범위, 20 블록)** — ⚠️ **술어와 각주를 함께 읽을 것**. 충족 계열은 위 **정본(strict)** 기준.
>
> | 항목 | 술어 (정규식) | 2026-08-08 | 2026-08-13 |
> |---|---|---|---|
> | 회수 키 보유 | `#[0-9]+` **또는** `](`·`http` <sup>a</sup> | 17 / 20 | **17 / 20 (85%)** |
> | 회수 키 전무 | 위 둘 다 없음 = **원리적 충족 불가** <sup>a</sup> | 3 / 20 | **3 / 20 (15%)** |
> | (참고) 번호만 | `#[0-9]+` 한정 <sup>a</sup> | 14 / 20 | 14 / 20 |
> | L73 형식 충족 | `^- (근거\|상세):` <sup>b</sup> | 12 / 20 | **17 / 20 (85%)** |
> | `- 상세:` 보유 블록 | `^- 상세:` <sup>b</sup> | 10 | 15 |
> | `- 근거:` 보유 블록 | `^- 근거:` <sup>b</sup> | 2 | 3 |
>
> <sup>a</sup> **제목 줄 포함** — `### ` 줄에만 회수 키가 있는 블록도 보유로 센다. 제외하면 `번호만` 이 14 → 13 으로 갈리고 나머지 두 행은 불변이다.
> <sup>b</sup> **제목 줄 무관** — 술어가 `^- ` 를 요구하므로 `### ` 줄은 구조적으로 매칭될 수 없다.
>
> ⚠️ 마지막 두 행의 합(15 + 3 = 18) ≠ 충족 17. 한 블록이 두 불릿을 **모두** 보유하기 때문이며(중복 1), 충족은 줄이 아니라 **블록 단위**로 센다.
>
> 08-13 열은 [#990](https://github.com/coseo12/astro-simulator/issues/990) 축 D 적용 후 값이다. 회수 키 계열 3행은 D 가 링크를 추가하지 않고 **재배치만** 했으므로 불변이고, 움직인 것은 형식 계열 3행뿐이다.

**재현** — 저장소 루트에서 아래를 그대로 실행하면 위 표의 6개 값이 **단일 패스로 한꺼번에** 나온다 (부분 재측정 금지 — #983). 미충족 블록도 함께 나열되며, 회수 키가 없어 원리적으로 충족 불가한 블록은 따로 표시된다.

```bash
awk '
/^## 실전 교훈/ {r=1; next} r && /^## / {exit} !r {next}
/^### / { n++; T[n]=substr($0,5); D[n]=0; G[n]=0
          K[n] = ($0 ~ /#[0-9]+/ || index($0,"](") || index($0,"http")) ? 1 : 0
          M[n] = ($0 ~ /#[0-9]+/) ? 1 : 0; next }
n { if ($0 ~ /#[0-9]+/ || index($0,"](") || index($0,"http")) K[n]=1
    if ($0 ~ /#[0-9]+/) M[n]=1
    if ($0 ~ /^- 상세:/) D[n]=1
    if ($0 ~ /^- 근거:/) G[n]=1 }
END { for (i=1;i<=n;i++) { key+=K[i]; num+=M[i]; d+=D[i]; g+=G[i]; sat+=(D[i]||G[i])
        if (!D[i] && !G[i]) printf "미충족  %s%s\n", T[i], K[i] ? "" : "   [회수 키 전무 — 원리적 충족 불가]" }
      printf "\n블록 %d | 회수 키 보유 %d | 회수 키 전무 %d | 번호만 %d | L73 충족 %d (상세: %d블록, 근거: %d블록, 중복 %d)\n",
             n, key, n-key, num, sat, d, g, d+g-sat }
' CLAUDE.md
```

경계는 줄 번호가 아니라 **헤더**로 잡고, 종결은 특정 제목이 아니라 **임의의 Level 2 헤더**(`r && /^## /{exit}`)로 한다. 그래서 줄 번호가 밀려도, `## 실전 교훈` 뒤에 **새 섹션이 끼어들거나 종결 섹션이 개명돼도** 깨지지 않는다. 종결자를 고정 문자열(`^## 프로젝트 고유`)에 묶으면 두 경우 모두 **조용히 과다 계수**한다 — 실측: `### ` 2개짜리 섹션 주입 시 `20` → `22`, 종결 섹션 개명 시 종결자가 사라져 EOF 까지 훑어 `20` → `33`. 각주 <sup>a</sup> 의 "제목 줄 제외" 변형은 `/^### /` 블록에서 `K`·`M` 초기값을 `0` 으로 두면 얻으며, **경계 규칙은 위를 그대로 상속**한다.

위 두 값(`22` / `33`)은 아래로 재현한다. 구 술어와 신 술어를 **나란히 출력**하므로 주장 자체가 전시된다:

```bash
old() { awk '/^## 실전 교훈/{r=1;next} /^## 프로젝트 고유/{r=0} r&&/^### /{n++} END{print n+0}'; }
new() { awk '/^## 실전 교훈/{r=1;next} r&&/^## /{exit} r&&/^### /{n++} END{print n+0}'; }

awk '/^## 프로젝트 고유/&&!d{print "## 주입";print"";print"### A";print"";print"### B";print"";d=1}{print}' CLAUDE.md > /tmp/f1.md
sed 's|^## 프로젝트 고유.*|## 개명됨|' CLAUDE.md > /tmp/f2.md
grep -qE '^### B' /tmp/f1.md && grep -qE '^## 개명됨' /tmp/f2.md ||
  echo "⚠️ 픽스처 무발동 — 종결 섹션이 이미 개명된 코퍼스다 (아래 한계 ②)"
echo "주입  구:$(old < /tmp/f1.md)  신:$(new < /tmp/f1.md)"   # 22 / 20
echo "개명  구:$(old < /tmp/f2.md)  신:$(new < /tmp/f2.md)"   # 33 / 20
rm -f /tmp/f1.md /tmp/f2.md
```

> **이것은 가드가 아니라 인용 수치의 재현 명령이다** ([#990](https://github.com/coseo12/astro-simulator/issues/990) PR 리뷰 🟡-1·🟡-2). 한계 둘: ① 위 펜스를 **실행하지 않고 경계 술어를 다시 적으므로**, 펜스가 고정 문자열형으로 되돌려져도 이 출력은 변하지 않는다 — **되돌림 검출률 `0`**. ② 픽스처 앵커가 리터럴 `^## 프로젝트 고유` 라 종결 섹션이 실제로 개명된 뒤에는 무발동이며, 그 경우 위 `grep -q` 단언이 경고한다(무발동인 채 조용히 `20` 을 내는 것만은 막는다).
>
> **상시 가드로 격상하지 않는 판정 근거**: 되돌림을 검출하려면 위 펜스를 **문서에서 위치로 추출**해야 하는데(첫 `bash` 펜스), 그건 방금 제거한 고정 **문자열** 결합과 같은 클래스의 고정 **인덱스** 결합이라 위에 펜스가 하나만 추가돼도 깨진다 — 결함을 옮길 뿐 줄이지 못한다. 게다가 CI 에 배선되지 않은 수동 검증물은 부패한다는 것이 바로 위 §"왜 `scripts/verify-*.mjs` 가 아니라 코드펜스인가" 가 `verify-*` 를 기각한 근거다. 같은 근거를 여기에 적용하면 **상시 가드를 세우지 않는 쪽이 일관**된다. 필요한 것은 상시 강제가 아니라 **인용 수치의 재현 가능성**이고, 그건 위 명령으로 충족된다.

> 섹션 **내부**에 `^## ` 로 시작하는 줄이 있으면 조기 종결하지만, 현 코퍼스에서 그런 줄은 `0` 이다 — 술어는 **고정 문자열 경계**로 잘라낸 뒤 계수한다 (`awk '/^## 실전 교훈/{r=1;next} /^## 프로젝트 고유/{r=0} r' CLAUDE.md | grep -cE '^## '`). 강인화 경계로 자르면 첫 `^## ` 에서 `exit` 하므로 **코퍼스와 무관하게 항상 `0`** 이라 반증 불가능하다 (🟡-4). 이 방향의 오차는 과다가 아니라 **과소** 계수라 조용히 부풀지 않는다.

> **왜 `scripts/verify-*.mjs` 가 아니라 코드펜스인가 (#990 축 C 판정)**: 위 측정에는 **임계가 없다**. 규범 스스로 3/20 을 *"원리적 충족 불가"* 로 선언하므로 (아래 문단) 전칭 PASS/FAIL 선을 그을 수 없고, 임계 없는 `verify-*` 는 가드가 아니라 **리포트 생성기**다. CI 에 배선할 판정이 없으면 그 스크립트는 아무도 실행하지 않는 채 부패하며, 이는 §2.3 이 경계하는 drift 와 같은 클래스다. 반면 코드펜스는 **표와 같은 파일에 있어 표를 고칠 때 같이 눈에 들어오고**, 버전 관리되므로 "일회성 `node -e` 는 산출물이 보존되지 않는다" 는 요구는 그대로 충족한다. 임계가 생기면(예: *"회수 키 보유 블록은 100% 형식 충족"* 을 강제할 때) 그때 §4 의 강제 메커니즘으로 승격한다.

**이 실측이 한정의 근거다** — 회수 키는 이미 **85% 준수**이므로 규범이 비현실적 요구가 아니다. 초판 실측에서 실제 격차는 **불릿 형식**(L73 충족 12/20)이었고, 그래서 형식을 `근거:` 또는 `상세:` 둘 중 하나로 넓혔다. #990 축 D 가 그 격차를 메워 **형식 충족 = 회수 키 보유 = 17** 로 수렴했으므로, 이제 미충족은 **원리적 충족 불가 3건과 정확히 일치한다**. 원리적으로 충족 불가한 **15%**(볼트·이슈 유래가 아예 없는 일반 교훈) 때문에 **전칭 선언을 피한다** — 전칭은 *"선언 즉시 대다수가 위반"* 을 만들어 규약 신뢰를 깎고, 이는 §1.4 가 교체한 취약 논거(*"약한 논거는 미래 다이어트에 반박당한다"*)와 **같은 실패 형태**다.

> **수치 오기록 2회 이력** (PR [#987](https://github.com/coseo12/astro-simulator/pull/987) 2·3차 리뷰): 초판 `36 / 3 / 전무 다수` 는 **범위 술어**가 틀렸고(36 = 문서 전체 `###` 수), 2판 `14 / 6` 은 **보유 술어**가 라벨(`링크·번호`)과 달랐다(실제는 `#N` 한정). **값만 적고 술어를 안 적은 것**이 두 번의 공통 원인이라 위 표에 **술어 열**을 넣었다.

#### 라벨 집합 판정 ([#1047](https://github.com/coseo12/astro-simulator/issues/1047))

착수 시점 두 선언의 라벨 집합은 **base 부터 어긋나 있었다** — 머리말은 `근거:` + `일반화된 설계 지식:`, 위 포맷 블록·술어는 `근거:` + `상세:`. 이슈가 제시한 세 선택지를 **실측으로** 갈랐다. 모집단은 전건 `## 실전 교훈` 절 (`awk '/^## 실전 교훈/{r=1;next} r&&/^## /{exit} r' CLAUDE.md` — §2.1 경계 규칙 상속), rev `38b6c8a`.

| 라벨 | 술어 | 착수 실측 | 판정 |
| --- | --- | --- | --- |
| `- 상세:` | `grep -cE '^- 상세:'` | **15** | **지배 라벨인데 머리말이 선언하지 않았다** → 머리말에 추가 |
| `- 근거:` | `grep -cE '^- 근거:'` | **3** | 양쪽 다 선언 — 불변 |
| `- 일반화된 설계 지식:` | `grep -cE '^- 일반화된 설계 지식:'` | **0** | 머리말이 선언한 형식이 코퍼스에 **0회** |
| `- 일반화:` (미선언 축약형) | `grep -cE '^- 일반화:'` | **1** | 선언 형식으로 정규화 (`1` → `0`) |
| 위 축약형의 **인라인** 사용 | `grep -cE '일반화:'` **−** 위 줄머리 계수 | **1** | `- 상세:` 줄 안에 붙어 있어 줄머리 술어에 안 잡힌다 → 별도 불릿으로 분리 |

> ⚠️ **마지막 두 행을 합쳐 `2` 로 적지 않는다** (PR [#1070](https://github.com/coseo12/astro-simulator/pull/1070) 리뷰 🔴-2). 초판 표는 축약형을 **`2`** 로 적었는데 그 값은 **줄머리 1 + 인라인 1 의 합**이라 표가 선언한 줄머리 술어로 재측정하면 **`1`** 이 나온다. 위 §수치 오기록 2회 이력 이 _"값만 적고 술어를 안 적은 것이 두 번의 공통 원인"_ 이라 적고 **술어 열**을 넣은 바로 그 절에서, 술어를 적고도 **다른 술어의 산출**을 넣은 자기 위반이다. 행을 갈라 각 행이 자기 술어의 산출만 담게 한다.

1. **머리말 → 포맷 블록으로 맞춘다 (채택)** — `상세:` 누락은 역할 차이로 정당화되지 않는다. 실측 `15` 대 `3` 으로 **지배 라벨이 선언에서 빠져** 있었고, 머리말만 읽은 에이전트는 회수 포인터를 `근거:` 로만 쓴다.
2. **술어를 `(근거|상세|일반화된 설계 지식)` 로 넓힌다 (기각)** — 이슈 본문은 *"그러면 충족 수가 바뀐다 — 재측정 필요"* 로 적었으나 **실측이 이를 반박한다**. 해당 라벨의 줄머리 hit 이 **`0`** 이라 술어를 넓혀도 위 표 6개 값이 **전건 불변**이고 (정규화 후 `2` 가 생기지만 그 블록은 이미 `- 상세:` 보유라 **블록 단위 충족은 불변**), 얻는 것 없이 술어 역할만 흐려진다.
3. **역할이 다르다고 명시한다 (부분 채택)** — 술어 확장을 기각하는 근거가 곧 역할 분리다. 머리말은 **작성 순서** 규범이고 §2.1 술어는 **회수 키 형식 충족 계수** 규범이다. 승격 포인터(`일반화된 설계 지식:`)는 블록의 **유래**가 아니라 **파생처**를 가리키므로 회수 키가 아니고, 따라서 계수 대상 밖이다. 이 문장을 CLAUDE.md 머리말에도 박제했다.

즉 **정본은 라벨 집합이 아니라 역할**이다 — 회수 포인터 2종(`근거:` / `상세:`)은 양쪽이 공유하고, 승격 포인터는 머리말 전용이다. 머리말의 나머지 컨벤션(내용 불릿 → 회수 포인터 불릿 → 선택적 승격 포인터)은 위 포맷 블록과 동일하다.

### 2.3 중복 금지 (선행 검사 — #962)

§2 추출 기준은 "새 블록의 **크기**" 만 본다. 그보다 먼저 **이미 있는지** 를 본다.

> CLAUDE.md 에 새 블록을 쓰기 전, 동일 주제를 다루는 `docs/guides|lessons|ops` 파일이 있는지 `grep` 한다.

- **있다** → 상세는 그 파일이 SSoT. CLAUDE.md 에는 **규칙 1~3줄 + 포인터** 만. (판정 종료 — §1.3 판정 질문 불필요)
- **없다** → §1.3 판정 질문으로.

0단계를 §1.3 앞에 두는 이유: 행동 판정부터 시작하면 "이건 행동 규칙이니 인라인" 이라는 결론이 나기 쉽고, **같은 규칙이 이미 `docs/` 에 있다는 사실은 검사되지 않는다**.

**실측 근거 (#962)**: 2026-08-05 감축분의 **100% 가 중복** 이었다. `branch-strategy-workflow.md` / `release-process.md` / `cross-validate-protocol.md` / `sprint-contract-roi.md` / `dead-wait-guard.md` 가 이미 verbatim superset 을 보유한 채 CLAUDE.md 가 전문을 중복 존치했고, 두 guide 는 자기 헤더에 잔여 형태("CLAUDE.md 본문은 표 + 1줄 포인터만 유지")까지 선언해 둔 상태였다. 즉 가지치기는 이미 결정(#266 / PR #287)됐고 **CLAUDE.md 쪽 집행만 누락**된 drift 였다. 크기 기준만으로는 이 클래스가 걸러지지 않는다.

**재증식 실측 (#962)**: #907 Phase C 직후 33,956 → 5일 뒤 34,980 (**+1,024**). 증가분의 96% 가 규약 1건(#915 qa 게이트 예외, 985 chars). 재증식은 야금야금이 아니라 **규약 1건 = 1,000자** 단위로 발생한다 — 따라서 "1,000자 여유" 는 다음 규약 1건에 즉시 소진되는 양이며, 감축 목표는 그보다 크게 잡아야 한다.

#### 3.1.1 재조정 이력

재조정은 본 절의 절차대로 집행하고 **여기에 1행 추가**한다. 별도 ADR 은 두지 않는다 — 결정("임계는 재조정 가능하며 절차는 §3.1")은 이미 본 가이드에 기록돼 있고, 재조정 PR 은 그 결정의 **집행**이지 새 결정이 아니다.

| 일자 | 변경 | 근거 | 재검토 조건 |
|---|---|---|---|
| 2026-04-25 (도입) | 35k / 40k / 45k | Claude Code 내부 경고(40k) + 당시 실측(42.6k) — §3.1 본문 | 아래 행으로 대체 |
| 2026-08-08 | 경계 경보 **35k → 33k** (40k / 45k 불변) | **재증식 단위 실측** — #907 Phase C 직후 33,956 → 5일 뒤 34,980(**+1,024**)이고 증가분의 96%가 규약 1건(#915, 985 chars). 재증식은 야금야금이 아니라 **"규약 1건 ≈ 1,000자"** 단위다 (§2.3 재증식 실측). 축 A 감축 착지 후 본 PR 반영 시점 **23,374** 기준으로 35k 까지 여유가 **11,626**(≈ 규약 11건분)이라, 경보가 *"다음 1건"* 이 아니라 *"이미 열 몇 건 쌓인 뒤"* 에 울린다. 33k 는 여유 **9,626**(≈ 9건분) ([#980](https://github.com/coseo12/astro-simulator/issues/980) 축 B) | (a) 경계 경보가 **상시 발화**해 무뎌지면 → 재상향이 아니라 **감축 PR** 로 대응 (§5). (b) 감축으로 여유가 다시 **10건분(≈10,000)을 초과**하면 → 재하향 검토 |

> **왜 "여유를 0에 붙이지" 않는가**: 경보 임계는 *감축 목표*가 아니라 *검토 트리거*다. 여유를 규약 1~2건분까지 조이면 정당한 신규 규약 1건마다 경보가 울려 **alert fatigue** 로 무력화된다 (선례: [#779](https://github.com/coseo12/astro-simulator/issues/779) CI alert fatigue). 반대로 여유가 10건분을 넘으면 경보가 실질적으로 사후 통지가 된다. **약 9건분**은 그 사이의 실용적 지점이다.

> ⚠️ **임계는 행동 규칙을 축출하지 않는다** ([#980](https://github.com/coseo12/astro-simulator/issues/980) 축 A 전례): 예산이 빠듯하면 **서사를 더 옮기지 행동 규칙(특히 "사용자에게 보고/확인" 류)을 자르지 않는다.** 축 A 1차 이관은 자기 부과 임계(`≤23,000`)를 맞추려다 인간-루프 의무를 원본 8회 → 1회로 강등시켜 *"탐지 100% / 대응 0%"* 상태를 만들었고, 해법은 감축이 아니라 **임계 완화**였다. 상세: [`docs/ops/zombie-process-guards.md`](../ops/zombie-process-guards.md) §잔여 계약의 근거.

### 3.2 char 카운트 방법

Node 기반 구현 (`scripts/verify-claudemd-size.mjs`) 이 `[...str].length` 로 **Unicode code point 단위** 측정. locale 독립 (#203).

```bash
# 공식 게이트 실행 — locale 영향 없음
node scripts/verify-claudemd-size.mjs
# 가드 자체 회귀 검사 (CI project-guards 가 본검사 직전 실행)
node scripts/verify-claudemd-size.mjs --self-test
```

> **이전 shell 구현의 한계 (#203 해소)**: `LC_ALL=en_US.UTF-8 wc -m` 은 self-hosted runner 에서 해당 locale 미설치 시 POSIX 로 폴백 → 바이트 수 (한글 62% 부풀림, 실측: 70,500 vs 실제 43,305) 오탐 유발. Node 포트로 완전 해소.

## 4. 강제 메커니즘

### 4.1 `scripts/verify-claudemd-size.mjs`
- CI `project-guards` workflow 에서 실행 (self-test + 본검사 — #905 fail-fast 복구, #907 이설)
- 33k 이상: stdout 경보만 (exit 0)
- 40k 이상: stdout warn (exit 0)
- 45k 이상: stderr fail + exit 1

> **문구 계약 — 산문 전수 (#988 → [#1051](https://github.com/coseo12/astro-simulator/issues/1051))**: 세 판정이 전부 `count >= 임계` 라 게이트를 서술하는 산문은 **`이상`** 이다. #980 축 B 가 본 절 3줄을, #988 이 스크립트 stdout 3개를 고쳤으나 **같은 파일 안에 `초과` 가 남아 자기모순**이었다. 전수 술어 `git grep -nF '초과' -- docs/guides/claudemd-governance.md` 의 **6 hit** 을 전건 분류해 **4건을 정정**했다 — §4.4 체크박스 (`40k`) / §5.3 헤더 (`45k`) / §6.1 (§2 추출 기준도 임계가 전부 `이상`) / §6.2 ADR 템플릿의 `<X>k chars`. 나머지 **2건은 게이트가 아닌 진짜 강부등호라 존치**한다: §3.1.1 재검토 조건 (_"여유가 다시 10건분을 초과하면"_ — 재하향 검토 트리거) / §9 (_"본 가이드 자체가 500 lines 초과 시"_ — 본 가이드 길이). **정정 후 재현** — 같은 명령의 매칭 줄은 `6` → **`4`** 다 (`6 − 정정 4 + 자기 매칭 2`). 내역: **존치 2건** (§3.1.1 · §9) + **자기 매칭 2건** (본 각주와 바로 아래 §6.2 각주 — 둘 다 존치·정정 사유로 원문을 인용한다). 즉 **게이트·기준을 서술하는 `초과` 는 `0`** 이다 — 잔존 hit 을 술어 없이 세면 _"아직 4건 남았다"_ 로 오독되므로 자기 매칭을 함께 적는다.
>
> ⚠️ **이 값 자체가 부분 재측정으로 한 번 틀렸다** (PR [#1070](https://github.com/coseo12/astro-simulator/pull/1070) 리뷰 🔴-R2). 라운드 2 가 §6.2 를 정정해 hit 하나를 없애면서 **동시에 그 낱말을 인용하는 각주(아래 §6.2 각주)를 신설**했는데, 갱신할 때 **없앤 쪽만 반영해 `4 − 1 = 3`** 으로 적었다. 실제는 `4 − 1 + 1 = 4` 다. [ADR `20260808-983`](../decisions/20260808-983-measurement-recording-convention.md) §(i) 확장 _"부분 재측정 금지 — 값 하나가 바뀌면 전체를 다시 재고 전체를 갈아끼운다"_ 의 위반이며, 그 ADR 의 **오기록 4 와 동형**이다.
>
> 그래서 이 각주는 **본문에 그 낱말을 리터럴로 쓰지 않는다** — 자기 매칭을 하나 더 늘려 값을 또 흔들기 때문이다. 자기 참조 계수에서는 **측정 대상 토큰을 인용하지 않는 것**이 값을 안정시키는 가장 싼 방법이고, 인용이 불가피하면 **모든 인용을 센 뒤 최종값 한 번**으로 적는다.
>
> ⚠️ **이 각주의 부수 사실도 한 번 틀렸다** (리뷰 🔴-R3). 초판은 위 신설 각주가 그 낱말을 _"세 번"_ 인용한다고 적었으나 **실측은 한 번**이고, 다섯 번은 **바로 위 문구 계약 각주**의 값이었다 — 두 각주를 혼동했다. 산식(`4 − 1 + 1 = 4`)은 **줄 수** 기준이라 영향이 없고 결론도 불변이지만, **서술에 쓴 수는 그 자리에서 세야 한다**는 본 절의 요구를 각주 자신이 어겼다. 계수 서술을 담은 문장은 **줄 단위인지 occurrence 단위인지**를 먼저 고정하고 쓴다.

> §6.2 는 초판에서 _"작성자가 값을 채우는 자리표시자"_ 라는 이유로 존치했다가 **정정으로 뒤집었다** (PR [#1070](https://github.com/coseo12/astro-simulator/pull/1070) 리뷰 🟡-4). 자리표시자인 것은 **`<X>` 값이지 부등호 방향이 아니고**, 그 지표는 다름 아닌 `verify-claudemd-size.mjs` 가 `>=` 로 게이팅하는 **CLAUDE.md size** 다. 템플릿은 **복사돼 증식**하므로 존치하면 예외 ADR 마다 `초과` 를 재생산한다 — #980 → #988 → #1051 로 이어진 잔여의 **다음 발생원**이 된다. 반면 §3.1.1·§9 는 대상 지표에 `>=` 구현이 아예 없어 존치가 옳다.

### 4.2 각인 예산 보고 (로컬 수동 확인)
- `node scripts/verify-claudemd-size.mjs` 직접 실행으로 현재 CLAUDE.md char 수 + 게이트 판정 확인
- 예: `[PASS] CLAUDE.md 23,374 chars — 예산 33,000 이내.`

### 4.3 `scripts/verify-docs-links.sh` (Gemini 제안 2 — 링크 무결성)
- CLAUDE.md → `docs/` 링크 전수 추출 후 `test -f` 로 파일 존재 확인
- 깨진 링크 발견 시 exit 1 + 누락 경로 stderr 보고
- 추출이 늘어날수록 link rot 위험 증가 — 본 스크립트로 구조적 방어

### 4.4 PR 템플릿 체크박스
CLAUDE.md 또는 `docs/` 를 수정하는 PR 에서:

## 5. 기존 블록 가지치기 프로토콜 (Gemini 제안 1 + 7)

신규 추가 기준만 있으면 시스템 불완전. **기존 규칙 재평가**가 대칭적으로 필요.

### 5.1 40k 진입 시 (PR warn 단계)
- `awk` 로 섹션별 bytes 재측정:

```bash
awk '/^## /{if(name)print chars"\t"lines"\t"name; name=$0; chars=0; lines=0; next} {chars+=length($0)+1; lines++} END{if(name)print chars"\t"lines"\t"name}' CLAUDE.md | sort -rn | head
```

- 상위 섹션 중 **6개월 미수정 + 참조 빈도 낮은 블록** 우선 추출 후보
- 다음 신규 블록 추가 전에 1건 이상 추출 목표

### 5.2 45k 접근 시 (CI fail 직전)
**새 규칙 추가 전 "무엇을 옮길지" 먼저 논의**한다. 대응은 "규칙을 어기는 것"이 아니라 **"새 규칙을 위한 공간 확보"**.

### 5.3 45k 이상일 때 (CI fail)
- 감축 PR 을 먼저 머지 후 새 규칙 PR 재개
- 감축 PR 은 **PATCH** 릴리스 (행동 변화 없는 문서 리팩토링 — 본문은 포인터 1줄로, 상세는 `docs/lessons/*` 등으로 이동)

### 5.4 가지치기 대상 선정 질문
1. 이 블록을 읽지 않아도 현재 에이전트 행동이 올바른가? (→ 참조층으로)
2. 이 블록의 근거 이슈가 마지막 참조된 지 6개월 이상인가? (→ 추출 후보)
3. 이 블록의 매트릭스/JSON 이 5줄 이상인가? (→ 추출 기준 2.1 재적용)

## 6. 예외 ADR 박제 (CODEOWNERS 대체안, Gemini 제안 6)

1인 개발자 환경에서 CODEOWNERS 승인 장치는 비현실. 대신 **ADR 박제** 로 프로세스 비용 + 영구성을 확보한다.

### 6.1 언제 예외 ADR 을 쓰는가
- 신규 블록이 추출 기준 중 하나라도 해당하나 (§2 — 임계는 전부 `이상`), 세션 각인 없이는 **즉각적인 잘못된 행동**을 유발
- 예: "체크리스트 5행" 이라 추출 대상이나, 체크리스트 자체가 CRITICAL 판정에 쓰여 docs/ 로 가면 어텐션 미도달

### 6.2 ADR 템플릿
파일명: `docs/decisions/<YYYYMMDD>-claudemd-exception-<topic>.md`

```markdown
---
title: CLAUDE.md 각인 예외 박제 — <topic>
date: <YYYY-MM-DD>
status: accepted
---

## 배경
- 대상 블록: CLAUDE.md `### <섹션>`
- 추출 기준 위반: 매트릭스 N 행 / 코드 N 라인 / 프로토콜 N 스텝 중 <해당>
- 현재 CLAUDE.md size: <X>k chars

## 대체 불가 근거
- 각인 없이는 어떤 잘못된 행동이 발생하는가 (구체 시나리오)
- `docs/` 포인터 1줄로 대체했을 때 실패한 실측 또는 예상 경로

## 결정
- 본 블록을 CLAUDE.md 에 인라인 유지
- 대신 <어떤 대체 조치> 로 비대화 영향을 상쇄 (예: 다른 블록 1개 추출)

## 재검토 조건
- <YYYY-MM-DD> 시점 재평가 (최대 6개월)
- 또는 CLAUDE.md size 가 <X>k chars 이상일 때 즉시 재평가
- 재평가 트리거: <조건>
```

### 6.3 금지
- 예외 ADR 없이 "사유 주석만 달고 넘어가기" 금지
- 재검토 조건 없는 ADR 금지 (`status: accepted` 는 반드시 재검토 일자 동반)

## 7. SSoT 결합 박제 (Gemini 제안 5 격상)

CLAUDE.md 본문 감축 시 **에이전트/스크립트 참조 결합**이 깨질 수 있다. 감축 PR 체크리스트로 구조화.

### 7.1 현재 확인된 결합
- `.claude/agents/*.md` (5개 파일) — 공통 JSON 스키마 SSoT 9개 필드 포함
- `scripts/verify-agent-ssot.sh` 주석 — "SSoT 선언 위치: CLAUDE.md `### sub-agent 검증 완료...`" 참조
- 일부 에이전트 파일이 CLAUDE.md 특정 섹션 앵커를 링크로 참조할 가능성

### 7.2 감축 PR 사전 조사 (리서치 phase)
감축 대상 블록을 선정하기 **전에** 참조 depth 전수 조사. 명령은 [`.claude/agents/reviewer.md`](../../.claude/agents/reviewer.md) §절차 4 (Grep) **정본**을 따른다 — 고정 문자열(`-F`) / 표기 변형 / **경로 무제한**:

```bash
# CLAUDE.md 섹션 앵커를 참조하는 파일 전수 검색
# 예: "### sub-agent 검증 완료 ≠ GitHub 박제 완료" 를 추출 대상으로 삼을 때
git grep -nFi -e 'sub-agent 검증 완료' -e 'sub-agent-검증-완료'
```

- **경로를 좁히지 않는다.** 구 문언은 `.claude/ scripts/ docs/` 로 제한돼 있었는데, 그러면 `.github/` 가 통째로 빠진다 — **그리고 감축이 끊을 참조가 정확히 거기에 있다**. 이 앵커는 `.github/PULL_REQUEST_TEMPLATE.md` 와 `.github/workflows/project-guards.yml` 이 참조한다. `--include` 확장자 제한도 같은 함정이다.
- **표기 변형** — 산문·헤더 표기(`sub-agent 검증 완료`)와 마크다운 앵커 slug(`sub-agent-검증-완료`)는 갈린다. `](CLAUDE.md#sub-agent-검증-완료--github-박제-완료)` 형태의 링크는 앞 변형만으로는 잡히지 않는다. 이는 **섹션 앵커의 최소 집합**이지 닫힌 열거가 아니다.
- **제외는 검색 시점이 아니라 분류 시점에** — 전 hit 을 §절차 4 의 5분류(활성 선언 / 이력 기록 / 무관 / 역참조 회귀 가드 / 규약 본문 자체)로 나눈 뒤 감축 대상을 정한다. 검색 단계에서 좁히면 그 판단 자체가 불가능해진다.

> **자기 적용 실증** (#995). 술어 = 매치 파일 수 / hit 줄 수, rev `2f64d76` = 본 절 개정 직전 develop head.
> 구 명령 (`grep -rn` + 경로 `.claude/ scripts/ docs/`) **15 files / 21 hits**, `.github/` **0 files**.
> 정본 (`git grep -nFi` 2변형 + 경로 무제한) **19 files / 25 hits**, `.github/` **2 files**.
> 차분 **4 files** — `.github/PULL_REQUEST_TEMPLATE.md` / `.github/workflows/project-guards.yml` / `CHANGELOG.md` / `CLAUDE.md`.
> 즉 구 명령을 믿고 감축했으면 **`.github/` 참조 2건을 끊은 채 _"전수 조사 완료"_ 를 선언**하게 된다. 본 절이 명령 리터럴을 포함해 head 계수는 **자기 참조**이므로 고정 수치를 박제하지 않고, 위 명령을 rev 와 함께 재실행해 확인한다.
