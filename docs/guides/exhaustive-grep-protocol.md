# 전수 grep 규약 — 절차 상세와 자기 적용 실증 이력

> 본 문서의 축은 **_"검사 방법이 결론을 지지하는가"_** 다. grep 그물 설계와 정규식 사각은 같은 축이므로 §4 (주석 전용 변경 증명) 도 여기에 함께 둔다 — 둘 다 _"결과가 맞은 것이지 방법이 맞은 게 아닌"_ 클래스다.

**정본은 [`.claude/agents/reviewer.md`](../../.claude/agents/reviewer.md) §절차 4 `(Grep)` 이다.** 명령 형태·5항 절차·5분류 계급은 거기가 SSoT 이고, 본 문서는 그 **절차 상세 / 실측 전례 / 자기 적용 실증 이력**을 담는다. 수치는 전부 [`20260808-983-measurement-recording-convention.md`](../decisions/20260808-983-measurement-recording-convention.md) §수치 박제 규약 (iv) 에 따라 **술어를 병기**한다.

## 1. 자기 적용 실증 이력

### 1.1 #989 — 규약화 시점 (`reviewer.md` §4 에서 이관, verbatim)

아래 blockquote 는 `reviewer.md` 57–61행(rev `b9c273a`)에서 **본문 바이트 그대로** 옮긴 것이다 (술어: 리스트 중첩용 선행 5칸 들여쓰기만 제거 후 `cmp` — IDENTICAL). 규약이 아니라 **그 시점의 측정 기록**이므로 §3.1 표의 **이력 기록** 계급이고, 정본이 바뀌어도 갱신하지 않는다.

> **자기 적용 실증** (#989, `dddeb4811` = #987 이 _"25/25 PASS / 모든 위치 정합"_ 을 선언한 시점). 술어 = grep hit 줄 수 / 매치 파일 수.
> 구 규약 (경로 제한 + `-E` 4변형 = 개정 5종 − `35 k`, `-i` 없음) **10 hits / 5 files**, `.github/` **0** — 단 이는 **당시 실행 경로 기준**이다. 구 문언은 *"저장소 전체 검색"* 을 2회 명시했으므로 **좁은 경로를 강제하지 않았고**, 같은 `-E` 로도 **경로만 풀면 `.github/`=1** (18 hits / 7 files) 로 7번째 지점이 잡힌다.
> **축 2 가 진짜 "구조적 0" 이다** — `무제한 + -E \b` = **0 hits / 0 files** (술어: 경로 무제한, `\b` 4변형). 즉 구 문언의 결함은 *"경로 제한"* 이 아니라 **자기모순적 모호성**이고, 1항이 그 처방이다.
> 개정판 (`-Fi` + 무제한 + 5종) **28 hits / 13 files**, `.github/` **1** = 7번째 지점 검출.
> 3분류: 활성 선언 **1** / 이력 기록 **16** / 무관 **11** (합 28). 활성 1건이 곧 차단 사유였다.

### 1.2 #995 — 첫 적용

[`claudemd-governance.md`](claudemd-governance.md) §7.2 말미의 자기 적용 실증 blockquote (rev 앵커 `2f64d76`). 사본을 만들지 않고 그 자리를 정본으로 둔다 — 같은 측정 기록이 두 곳에 있으면 그 자체가 drift 원이다.

### 1.3 #999 — 낱말 그물이 주장 문장을 통과시킨다

`reviewer.md` §4 3항 **서술 변형 축**의 근거 실측. 술어 = `grep -c -Fi`, 대상 = `git show b26994d:.github/workflows/auto-close-issues.yml` **14–17행 한정** (재현 명령 아래).

| 술어 (14–17행 한정) | hit 줄 수 |
| --- | --- |
| 낱말 11변형 union — `auto-close` / `auto close` / `autoclose` / `auto_close` / `수동 close` / `gh issue close` / `closes` + `#` / `closing keyword` / `close 키워드` / `자동 close` / `--reason completed` | **0** |
| 동작 서술 술어 5종 — `실발동` / `미발동` / `발동하지 않` / `동형` / `구조적으로 불가` | **2** (14행 · 16행) |

```bash
git show b26994d:.github/workflows/auto-close-issues.yml | sed -n '14,17p' \
  | grep -c -Fi -e '실발동' -e '미발동' -e '발동하지 않' -e '동형' -e '구조적으로 불가'
```

14–17행은 **본 workflow 를 도입하는 PR 자신의 머지에서는 실발동이 구조적으로 불가**하다고 주장했고, 그 주장은 workflow run 이력 실측으로 반증됐다 (#999 라운드 1). 파일 자체는 3·5·7·8행 때문에 11변형 hit 목록에는 올랐지만, **줄 단위로 분류하는 reviewer 에게 14–17행은 보이지 않았다** — 파일 단위 hit 은 줄 단위 검토를 보장하지 않는다 (§5 규칙 (나) 와 같은 뿌리).

**#999 의 5분류 수치는 소급 정정하지 않는다.** 그 시점의 분류 사실이고, 소급 편집은 본 규약이 금지하는 기록 위조다. §5 의 재분석은 개정판 정의의 **예시**로만 쓴다.

## 2. 0 hit 은 결과가 아니라 신호다 — 가정 벗기기

정본은 **넓게 훑어 N hit → 5분류로 실잔존 0** 이지 **좁게 훑어 0 hit** 이 아니다. 0 hit 에는 **분류할 대상이 없어서** _"모집단이 깨끗해서 0"_ 과 _"그물이 좁아서 0"_ 이 구분되지 않는다. §4 4항이 _"이 분류를 거쳐야 실잔존 0 이 검증 가능한 주장이 된다"_ 고 못박은 전제를, 0 hit 은 원리적으로 충족할 수 없다.

**가정 벗기기 절차** — 0 hit 을 얻으면 결론으로 삼지 말고, 술어에 들어간 가정을 **하나씩** 빼고 재실행한다.

1. **인용부호** — 패턴에 `'` `"` 를 포함시켰는가 (실제 문서는 백틱·강조로 감쌌을 수 있다)
2. **공백** — `35 k` / `auto close` 처럼 구분자가 들어간 표기
3. **대소문자** — `-i` 누락
4. **이스케이프** — `\b` `\|` 등이 `-F` 에서는 **리터럴**이고 `-E` 에서는 침묵 실패한다 (§4 1항)
5. **경계 축소** — 가장 짧은 안정 부분 문자열까지 줄여 본다

**실측 전례** (술어 = hit 줄 수 / 매치 파일 수, rev `b9c273a`, 경로 무제한):

| 술어 | hit |
| --- | --- |
| 인용부호 가정 포함 2변형 (`git grep -nF -e "'^\| 2026-" -e '"^\| 2026-'`) | **0 hits / 0 files** |
| 인용부호 가정 제거 1변형 (`git grep -nF -e '^\| 2026-'`) | **1 hit / 1 file** (`CHANGELOG.md`) |

#997 라운드 2 는 위 0 hit 으로 _"잔여 0"_ 을 선언했다. **결론은 맞았다** (드러난 1 hit 은 CHANGELOG 의 이력 기록이라 보존 대상). 그러나 **방법이 그 결론을 지지하지 않았다** — 0 hit 은 그물이 좁아서 나온 것이었고, 잔여가 활성 선언이었더라도 같은 0 이 나왔을 것이다.

넓은 sweep 이 hit 을 내는 것이 **정상**이고, `-F` 과매칭은 **비용이지 결함이 아니다** — 분류 단계(§4 4항)에서 걸러진다.

## 3. 리포 외부 매체 — 조건부 확장 sweep

`git grep` 의 모집단은 **tracked 파일**이다. `--untracked` 는 작업 트리의 미staged 신규 파일까지 넓히지만, **PR·이슈·리뷰 코멘트 본문은 애초에 작업 트리 밖**이라 어떤 플래그로도 나오지 않는다. §4 2항의 _파일 상태 축_ 경고와 뿌리는 같고 처방이 다르다.

이 리포는 지시문·규약·수치를 PR 본문과 이슈에 상시 박제하는 관행이라 (#997 BLOCK-A 모집단 3 중 1건이 PR 본문이었다) 그 매체가 사각이면 _"전수"_ 선언이 구조적으로 불완전해진다.

### 3.1 선언 문언 제약 (상시 · 비용 0)

외부 매체를 훑지 않았으면 _"실잔존 0"_ 이 아니라 다음과 같이 적는다.

> **tracked 파일 기준 실잔존 0** (술어: `git grep` 모집단 — PR·이슈·코멘트 본문 제외)

이것이 1차 방어다. §수치 박제 규약 (iv) **술어 명시 의무**의 직접 적용이고, _"전수"_ 과대선언을 구조적으로 차단하면서 **비용이 0** 이다.

### 3.2 조건부 확장 sweep (트리거 명시)

아래 **두 조건을 모두** 만족할 때만 외부 매체를 병행한다.

1. 정정 대상이 **지시문 · 규약 · 수치**이고 (코드 상수·식별자는 해당 없음)
2. 그 값이 PR·이슈 본문에 박제된 이력이 있다

모집단은 **링크 그래프상 유한 집합**으로 한정한다 — 그 값을 **도입·개정한 PR/이슈 + 본 PR** 뿐이다.

```bash
gh pr view <N> --json body --jq .body | grep -nFi -e '<변형1>' -e '<변형2>'
gh issue view <N> --json body --jq .body | grep -nFi -e '<변형1>' -e '<변형2>'
```

**전 PR sweep 은 비-정본이다.** 머지된 PR 만 579건 (술어: `search/issues is:pr is:merged` total_count, 2026-08-09 실측, #999 박제) 이라 매 리뷰마다 수행할 수 없고, **지켜지지 않는 규약은 규약이 아니다.**

> 관련 후속 후보 (본 문서 범위 밖): _"규약·수치를 **선언**하는 문언은 PR 본문 단독 박제 금지"_ 규범. CLAUDE.md §스프린트 계약 7항 (세 위치 동시 박제) 의 확장이고, 관행 변경이라 별도 계약이 필요하다.

## 4. 주석 전용 변경 주장의 증명 정본

PR 이 _"주석만 바뀌었다 → 런타임 표면 변화 0"_ 을 주장할 때의 검증 절차. **주장하는 쪽이 아니라 검증하는 쪽(reviewer)의 규약**이다.

### 4.1 금지 — 정규식 단독 판정

```bash
# ❌ 단독 판정 금지
grep -vE '^\s*(//|\*|/\*)' <file> > stripped && cmp stripped_before stripped_after
```

`^\s*\*` 는 `  * b;` 같은 **곱셈 연속행**을 주석으로 오인해 제거한다. #997 은 이 방법으로 통과했지만 해당 패턴이 diff 에 없었을 뿐이고, **결과가 맞은 것이지 방법이 맞은 게 아니다** (§2 와 같은 클래스). 보조 지표로 쓰는 것은 무방하나, 그때는 stripped 라인을 전수 감사한 사실을 함께 박제한다.

### 4.2 정본 — 컴파일러 emit 대조

```bash
tsc --removeComments --noResolve --skipLibCheck --target esnext --module esnext <files>
# before / after 산출 JS 를 cmp → IDENTICAL 이어야 한다
```

컴파일러가 주석 경계를 판정하므로 **정규식 사각이 없고**, _"런타임 표면 변화 0"_ 을 **emit 바이트 동일**로 직접 주장한다. #997 실측: `asteroid-belt.js` 122줄 / `tier-proportion.test.js` 76줄 모두 **IDENTICAL** (술어: 산출 JS 바이트 `cmp`).

### 4.3 병행 — 시맨틱 주석 패턴 0건

주석이 **컴파일·번들 의미를 갖는** 경우가 있으므로 emit 대조와 함께 확인한다. diff 의 `+` 라인 전수에 아래 패턴을 건다.

`@ts-ignore` / `@ts-expect-error` / `@ts-nocheck` / `/// <reference` / `webpackChunkName` / `eslint-disable` / `prettier-ignore` / `c8|istanbul|v8 ignore` / `@jsx` / `@vitest-environment` / `use client` / `use server`

- **토큰 12** (술어: 위 목록의 `/` 구분 항목 수)
- **grep 대안 14** (술어: `|` 대안을 전개한 수 — `c8|istanbul|v8 ignore` 가 3 대안)
- ⚠️ 원 출처 (PR #997 qa 코멘트) 는 이를 _"13 패턴"_ 이라 적었으나 **어느 계수 규칙으로도 13 이 재현되지 않는다.** 인용할 때 _"13"_ 을 옮기지 말고 위 두 술어 중 하나를 명시한다 — 열거를 그대로 두고 개수만 술어와 함께 적는 것이 §수치 박제 규약 (iv) 준수다.
- 이 목록은 **출발점이지 닫힌 열거가 아니다** (§4 3항의 _"최소 집합"_ 논리와 동일). 새 번들러·러너 지시자가 생기면 추가한다.

## 5. 분류 오분류 사례 — 규칙 (가)(나) 의 근거

`reviewer.md` §4 4항의 5계급은 **개수가 5로 고정**돼 있다. #995·#999 의 오분류는 계급 부족이 아니라 **정의 오적용**이었고, 아래 두 사례가 그 실측 근거다.

### 5.1 규칙 (가) — 위치가 아니라 기능으로 판정한다

#995 는 [`claudemd-governance.md`](claudemd-governance.md) §7.2 의 자기 적용 실증 blockquote 를 **규약 본문 자체**로 분류했다. 그 blockquote 가 **규약 절 안에 있다**는 위치가 근거였다.

- **귀결은 같다** — 두 계급 모두 정정 대상이 아니다.
- **수명이 다르다** — 규약 본문 자체는 **정본이 바뀌면 함께 갱신**되고, 이력 기록은 **보존**된다. 섞으면 후자가 갱신 대상으로 오인된다.
- 그 blockquote 는 rev 앵커 (`2f64d76`) 가 붙은 **시점 측정 기록**이고, 구 명령을 **반례로** 인용한다. 개정판 정의의 _"구 값·구 명령의 before·반례 인용"_ 에 문언 그대로 해당하므로 **이력 기록**이다.

→ **제6계급을 만들 필요가 없다.** 필요했던 것은 _"위치가 아니라 기능으로 판정한다"_ 는 적용 규칙이다.

### 5.2 규칙 (나) — 한 블록의 hit 을 한 계급으로 뭉쳐 세지 않는다

#999 는 _"규약 본문 자체 **11**"_ 로 분류했다 (술어: #999 CHANGELOG entry 의 5분류 표, 합 96 정합). CHANGELOG 자신의 내역은 `5 에이전트 SSoT 9 필드 스키마 10 + 스키마 원본 1` 이다. 개정판 정의로 다시 읽으면 그 **10** 이 갈린다.

| 재분류 (개정판 정의 적용) | 계급 | 근거 |
| --- | --- | --- |
| 스키마 리터럴 5 (`"auto_close_issue_states": {}`) | **활성 선언 — 정합** | auto-close 규약을 예시로 서술하는 게 아니라 **이름이 겹친 식별자**다. `scripts/verify-agent-ssot.sh` 가 존재를 강제하는 **살아있는 계약** |
| 필드 설명 산문 5 | **활성 선언** | _"정본 명령이 예시로 그 값을 포함한다"_ 에 해당하지 않는다. **지금 행동을 지시**하는 문장이다 |
| `docs/lessons/sub-agent-ssot-handoff.md` 1 | **규약 본문 자체** | 유일하게 정의에 문언상 부합 |

산문 5 중 2건 (`developer.md` · `qa.md` 의 _"PR 본문/커밋 메시지"_) 이 **stale 이었는데 스키마로 묶여 검토에서 빠졌고**, 리뷰가 별도 경로로 잡았다. 즉 **현행 정의는 이미 셋을 갈라놓고 있었고, 적용이 파일·블록 단위로 뭉쳐진 것**이다. 계급을 하나 더 만들어도 같은 뭉치기는 재발한다.

→ **hit 은 줄 단위로 센다.** 스키마 리터럴과 그것을 설명하는 산문은 별개 hit 이고, 같은 파일 안에서도 계급이 갈린다.

### 5.3 계급 증설 압력에 대한 답

새 hit 이 어느 계급에도 안 맞아 보이면, **계급 신설 전에 §4 4항 결정 절차를 순서대로 다시 밟는다.** 계급 추가 비용은 두 가지다.

1. **열거 사본 동기화** — 5계급 명칭은 [`claudemd-governance.md`](claudemd-governance.md) §7.2 와 [`packages/core/src/scene/tier-proportion.test.ts`](../../packages/core/src/scene/tier-proportion.test.ts) 주석에 열거돼 있다. 술어: `git grep -lF '역참조 회귀 가드'` rev `b9c273a` **4 files** = 정본 1 (`reviewer.md`) + **갱신 대상 열거 사본 2** + 이력 기록 1 (`CHANGELOG.md` — 보존 대상이라 갱신 비용에 들어가지 않는다). 명칭·개수를 유지하면 동기화 비용이 **0** 이다.
2. **hit 당 판정 비용** — N-way 판정은 계급 수에 비례해 오분류 확률을 올린다.
