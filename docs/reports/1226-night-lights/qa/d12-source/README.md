### MN-2 — 계약이 예고한 사각 실증

가드는 **8 게이트 FAIL** 인데 `packages/core` 단위 테스트는 **`1130 / 1130` 통과**다 (`20-mn2-unit.log`, `exit=0`). GLSL 정적 assert 는 소스가 그대로라 전건 통과하고, 바인딩 소실은 픽셀만이 잡는다 (§A8.8 M-2 동형). 가드 고유 검출력의 직접 증거다.

### MN-5b — 「단위 테스트가 잡는 자리」 처분 확인

가드 `exit=0` 이 **결함이 아니다.** 판정량이 baseline 과 전 항목 동일하다 (`D2 0.021870` · `D4 0.840400` · `D6 0.699314` · `D7(1) 0.021659`) — 결함 픽셀이 `NI` 판정 대역 (`ndv ≥ 0.6`) 밖이라는 §A11.18.1 실측대로다. 이 축은 단위 테스트가 잡는다 — `55-mn5b-unit.log`: **`1 failed | 1129 passed`, `exit=1`**, 실패 테스트 = `procedural-planet-night-lights.test.ts` › `N3 박제 형태`.

- ⚠️ 잡는 것은 **GLSL 문자열 assert 1건**이다 (`expect(CODE).toContain('float lightGate = landMask * (1.0 - iceMask) * uMaskEnabled')`). 미러 테스트 `N5 Q1-b 극관 억제 — iceMask 1 → 정확히 0` 은 **통과한다** — `nightLightTermMirror` 는 별 JS 함수라 GLSL 변이에 반응하지 않는다. `../../phase2/README.md` 의 「`lightGate` 문자열 + `iceMask 1 → 정확히 0`」 표현은 두 테스트가 함께 잡는 것처럼 읽히나, GLSL 변이에 대해 하중을 지는 것은 **문자열 assert 하나**다 (미러 테스트는 미러의 회귀를 막는다 — 직교 축).

### MN-8 — 계약 문면과 구현의 관계

계약은 「D9 (a) FAIL + 「측정 불가」」인데 두 판정은 이 가드에서 **양립하지 않는다**. 전제 `(5)` (불빛 OFF 페이지의 `nightLightStrength` 비-0 — 하네스 설정 실패) 가 **모든 게이트보다 먼저** 발화해 `exit 2` 로 끝나고 게이트 줄이 인쇄되지 않는다. 결함 자체는 측정 데이터에 남아 있다 — `80-mn8-d9.log` 의 `d9-a fullChanged 987` · `d9-c 1006` (둘 다 `≠ 0` = D9 (a)(c) 가 FAIL 할 값). dev 로그도 동일하므로 **qa ↔ dev 불일치가 아니라 계약 문면 ↔ 구현의 표현 차이**다. 설계상 올바른 쪽은 구현이다 — #1215 X2 (「전제에 제품 속성을 섞으면 결함이 전제 뒤로 숨는다」) 의 반대 방향으로, 플래그가 작동하지 않으면 **쌍 자체가 성립하지 않아** 게이트가 의미를 잃는다.

### MN-3 · MN-4 불일치의 원인 = 레시피 형태 (제품 거동 아님) [실측 확정]
